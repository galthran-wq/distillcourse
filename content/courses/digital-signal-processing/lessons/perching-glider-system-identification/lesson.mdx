A fitted recurrence is useful only when it predicts held-out flight measurements and its residuals expose the physics it omits.

<Ref lesson="difference-equations-and-stability">Difference Equations and Stability</Ref> ended with an output-only record split into training and validation samples. A second-order recurrence reproduced its training values exactly but lost to a first-order model on held-out RMSE. That calculation established the seam: roots describe a stated recurrence, while untouched records test whether the recurrence predicts anything beyond the data that chose it.

Here the evidence is no longer a small teaching sequence. We will audit nine measured longitudinal maneuvers from the Skywalker X8 UAV campaign: seven creator-designated training records choose one frozen elevator-to-pitch-rate recurrence, and two creator-designated validation records judge it. The route is data contract, boundary-safe fitting, root check, one-step and free-run validation, residual diagnosis, and a deliberately narrow physical conclusion.

Those rasters stop at motivation. Every coefficient, error, and residual below comes instead from the CC0 **System identification campaign - Skywalker X8 UAV**, DataverseNO Version 1.0, DOI `10.18710/U4TLYV`. Nothing is pooled or compared numerically across the two vehicles.

<Definition title="system identification">
**System identification** estimates and validates a dynamical model from ordered input-output records under a declared preprocessing, model-selection, and evaluation protocol. Fitting chooses coefficients; validation tests the frozen choices on records that did not choose them.
</Definition>

That separation determines the next move: before writing any recurrence, we must fix the X8 records' indices, units, file boundaries, and creator-designated roles.

## The record contract comes before the recurrence

### Nine files are nine independent maneuvers

The released CSVs are headerless. The Version 1.0 README assigns exactly 41 numeric columns and their units. This lesson uses only

| position | README name | symbol | unit | role |
|---:|:---|:---:|:---:|:---|
| 1 | `t` | $t[n]$ | s | time |
| 2 | `elevator` | $u[n]$ | rad | input |
| 9 | `IMU_angvel_q` | $q[n]$ | rad/s | measured output |

Each file starts again at row 1, $n=0$, $t=0$, and includes its last row. Its nominal rate is $40$ samples/s, so $T_s=0.025$ s. The deterministic integrity audit found 3,828 complete rows across the nine longitudinal files, exactly 41 finite fields per row, no missing values, and every within-file time increment equal to $0.025$ s within $10^{-9}$ s.

The creator—not this lesson—designated the split. Training contains four 3211 elevator maneuvers and three elevator doublets. Validation contains `longitudinal_3211_5.csv` and `longitudinal_doublet_4.csv`. These are two separate maneuvers; this study creates neither a random row split nor a percentage-based tail split.

<KeyFact>
A maneuver boundary is a state boundary. Using the last $q$ or $u$ from one file as a delayed regressor or recursive seed for the next invents a transition the aircraft never made; that false row can move fitted coefficients, characteristic roots, and every downstream validation score.
</KeyFact>

### Integrity failures stop the analysis

## A frozen ARX recurrence asks whether elevator helps

### Match output memory before adding input

With channel meanings and state boundaries fixed, the comparison can now isolate one question: hold pitch-rate memory at order two, then ask whether recorded elevator adds predictive information.

The baseline is an input-free second-order autoregression,

$$
\hat q_0[n]=c_0+a_{01}q[n-1]+a_{02}q[n-2].
$$

It asks how much pitch-rate prediction comes from pitch-rate memory alone. The candidate keeps that output order and adds one recorded elevator term:

$$
\hat q_1[n]
=c+a_1q[n-1]+a_2q[n-2]+b_1u[n-1].
$$

This is ARX$(2,1,1)$: two output lags, one input term, and a one-sample input lag. Because $q$ is in rad/s and $u$ is in rad, $a_1$ and $a_2$ are dimensionless, $b_1$ has units $1/$s, and $c$ has units rad/s.

The one-sample lag is a precommitted discrete modeling convention; it does not measure $0.025$ s of actuator latency. The source channels were manually synchronized, so an effective record-level lag can contain alignment error as well as physical response.

### Construct lags inside each training file

For a training file of length $L$, make design rows only for $n=2,\ldots,L-1$:

$$
X_1[n]=[q[n-1],q[n-2],u[n-1],1],
\qquad y[n]=q[n].
$$

Build those rows separately in all seven files, then stack the completed matrices. Never concatenate raw sequences first. Unweighted float64 least squares on the resulting 2,936 training rows fixes all coefficients. There is no centering, scaling, detrending, smoothing, filtering, clipping, resampling, or maneuver-specific refit; the intercept absorbs one pooled offset.

<Exercise>
To isolate the boundary issue, fit the first-order special case $q[n]=a q[n-1]$ through the origin on two short independent training maneuvers:

$$
q_A=[1,0.5],\qquad q_B=[10,5].
$$

Find $a$ when lag state resets between files. Then concatenate the records, include the false transition $0.5\to10$, and refit. What changed?

<Solution>
With a reset, the only valid pairs are $(1,0.5)$ and $(10,5)$, so

$$

$$

Concatenation invents the pair $(0.5,10)$. The fitted coefficient becomes

$$

=\frac{1(0.5)+0.5(10)+10(5)}{1^2+0.5^2+10^2}
=\frac{55.5}{101.25}\approx0.5481.
$$

No aircraft transition produced that change; the parser did. In the real study, every lag matrix and every free-run state is reset at each maneuver boundary.
</Solution>
</Exercise>

### Freeze coefficients before opening validation

The training-only checkpoint gives

$$
\begin{aligned}
a_1&=1.7421463, & a_2&=-0.8284751,\\
b_1&=-0.3877093\ \mathrm{s}^{-1}, & c&=-0.0114088\ \mathrm{rad/s},
\end{aligned}
$$

and the matched baseline gives

$$
a_{01}=1.8724058,\qquad
a_{02}=-0.9386441,\qquad
c_0=0.0001603\ \mathrm{rad/s}.
$$

The stacked training RMSE values are $0.04256$ rad/s for ARX and $0.04863$ rad/s for AR(2). That difference is not the result. It only freezes two candidates for validation.

### The fitted homogeneous modes decay

Set input and intercept to zero and substitute $q_h[n]=r^n$:

$$
r^2-a_1r-a_2=0.
$$

The ARX roots are

$$
r_{1,2}=0.8710731\pm j0.2640202,
\qquad |r_1|=|r_2|=0.9102061<1.
$$

Thus the homogeneous modes of this fitted recurrence decay. That passes the precommitted model-stability check. It does not establish stability of the aircraft, its controller, its sensor chain, or the experiment.

## Validation asks two different prediction questions

### One step tests the local update rule

For each validation file, one-step prediction uses measured $q[n-1]$ and $q[n-2]$ at every scored index. Its residual sign is

$$
e_1[n]=q[n]-\hat q_1[n].
$$

The first two rows are needed as lags, so scoring begins at $n=2$. The 3211 file has 416 raw rows and $M=414$ scored samples; the doublet has 462 raw rows and $M=460$.

### Free run tests accumulated recurrence dynamics

Free run uses the two measured seeds only once:

$$
\tilde q[0]=q[0],\qquad \tilde q[1]=q[1].
$$

Thereafter it feeds back its own predictions,

$$
\tilde q[n]
=c+a_1\tilde q[n-1]+a_2\tilde q[n-2]+b_1u[n-1],
$$

while continuing to use the recorded elevator input. The AR(2) baseline follows the same seed and scoring rule but has no elevator term. A one-step model is repeatedly corrected by measurement; a free-run model must carry its own state. Their errors answer different questions and must remain separate.

### Normalize within each maneuver, then average maneuvers equally

For $M$ scored samples,

$$
\operatorname{RMSE}=\sqrt{\frac1M\sum e[n]^2},
\qquad
\operatorname{NRMSE}=\frac{\operatorname{RMSE}}
{\sqrt{M^{-1}\sum(q[n]-\bar q)^2}}.
$$

NRMSE accounts for the different pitch-rate scale in each maneuver. The primary aggregate is the arithmetic mean of the two per-file values, giving the 3211 and doublet equal weight. It is not one concatenated trajectory.

| maneuver / aggregate | mode | AR(2) RMSE | AR(2) NRMSE | ARX RMSE | ARX NRMSE |
|:---|:---|---:|---:|---:|---:|
| `longitudinal_3211_5` | one step | 0.04727 | 0.077 | 0.04260 | 0.069 |
| `longitudinal_3211_5` | free run | 0.6170 | 0.999 | 0.2335 | 0.378 |
| `longitudinal_doublet_4` | one step | 0.04966 | 0.095 | 0.04283 | 0.082 |
| `longitudinal_doublet_4` | free run | 0.5227 | 1.005 | 0.2169 | 0.417 |
| equal-maneuver macro | one step | 0.04847 | 0.086 | 0.04272 | 0.076 |
| equal-maneuver macro | free run | 0.5699 | 1.002 | 0.2252 | 0.397 |

RMSE is in rad/s; NRMSE is unitless. The precommitted rule promised no minimum improvement and no successful outcome. It required ARX to beat AR(2) in both metrics, both modes, and both validation files; both macro NRMSE effects had to be positive; and both ARX roots had to remain inside the unit circle. Every gate passed.

Using full-precision macro NRMSE,

$$
100\left(1-\frac{0.0756403}{0.0859842}\right)=12.0\%
$$

for one step, and

$$
100\left(1-\frac{0.3974635}{1.0017412}\right)=60.3\%
$$

for free run. The supported primary claim is specific: recorded elevator supplies held-out predictive information beyond matched-order pitch-rate memory.

## Better prediction does not finish identification

### Residual autocorrelation exposes remaining memory

For each validation file separately, subtract the mean from the ARX one-step residuals: $r[i]=e_1[i]-\bar e_1$. Then compute

$$
\rho[k]=
\frac{\sum_{i=k}^{M-1}r[i]r[i-k]}
{\sum_{i=0}^{M-1}r[i]^2},
\qquad k=1,\ldots,20.
$$

No pair crosses a file boundary. The approximate descriptive band is $\pm1.96/\sqrt M$: $\pm0.0963$ for the 3211 file and $\pm0.0914$ for the doublet. Lag 1 is $0.5589$ and $0.5349$, respectively, and multiple later lags also cross the bands. These twenty correlated comparisons are diagnostic flags, not a formal whiteness test. Still, the structure is too large to dismiss as an aggregate-score detail.

<KeyFact>
The frozen ARX model is **predictively better but structurally incomplete**. Lower validation error supports the value of elevator input; correlated residuals reject the stronger claim that this recurrence captures all predictable longitudinal dynamics.
</KeyFact>

### The idealization gap is measured and procedural

The campaign documents strong northwesterly wind with a significant vertical component. An elevator-only recurrence omits that disturbance, along with throttle, airspeed, attitude, lateral coupling, saturation, and changing operating conditions.

The STIM300 IMU was downsampled from 200 Hz, GPS and propulsion channels were upsampled from 10 Hz, command data originated at 40 Hz, and the sources were manually synchronized. Therefore the fixed input lag is an effective lag in the released record, not a measurement of actuator latency. The output is an IMU gyro measurement, so correlated sensor error can appear in both target $q[n]$ and its delayed regressors and bias ordinary least squares.

Finally, 3211 and doublet excitations probe different input patterns. A residual difference between them may reflect maneuver shift, wind, timing, or omitted dynamics; it does not isolate one aerodynamic cause. Neither validation file is documented as perching or stall data, and `EstimatedState_alpha` is not a stall flag.

The local projection preserves unmodified source files and MD5s, excludes GPS/location fields from derived artifacts, and records every computation.

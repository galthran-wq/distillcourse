**Problem.** An adversary who knows the classifier edits positives at a price per feature: what is its cheapest way through, what should the classifier do knowing that, does the back-and-forth settle? Answer: against naive Bayes the reply is the minimum-cost camouflage (a 0-1 knapsack on log-odds cuts, solved by a table over the discretised gap), used only if its price < ΔU_A; the classifier's reply keeps P(+), P(x|−) and replaces P(x'|+) by the pre-image mass P_A(x'|+), computed from single-feature reverts (triangle inequality); on Ling-Spam add-words FN 481/481 → 93 with 0 FP; the repeated game on Ling-Spam add-words alternated with period 2 (measured in that one setting only), no equilibrium.

## Explained
- Change as a function of the classifier: positives mapped x → A(x), negatives untouched; fit C1 to P_{A0} (A0 = identity), adversary answers, no stationary target; this is real drift in concept-drift's terms (p(x|+) moves p(y|x)) but a reply, not weather — intro, §A change that answers the classifier / ### Why drift handling does not cover it
- Utility = −cost convention — ### Two players, two utilities
- Definition: adversarial classification game (U_C with V_i measurement costs, U_A minus W edit cost, W_i(x_i,x_i)=0, W sum over features); ΔU_A = U_A(−,+) − U_A(+,+); adversary never edits beyond worth; V_i set aside (spam ≈ 0; fraud: a call is a measurement) — same ###
- Nash equilibrium named and set aside: 2^n messages, 2^{2^n} classifiers (n = 20: ~10^6 messages, 2^{1,000,000} classifiers), equilibria assume optimal play; Aside: unit-or-impossible edit costs → polynomial in number of instances (= 2^n); single-shot sequential play with complete information (stated strong; real fraudsters probe instead); figure game-loop.svg (key image; boxes in plain words: fits on pre-attack mail / cheapest worthwhile edit / answers knowing the edit; dashed repeated-game loop); no KeyFact — ### Which solution to look for
- Naive Bayes log-odds additive: LO_C(x) = ln P(+)/P(−) + Σ LO_C(x_i) (naive Bayes from classical-ml, not re-derived) — §The classifier the adversary faces
- Retrieval Task (per-payment rule C_a ≤ Amt·p); expected-utility decision → LO_C(x) > LT(U_C) = ln[(U(−,−) − U(+,−))/(U(+,+) − U(−,+))]; = Bayes minimum-risk rule on log-odds scale; Example: penalties 10/100/1000 → LT 1.70/3.92/6.22 (odds 5.5/50/500) — ### Where the threshold comes from
- Definition gap(x) = LO_C(x) − LT, spam iff > 0; a log-odds distance; ΔLO_{i,x_i'} = LO_C(x_i) − LO_C(x_i') the cut, cuts add; figure gap.svg; KeyFact: the classifier's own penalty sets how much camouflage is needed — ### The gap
- Largest-first (e1+e2, 3.6, price 15) and best-ratio-first (e3,e5,e7 then e4: 3.6 for 10) both miss the optimum e3+e4+e5 (3.2 for 9) — §The cheapest way through / ### Largest-first is not cheapest
- Definition MCC (integer program, z_{i,v} binary, ≥ gap, one value per feature); knapsack defined in one sentence; reduction both ways → NP-hard; "act condition" W(x,MCC(x)) < ΔU_A named here; A(x) = MCC(x) iff classified spam and act condition holds, else x — ### A knapsack, and when the adversary bothers
- DP F(i,w) = min{F(i−1,w), W_i + F(i−1, w − u_i)}, F(0,w>0)=∞, F(i,w≤0)=0; steps of 0.4; one row per feature, multi-valued feature = one row taking min over its values; FigureSequence findmcc-1..5 + Task (F(5,8) = min{12, 2+7} = 9); answer 9 < 20 → edits; Demo CamouflageKnapsack + Task (three rounds, wall at round four at the latest; states only that this classifier never forgets — the contrast with forgetting is left to the repeated game) — ### A table over the discretised gap

# alert-budget-metrics — ledger

**Problem.** A model has scored a day of ~8,300 payments and the team opens 100: what number, computed from a labelled test week, rises exactly when more fraud is caught within the hundred? Answer: threshold metrics score one cut nobody chose; ROC-AUC averages over FPRs a 100-alert budget cannot reach (FPR ≤ 0.012 on the simulator, < 0.1% on real streams); average precision (mean precision at each fraud, floor = base rate) summarises the top of the list; card precision at k per day (max score, max label per card; cards detected on earlier days removed) is the team's own number; report AUC, AP and CP@k together, CP@k at the team's k decides.

## Explained
- **The five-model baseline experiment is SET UP here** (later lessons Ref `alert-budget-metrics#five-models-scored-on-a-test-week`, never re-teach): motivated as "a metric is judged by which model it calls better, so it needs held-out ranked lists from several models"; simulator weeks of 2018 — training 25–31 Jul (67,240 payments / 598 frauds), delay 1–7 Aug (unused; why → delayed-labels-prequential), test 8–14 Aug = days 129–135 (58,264 payments, 385 frauds after dropping cards already known compromised, ~55/day, 0.66%); fifteen inputs (amount, weekend, night; card count + avg amount and terminal count + fraud rate over 1/7/30 days, rate from labels already held; how built → later module); five models at library defaults, nothing tuned, one clause each: logistic regression, depth-2 tree (Ref canonical-datasets#three-scripted-frauds, same training week; score = leaf's training fraud share), full-depth tree (pure leaves ⇒ scores 0/1), random forest (100 full-depth trees on resamples, averaged), XGBoost (100 boosted trees depth ≤ 6); every number = ROC-AUC, AP, top-100 counts from those scores and test labels. Real half: same five models, same way, same three weeks on the Belgian e-commerce stream (Ref fraud-detection-system), 2,858,663 training payments / 6,605 frauds, test fraud share ~0.2% (1 in 500) after the same removal; confidential, quotable not re-runnable — §Five models scored on a test week
- Ten-payment toy (frauds at ranks 1 and 4; scores 0.90, 0.45, 0.40, 0.35, 0.20×3, 0.10×2, 0.00); alert iff score ≥ τ; error 0.2 / 0.1 / 0.2 at τ = 1 / 0.5 / 0.3; on a simulator day (150 genuine per fraud) do-nothing accuracy 8,250/8,305 ≈ 0.993 vs 0.988 for a 100-alert detector catching 29 of 55 — §A threshold metric judges a cut nobody chose / The ten-payment toy
- Full threshold table (recall, precision, F1, balanced error rate defined as mean of miss rate and false-alarm rate); precision picks 0.9, BER 0.35, F1 ties; threshold metric meaningful only once the objective fixes the threshold; the team fixes its cut by count (k), so a fixed τ does not describe it — same §, ### Every threshold metric picks its own winner
- AUC by pair counting on the toy (14/16 = 0.875) and by the staircase; second toy ranking (frauds at 2, 3) same AUC; equal-AUC/different-top point NOT re-taught (Ref economics-of-detection#exercises, the three AUC-0.625 rankings) — §ROC-AUC: a ranking metric averaged over cuts the team never makes / Reading AUC off the toy
- Reachable region: 100 alerts over ~8,250 genuine/day ⇒ FPR ≤ 0.012 (98.8% of the axis unreachable); real streams (Belgian, 400,000/day) < 0.1% — same §, ### How much of the curve a hundred alerts can reach
- Crossing ROC curves (illustrative A: AUC 0.81, recall 0.45 at FPR 0.012; B: AUC 0.87, recall 0.22); simulator trees (same training week): depth-2 AUC 0.763 vs full-depth 0.788; full-depth tree = two scores, tied payments cannot be separated ⇒ one-corner ROC, area from the unreachable straight segment; few corners = few distinct scores — same §
- ROC axes are within-class rates (blind to class sizes); precision in count form TP/(TP+FP) (Bayes form NOT re-taught: Ref economics-of-detection#bayes-rule-and-why-the-error-rates-cannot-rescue-precision); a cut of a alerts has precision ≤ 55/a; beyond 825 alerts (FPR ≈ 0.1) < 0.07 — same §, ### Precision sees the base rate; the ROC axes do not
- PR curve defined; budget does not shrink the recall axis; cuts of ≤ 100 alerts lie on/above precision = 0.55·recall (TP+FP ≤ 100), illustrative detector A's 100th alert ≈ (0.4, 0.22); cuts beyond the budget lie below it, FPR > 0.1 squeezed under precision 0.07 above floor m/n = "zoom by arithmetic" — same §, ### Where the hundred alerts land on the PR plot
- "On or above" defined (rankings without ties): at recall j/m the best point = fewest false alerts FP(j) (genuine above the j-th fraud) = top of the PR stack = ROC corner at FP(j)/(n−m); ROC dominance ⇔ FP_A(j) ≤ FP_B(j) ∀j; Theorem (with proof): ROC dominance ⇔ PR dominance; ROC and PR disagree only on crossing curves — same §, ### Dominance survives the change of axes
- PR walk on the toy: non-monotone (0.5 → 0.33 → 0.5); recall moves only at frauds, by 1/m; straight-line interpolation describes no cut and is ambiguous at repeated recalls (0.875 vs 0.708) — §Average precision: the precision at each fraud, averaged / Walking down the toy's list
- Definition: AP = (1/m) Σ_j j/r_j = Σ (R_n − R_{n−1}) P_n (step sum, rectangles never trapezoids); toy AP = 0.75; AP = 1 iff frauds first; in-body exercise: frauds at 2, 3 → AP 0.583, ROC curves differ only on FPR ∈ [0, 0.25] (first ranking ahead below 0.125, second between 0.125 and 0.25, equal rectangles 0.125×0.5) — same §, ### What the team sees at each fraud
- Tie convention (KeyFact "Ties"): a block of tied scores is one cut; every fraud in it reached at the block-end precision, adds (1/m)·that; ROC: one cut, straight segment, tied pair = half a correct pair; grounded in the toy's 0.20 block (alerts jump 4 → 7); constant-score toy AP = 0.2 — same §
- Demo RankingBudgetExplorer (start: frauds at ranks 1 and 10, AUC 0.50, AP 0.60): prose Task tightens target 1 to AUC ≥ 0.75 with AP < 0.5; for two frauds in ten AUC = (19 − r1 − r2)/16, AP = ½(1/r1 + 2/r2); a fraud at rank 1 forces AP ≥ 0.5; only answers 2 & 5 (AP 0.45) and 3 & 4 (AP 0.42), AUC 0.75; target 2: AUC 0.50 with P@3 = 0 (e.g. 4 & 7) — same §, ### Why the first target has only two answers
- AP floor: constant score = one tied block ⇒ exactly m/n; random order ⇒ m/n + O(ln n / n); read AP as a multiple of the base rate; AP reversal of the trees (0.496 vs 0.309) explained by the tie convention: full-depth tree's frauds in the 0 block reached at exactly the base rate; AP belongs to its stream like precision; the five models' real-stream APs quoted against the setup section, not re-described — same §, ### What a ranking with no information scores
- Why cut per day (budget renews daily; pooling lets busy days starve quiet ones); why payments first (test week labels payments; one change at a time before the unit change); Definition P@k(t) and its mean over days; P@k = the economics lesson's hit rate as an evaluation metric — §Precision at k: the metric cut where the team cuts / One day of the simulator
- Ceiling P@k(t) ≤ min(1, γ_t/k); KeyFact: mean ceiling 385/700 = 0.55 splits the tree's gap 0.29 → 1 into 0.26 model + 0.45 calendar; ceiling 1 on streams with > k frauds/day — same §, ### Reading a day against its ceiling
- Aside: AUCPR@0.2 (area up to recall 0.2, max 0.2) fixes recall instead of k — same §
- KeyFact: P@k and CP@k part only where cards repeat in the top k; with no repeat the top-k cards = cards of the top-k payments and CP@k ≥ P@k (excess only from a card whose fraud scored below its genuine payment); simulator differ by 0.005, real data one card can take 3 payment slots — §Card precision at k / On real card data
- Card collapse: ranking by max score NOT re-taught (Ref fraud-detection-system#ranking-then-cutting-at-the-capacity); new here: max label (compromised that day if any payment is fraud); Definition CP@k(t); same ceiling with γ_t = compromised cards — §Card precision at k: the team calls cards / Collapsing a day to cards
- Why CP@100 ≈ P@100 on the simulator: scenario 2 (9,099 of 14,681 frauds) hits whoever pays at the terminal; ~2 payments/day over ~75 terminals ⇒ almost never twice a day; such a card is not stolen, "compromised" = had a fraud that day, recurs only on return within the terminal's 28 days; scenario 3: 1/3 of ~2 payments/day for 14 days — same §
- Repeat days: leaked card compromised 14 days; terminal-hit card again on any return within 28 days ⇒ day-by-day metric re-credits blocked cards — §A detected card is a blocked card
- Detected-card removal: carry detected cards through the test week, remove their payments from later days; γ_t then counts compromised cards not yet found; unqualified CP@k means the version with removal; the test week was already cleaned of cards known from training (raw 74–91 frauds/day) — §A detected card is a blocked card / Removing cards the team has already found
- NCP@k(t) = CP@k(t)/min(1, γ_t/k); backtesting only (γ_t known late); undefined when γ_t = 0 — same §, ### Normalising by the day's ceiling
- Three metrics, three questions (trees: AUC won on the unreachable straight segment, AP lost because tied frauds are reached at the base rate, CP@100 a tie within 0.002); rule (KeyFact): report all three, CP@k at the team's k decides deployment, AP breaks ties when k uncertain; CP@k differences under ~2 cards/day on one week are within noise; closing in a <Conclusion> block — §Three numbers for three questions / What each disagreement means

## Notation
- τ score threshold (alert iff score ≥ τ); t = day (course convention)
- m frauds, n items in a ranked list; r_j rank of the j-th fraud; P_n, R_n precision/recall at cut n
- AP; P@k(t), P@k (mean over days 𝒟); A_t top-k payments of day t
- CP@k(t), C_t top-k cards of day t; γ_t frauds (for P@k) or compromised cards not yet found (for CP@k) on day t; NCP@k(t)
- π base rate (from economics-of-detection)

## Running cases
- Simulator test week (set up in §Five models scored on a test week): five models trained 25–31 Jul 2018 (days 115–121; 67,240 payments / 598 frauds), test 8–14 Aug (days 129–135), delay block 1–7 Aug; 58,264 payments (~8,300/day, ~8,250 genuine), 385 frauds after known-card removal (~55/day, 0.66%); raw week 74–91 frauds/day
- Depth-2 tree P@100 per day 0.26, 0.35, 0.26, 0.33, 0.30, 0.35, 0.19 (mean 0.291) against frauds 55, 60, 56, 56, 59, 58, 41
- CP@100 without removal 0.24, 0.35, 0.26, 0.32, 0.30, 0.34, 0.19 (mean 0.286), γ 50, 54, 51, 54, 55, 54, 38; with removal 0.24, 0.32, 0.27, 0.25, 0.23, 0.26, 0.12 (mean 0.241, the course's CP@k), γ 50, 50, 49, 47, 46, 44, 31; NCP on day 135 0.12/0.31 ≈ 0.39
- Five baselines on the test week, AUC / AP / CP@100: LR 0.871 / 0.606 / 0.291; DT2 0.763 / 0.496 / 0.241; DT∞ 0.788 / 0.309 / 0.243; RF 0.867 / 0.658 / 0.287; XGB 0.862 / 0.639 / 0.273; random AP ≈ 0.007
- Real Belgian data (same five-model setup, same weeks; 2,858,663 training payments / 6,605 frauds; test fraud share ~1 in 500): ~300 compromised cards/day (200–350 after known-card removal), random CP@100 ≈ 0.0025, LR ≈ 0.15, DT2 ≈ 0.10; APs 0.003–0.035 vs floor 0.002
- NCP worked: 40 of 100, γ = 50 → CP 0.4, NCP 0.8
- Toys: ten-payment list; 8-payment card collapse (A×3 fraud top, P@3 = 1 vs CP@3 = 2/3); two-day removal example (mean 0.75 → 0.5)
- Exercises: warm-up 20-payment day (frauds 1, 3, 8, 15: AP 0.577, P@5 0.4, AUC 47/64); ceiling edges (γ_t = 0 days dropped, k = all cards → CP = share); equal-AUC 1,000-row rankings with P@100 0.6 vs 0 (AUC 8/9, AP 0.70 vs 0.31, curves differ only on FPR < 0.28, budget reaches ≤ 0.11); E[AP] random = H_n/n + (m−1)/(n−1)(1 − H_n/n) (toy 0.371, test week 0.0068); NCP not model-neutral with removal: days 129–130, tree CP 0.28 / NCP 0.56 vs model B (finds 24 then 34, γ_130 = 54) CP 0.29 / NCP 0.555; value pricing V = €360, C_a = €5: 0.286 vs 0.241 → €11,340/week overstatement (vs honest €57,232), break-even CP = C_a/V ≈ 0.014; forward exercise on removal date = test day − δ

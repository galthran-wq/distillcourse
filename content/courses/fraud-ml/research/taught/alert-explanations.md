NOTE (data): every simulator number is this lesson's own re-run of the handbook generator (exact: 1,754,155 payments, 973 / 9,077 / 4,631 by final scenario) and of the alert-budget-metrics XGBoost baseline (xgboost 3.x, tree_method exact, 100 trees, depth 6, η 0.3, seed 0; trained 25–31 Jul on the fifteen handbook inputs, unscaled; test 8–14 Aug with known-card removal, 58,264 / 385). Attributions: exact Shapley over all 2^15 coalitions, interventional, margin (log-odds) space; reference = 300 random training-week payments (seed 0) unless stated; "exact tree algorithm" numbers = xgboost pred_contribs / pred_interactions (path-dependent TreeSHAP, base −6.40). Hinton MLP and two-stage model also fitted here. Card-toy numbers recomputed exactly (match guilt-by-association).

**Problem.** A case reaches three readers with a score of 0.93: what does each need explained, which methods produce it from a booster, a network, a scorecard, and which explanations are honest? Answer: an explanation is a statement about one payment against a stated reference; the Shapley attribution splits the log-odds from a base value; the reference (training sample vs the card's own past) changes every number; joint effects and copies split credit; attributions describe the model, not the world; a scorecard is its own explanation (points from a conventional zero); reason codes for customers within GDPR/AMLR limits incl. tipping-off; readable stand-ins (Hinton, backward elimination, extracted rules with fidelity, two-stage) must report how much of the model they cover; attention and exposure paths are honest but narrow; each reader gets a different object; honesty = computed from the model and served input, reference named, omissions stated.

# contrastive-event-embeddings — ledger

NOTE (data): three measurements are the writer's own, on the public MBD 100,000-client cut (MBD-mini parquet, `ptls/trx`), and the lesson presents them as "the course's run": (1) KL check: fold 0, first 12 parquet parts, 1,955 clients with ≥ 120 events, two disjoint 50-event slices each, event_type histogram over the 15 most frequent of 52 types + pooled rest, +0.5 per bin, numpy seed 0; control = event types pooled, permuted, dealt back. (2) Identity shortcut: research/representations/feasibility-spike.py extended with a per-client random code (1,000 values) as a 7th categorical on every event; 6,000 clients (half buyers), 5 CPU minutes each (617 batches dynamic, 772 with code), held-out checks over 20 batches; downstream logistic regression on the vector only. (3) Order experiment = the feasibility spike's big/shuf runs (12,000 clients, 10 min, 786 batches), single seed. Scripts in the writer's scratchpad, not committed.

**Problem.** With unlabelled histories only, what task can train a sequence encoder so that what it learns serves an unnamed later task, and how does it cheat? Answer: are two pieces from the same customer? Positives = random contiguous slices of one history, checked by event-type KL; margin loss (pull positives, push negatives to ρ); unit vectors so the batch is one matrix product; k nearest other-customer slices as hard negatives; event encoder + GRU, last state normalised; a static field solves the task by identification (identity shortcut) → dynamic fields only. Frozen, the vector describes stable behaviour: ahead on churn/default, level or behind elsewhere, redundant beside 30 engineered features (0.9245 / 0.9205 / 0.8644).

- Unit vectors: normalising is FORCED by the margin (an encoder free to rescale all vectors changes every distance, ×10 clears negatives and makes positive terms ×100, so ρ would mean nothing; on unit vectors distances run 0–2 and ρ = 0.5 ≈ 29°); the simplification it buys: for any vectors d² = ‖c_u‖² + ‖c_v‖² − 2c_u·c_v (one product CCᵀ plus norms), with unit vectors d² = 2 − 2CCᵀ; batch-matrix.svg toy (4 customers × 3 slices, hard negatives circled) — ### Unit vectors give the margin a scale
- Most negatives beyond ρ contribute zero and dilute; Definition: hard negatives = k nearest other-customer slices per row (a rank, not a property of the customer) — §Which negatives / ### Hard negatives

## Notation
- u, v slices; c_u unit embedding of slice u; d_{uv} Euclidean distance; Y_{uv} ∈ {0,1} positive-pair indicator; ρ margin; 𝓛_{uv} pair loss
- T events of a customer; m, M shortest/longest slice; K slices (attempts) per customer; L slice length; s start
- N customers per batch; C matrix of stacked unit vectors (rows); k hard negatives per slice
- z_t event vector; h_t GRU state, h_0 learned initial state; GRU gates g_t (update), r_t (reset), h̃_t (Aside only); embedding dimension written in words (d is the distance here; limits used d for vector length)
- V number of values of a static field

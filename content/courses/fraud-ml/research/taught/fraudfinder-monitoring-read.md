**Problem.** A published cloud reference pipeline (FraudFinder) gates deployment on accuracy > 0.95 and monitors 9 of 25 features: read against module 9, what does each gate/monitor implement and what gets through? Answer: the gated pipelines deploy to endpoints nothing calls; the served and monitored model (bqml_fraud_classifier, hand-trained in bqml/04, deployed by hand in bqml/06 to the _monitored endpoint that bqml/07's Cloud Run app calls) passed no gate. The gate arithmetic stays, as a reading of the recipe. The data path is the module's (feature store, as-of read, terminal risk delayed 7 days); the accuracy gate passes the model that never alerts (0.98 at 2%); the sibling AP > 0.2 gate is the right kind (10× random) but measured on a shuffled day with no delay block; the threshold is Youden's point = cost rule with c_FN/c_FP = 49; the monitoring job is a label-free input check with lines past red, 16 unwatched features and an all-zero baseline it cannot cross; no labels → no backtest, pools or fraud-row index; serving approves everything; the structured table keeps a random half without identifiers, the free-text service log keeps every payment; no testing/staging, and no gate on the serving route.

## Explained
- The artifact: four paths (data, training, serving, monitoring); endpoint defined (hosted service: feature vector → score); pipeline (fixed steps run without a person) and condition gate (deploy steps run only if an evaluation number clears a threshold); two *tracks* introduced here (first: logistic regression in the warehouse; second: boosted tree in a managed training job) — §The artifact: one stream, four paths / ### What runs where
- Data: synthetic, ~2% fraud, simulator-style features; labels instant (notebook says so, trains on yesterday, notes bank delay); training table = one day read as of each payment; terminal risk window ends 7 days back (two rolling sums, count beside) = module's answer — ### What the data are, and what the pipeline gets right
- Accuracy gate: the *constant model* (one score below 0.5 for every payment: never alerts, ranks nothing) 0.98 > 0.95; ANY never-alerting model gets 0.98 (accuracy reads only the 0.5 cut); passes for any π < 5%, so it cannot tell a model that ranks well from one that never alerts; KeyFact: a gate stops a bad model only if its metric moves when ranking fails; after it, the served model never meets the gate (pipeline deploys its gated model to its own endpoint; the _monitored endpoint gets the bqml/04 hand-trained model in bqml/06, no threshold), arithmetic kept as a reading of the recipe — §The deployment gate / ### The arithmetic of a 2% stream (figure two-gates.svg)
- AP > 0.2 gate (second track): constant AP = π = 0.02 → 0.2 = 10× random; constant model fails; a never-alerting model that ranks frauds first passes, rightly (AP judges order, not the 0.5 cut); a floor, not a choice (not vs best candidate or production), not CP@k — ### The sibling track gates on average precision
- Three splits: warehouse track random holdout of one day at 2% (accuracy gate); second-track notebook balances whole day then 60/20/20 (test half fraud; threshold sweep); second-track pipeline random 80/10/10, undersampling training only (AP gate); FigureSequence split-1..3 + Task — §What the gate's number is measured on / ### Three splits in two tracks
- Why none describes live: time order (siblings on both sides), prevalence (precision 0.89 balanced vs 0.14 at 2% for TPR 0.8 / FPR 0.1), no delay block; notebook's own AUC 1.0 honesty note (on such a set both gates pass almost anything that ranks); KeyFact: the gate's metric must be computed on a later block after a delay at the stream's fraud rate — ### Why none of them describes the live stream
- Youden's point defined (max TPR − FPR, slope 1); cost-minimising ROC slope (1−π)C_a/(π(Amt − C_a)) under the course convention, with its reason in one sentence (a step adds (1−π)C_a dFPR in calls, saves π(Amt − C_a) dTPR; cost stops falling where dTPR/dFPR equals the ratio; full derivation in the Youden exercise); Example: slope 5 at π 0.02, C_a €5, Amt €54; the notebook's threshold: ten confusion matrices for 0.1–1.0, then argmax(TPR − FPR) over roc_curve's own thresholds, prefaced by the notebook's 'if we believe the optimal threshold … offers the highest TPR and minimum FPR'; illustrative binormal: Youden TPR 0.84/FPR 0.16, 1,723 calls, ≈€10,330 per 10,000; cost point TPR 0.58/FPR 0.036, 464 calls, ≈€6,880; flag nothing €10,800 (figure youden.svg); Youden = one missed fraud worth 49 false alarms: slope 1 means Amt − C_a = 49 C_a, so Amt = 50 × €5 = €250 (step written out in the body); still a fixed cut, needs calibrated p — §The threshold / ### Youden's point is the cost rule with one price ratio
- Saved model = last of the 8-config loop (`i` after loop), not the best; Aside: log-loss on hard predictions, probability clipped at a tiny ε (1e-15 in older library versions, machine eps ≈ 2.2e-16 now; the training image installs it unpinned) so each error costs 34.5 or 36.0 nats ≈ 35 × error rate; prose says skip balancing, code balances — ### Which model the threshold belongs to
- Monitoring job (sixth notebook of the first track, bqml/06_model_deployment): skew baseline = one-day training table; sample rate 0.5; hourly; thresholds 0.5 skew / 0.05 drift for 9 features and their attributions; email; vendor's skew = SI vs development, drift = vs recent window (course's training–serving skew and concept drift are different things) (figure monitor-job.svg) — §The monitoring job / ### What the job computes

## Running cases
- FraudFinder: 2% fraud; 25 inputs (amount + 12 card + 12 terminal features, windows 15/30/60 min, 1/7/14 days; terminal risk 1/7/14 days); training table one day; first track (warehouse logistic regression, accuracy > 0.95 gate); second track (boosted tree, AP > 0.2 gate, 0.8/0.1/0.1)
- Constant model: accuracy 1 − π (0.98 / 0.992 / 0.9975 / 0.94 at 2 / 0.8 / 0.25 / 6%); AP = π
- Illustrative ROC (binormal, separation 2), per 10,000 at 2%: Youden 1,723 calls / 168 caught / €10,330; cost point 464 / 115 / €6,880; nothing €10,800
- JS zero baseline: s 0.05 → 0.0177 (out-of-range share 5%; index 0 with open bins, 0.31 with floor 1e-4, 0.19 with floor 1e-3); 0.3 → 0.117; crossings 0.14 (0.05) and 0.88 (0.5) in nats; 0.10 and 0.71 in bits
- Random AP (n 100,000, m 2,000): mean 0.0201, sd 0.00046, 95th pct 0.0209, 99th 0.0212, 58% above π; 0.2 ≈ 390 sd above
- Hourly drift noise: E[JS] ≈ (B−1)(1/n_1 + 1/n_2)/8 → 0.05 at 45 sampled payments/hour (B = 10)
- Fraud wave 2% → 4% for an hour: the job has no score check at all (9 inputs + attributions); a score SI would be at most the monitoring lesson's two-bin bound f ln((1+10f)/(1−10f)) ≈ 20f² = 0.008, JS ≈ 0.001

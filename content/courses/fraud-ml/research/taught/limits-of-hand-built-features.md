# limits-of-hand-built-features — ledger

**Problem.** Hand-built aggregates are designed per task and per issuer; can a
summary of a customer's history be learned from the events alone, before any
label, and when does it beat the hand-built one? Answer: pretrain an encoder on
a task the events grade, freeze it, read its vector as of a time and hand it to
the downstream model. Against a schema-generated whole-history aggregation
recipe: with labels for ~2M clients a GRU trained end to end on the labels wins
(0.819 vs aggregates 0.783; pretrained rows 0.802 / 0.773 / 0.762); on a
69K-client subset it falls to last (0.745) while the label-free rows sit at
0.779–0.785. A pretrained vector is mostly added beside the features (alone <
features < both), has an edge where the grouping key cannot be named, cannot
produce label-derived features, and is blind to the network. The evidence is consistent with labels × grouping key ×
vocabulary deciding the winner; only the label count was varied alone against
the aggregates (four public non-fraud tasks: a fine-tuned pretrained network
ahead of a tree on the recipe at a few hundred labels on 3 of 4, level on
churn), the grouping key and vocabulary never, so the decision map is a
reading, not a measured rule.

**Problem.** How to turn a published/vendor headline about a pretrained or
sequence model (59%→97%, +22.5%, PR-AUC 0.958 …) into a number comparable with a
boosted tree on windowed aggregates, or show it incomparable. Answer: six
questions — baseline (absolute, what given, how strong), metric and the fraud
share it was taken at, split (forward in time, entities apart, delay), pretraining
cut, runs and intervals, blind spot — applied to eight claims and to the course's
own run. Module 8's application (L16).

## Explained
- Obvious move fails: three headline numbers are different kinds of quantity from the course's real-stream XGBoost (ROC-AUC 0.928, AP 0.095) — intro
- Definition: relative improvement RI = x/b − 1 (the digital bank's own "(x/baseline − 1)") — §Against what / ### What a relative improvement leaves out
- Example: +22.5% on precision@100 from b 0.40 (40→49/day) vs b 0.04 (4→4.9, under the 2-cards/day noise line); in-body exercise +50% at 0.06 vs 0.30 (3 vs 15 more/day) + what must match (k, fraud share, own baseline) — same ###
- Card network claim setup: "key revenue-driven product", 100M train / 10M later-period test sequences of 8 txns, 3M merchants, 2 classes, ~400 features; AD = "accuracy under an operational threshold", formula withheld, RI only; production model trained on complete rows, new models on merged rows with metadata-only gaps; task never called fraud — ### What the baseline was given
- Ablation ladder (figure ladder.svg): metadata-only histories −90.5 / −87.0; one-level history with features −9.1 (fields + 400 features squeezed by an MLP into one vector, one time transformer; report attributes the loss to features not related by attention within a transaction); single transaction with features, no history +7.7; 2-level history with features +7.3 (one transformer over fields + 400 features together, reduced to ONE vector per transaction, then a time transformer; history adds nothing; Task names this pair); feature-first design +19.2, explained by its two differences from the 2-level model: (1) the 400 features get their own transformer, compressed by a learned layer into a few vectors as wide as a basic field's, before being read with the basic fields (named difficulty, TGPT §3.1: in the 2-level model every field and feature must share one vector width inside one attention — wide enough for the merchant (3M values) is costly and overfits the 400 features, narrow enough for the features starves the merchant); (2) a second learned layer of the same kind turns that stage's output into several vectors per transaction (virtual tokens, Ref'd to transaction-foundation-models the-price-one-vector-per-event), not one; variant without that second layer −12.9; + LLM-initialised MCC vectors +22.5; Task: +7.7 vs +7.3 differ ABOVE ALL in history (separately trained single-transaction model); one number per variant, no repeated runs or interval reported (tie, not order); 3D-MTF rows (+14.6/+9.5) not used; features carry the metric (module's additive pattern) — ### The ladder behind the headline

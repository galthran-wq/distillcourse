# transaction-foundation-models — ledger

NOTE (sources): every institutional number is from industry reports with
relative results against undisclosed references; the lesson says "relative" and
names the reference each time. Brief corrections applied: the "203M" in the
lender's 7-days-on-8-A100s figure is 203M training ROWS (a 330M-parameter
joint-fusion run), not a 203M-parameter model; the profile ablation is reported
as Full vs Event-only (+46.8% P, +85.6% R for the model WITH the profile), and
the whole profile branch was removed (attributes + first-occurrence events
together); the event-bus staleness window's size is not given (lesson calls it
a delivery lag, never "seconds"); the "2.5–4×" hierarchy speed-up is the public
next-event model's L4 timing (1.5 h vs 3.9 h / 6.2 h), not the digital bank's.
The digital bank and the card network both encode AT SCORING TIME for fraud,
so the brief's "obvious attempt (encode at authorisation) fails" was not used;
the serving section presents two designs by task clock instead.

**Problem.** One bank, forty models, 26M customers in one store: can one encoder
be pretrained once and fitted per task, at what training and serving cost, and
do its gains come from the history alone or beside the features? Answer: a
hierarchical encoder (event encoder → history encoder) plus a profile state
makes 6,500-event histories fit; one encoder is adapted per task by a probe
(minutes) or rank-8 adapters (~1/8 of pretraining time); it meets the features
by early / late / joint fusion (joint +1.25% vs late +0.97% relative AUC on one
credit task's full data; early measured only in a separate 10M-row ablation,
0.51% below joint, so early vs late is an expectation from the wiring, never a
measured order); pretraining costs ~2 days on 16 H100s (10M) to ~2 weeks on 32
(1B); scale pays alone (0.750 → 0.787) far more than beside features (0.792 →
0.801); fraud encodes at scoring time, slow tasks store a dated, versioned
embedding with delta scoring; the vocabulary ties weights to one institution;
the four controlled comparisons on external fraud rank profile > adapters >
size > pretraining, none additive.

## Explained
- Definition: *transaction foundation model* (one encoder pretrained once on an institution's whole stream, adapted to many tasks; tokens = institution's own codes); framed as the third option after per-team end-to-end models and per-team pretraining — intro (before first ##)
- Running case SET UP in intro ("the digital bank"): 26M customers, 111 countries, 24B events over 25 months 2023–25, key–value tokens, 207B tokens = 8.6/event; six tasks (credit scoring, external fraud, lifetime value, abandoned-application re-engagement = whether a customer who abandoned a loan application opens the message sent to bring them back, recurring subscription, product recommendation); external fraud defined by the bank ONLY as binary classification scored by precision and recall, label contents and operating point undisclosed; each task has fixed train/validation/test partitions of undisclosed construction, shared by every comparison on it; every result relative to an undisclosed reference — intro (so every later digital-bank number has its setup in front of it)
- Flat cost: mean ~920 events/customer (recalls generative ex. 10: ~7,900 tokens, two 4,096 windows); cap 6,500 events → ~56,000 tokens → 3.1×10^9 pairs/layer vs 1.7×10^7 for 4,096 (186×) — §Thousands of events per customer / ### What one flat sequence would cost
- Definition: *event encoder*, *history encoder* (positions = time to last event), *hierarchical event encoder* (Ref generative §masking-a-window where the two-level shape was first met) — ### Two levels: events first, then the history
- Example: pairs flat 74E² vs hierarchical 74E + E²; E = 6,500 → 3.1×10^9 vs 4.3×10^7, ratio 73; general 74E/(E+74) → k² = 74. In-body exercise E = 920: 6.26×10^7 vs 9.14×10^5, ratio 68; history term dominates once E > 74 and stays quadratic in E (hierarchy divides by k², leaves the square; remedy deferred to ### The price) — same ###
- Measured (public next-event model, 100,000-client MBD cut, one L4, 655M tokens): hierarchy 1.5 h at 2,048/4,096/8,192 windows; flat 3.9 h / 6.2 h / not trained → 2.6–4.1×; *token decoder* named here (the next-event model predicts the next event token by token: 2 layers on top of the history encoder, reading its state and the next event's tokens — not part of the general hierarchy Definition); 4.75 = 2 + 6/8 + 2 vs 10 layer passes per token (event-encoder and token-decoder layers on every token, 6 history layers on one vector per ~8 tokens); feed-forward block glossed; measured 3–4×, not 70× (no KeyFact in this ###) — ### Seventy times fewer pairs, three times faster (figure hierarchy-speed.svg)
- Bottleneck of one vector per event: card network widened event vector 64 → 128 (better), 256 out of memory on 80 GB; *virtual tokens* (several vectors per event) named; *local attention* of width w: the ONE place ~wE pairs instead of E² is stated (bounds the history term the exercise left quadratic; cost linear in history length), −a quarter peak memory, +2.8% relative on an undisclosed anomaly accuracy — ### The price: one vector per event
- Aside: packing — files grouped by event count (rectangular history batches), event tokens concatenated in one buffer with a per-event attention kernel, 2–5× throughput vs padding; events truncated at 24 tokens (0.01%), profile at 200 — same §
- Truncation example: 4-year customer, ~20 events/day → 6,500 events ≈ 325 days; milestones ~3 years before the window — §What the newest 6,500 events leave out / ### Truncation cuts the oldest milestones (figure truncation.svg)
- Definition: *profile state* (attributes at the cut-off: plan, region, balance quantile; *first-occurrence events* with time to the cut-off, log seconds), profile encoder → one vector as the history encoder's first position; static attributes stated once = generative's shortcut rule; embedding = history encoder output at the profile position; [USR] / [EVT] named — ### A profile, encoded once (KEY IMAGE backbone.svg)
- Profile ablation (10M only, branch removed whole): external fraud +46.8% precision, +85.6% recall relative to events-only; credit PR-AUC +31.8%; LTV ~+2%; abandoned-application −3.0% PR-AUC; KeyFact: largest comparison on that task, smallest size only, mechanism (account age) is a reading; typology reading, explicitly marked an interpretation of an undefined label ("if the label holds both"): takeover = break from a long pattern vs a mule account with none — ### What it is worth on fraud
- Probe: standardised frozen vector (192 numbers at 10M), logistic regression, couple of minutes, settings-insensitive; tree on 192 columns works but needs tuning; uses: is the task worth it, which checkpoint, does a tokeniser change pay; limit: re-weights only what masked pretraining kept — §One encoder, forty tasks / ### The probe
- Definition: *low-rank adapter* (W x + B A x, B d_out×r, A r×d_in, W frozen, B starts at 0); named LoRA; rank ≤ r subspace; Example: 512×512 at r = 8 → 8,192 = 3.1%; 512×2,048 → 20,480 = 2.0%; in-body exercise: per layer 65,536 adapter vs 3,145,728 = 12d² weights; 25 layers (3 + 16 + 6) → 1.64M vs 78.6M = 2.1% of layers, ~1.6% of 100M (embedding table ~14.4M); rank 16 doubles; cost ~1/8 of pretraining wall-clock, 12 h to days; tasks share the frozen encoder, store only adapters + head — ### Low-rank adapters (figure adapter.svg)
- Measured (digital bank, fixed per-task splits, construction undisclosed): adapters over probe on external fraud +30.8 P / +27.4 R at 10M, +29.8 / +24.5 at 100M, +23.8 / +13.3 at 1B; adapters won every task and size, most on abandoned-application (+72.9% PR-AUC at 10M, the smallest-data task); shrinking margin read (labelled as a reading) as the probe's limit; pretrained + adapters over same architecture from scratch at 100M: fraud +8.0 P / +17.0 R, abandoned-application +18.6% PR-AUC, LTV / recurring +0.3–0.6%; = label-scarcity regime; large bank at 8M params, frozen encoder + small network trained on the frozen embedding, beside features 0.795 vs same architecture end-to-end 0.791 ("adapter" reserved for LoRA); MBD end-to-end 0.819 vs 0.802 recalled; KeyFact: probe is the screening instrument, not a weaker production model — ### What each choice buys, measured (figure lora-probe.svg)
- Definition: *embedding–feature fusion*: early (frozen embedding + features as columns of one model, typically a tree), late (encoder fine-tuned on labels alone, then tree on embedding + features), joint (encoder + neural feature network trained end to end, one loss) — §Meeting the features / ### Three wirings (figure fusion.svg; its SVG footer keeps 'two experiments, two references, not one ranking' so the figure stands alone; caption no longer repeats it); lender SET UP here, before the figure (L0g; later lessons Ref ### Three wirings): >100M customers, credit default = 65 days late 6 months after scoring, 203M training rows / 2M test rows from a later separate period, 291 features (transactions + bureau), LightGBM production = baseline of the full-data relative AUCs; the wiring SUGGESTS early < late < joint (early's embedding shaped by masked pretraining, re-weighted only; late tuned to the task but in isolation from the features; joint's loss sees what the features explain) — stated as an expectation, not yet a measurement
- Why a tree cannot join: joint fusion trains both branches by gradient from one loss; a tree's thresholds are found by search, its output is a step function, a split passes no gradient (Ref neural-tabular §four-things) → a tree cannot be a branch of that loss, and as the combiner it would block the gradient to the encoder → feature branch must be a network tuned to parity with the tree first; neural branch vs LightGBM relative AUC: MLP −0.44, cross network −0.09, MLP + periodic −0.23, cross + periodic +0.06, + weight decay +0.08 (periodic = generative's frequency features, but with learned frequencies where generative's were fixed at 2^l π; parity reached at the fourth architecture, the fifth edges past) — ### Why a tree cannot join
- Two experiments: full data, 330M encoder, late (encoder fine-tuned on a fifth of rows without features, tree on the rest) +0.97%, late (neural) +0.97%, joint +1.25% relative AUC over LightGBM on features; 10M-row ablation (a twentieth of rows, 1,024-token context) vs joint: features alone −0.96, encoder alone −2.83, early −0.51; ONE paragraph says neither holds all three (early not on full data, late not in ablation), joint>late and joint>early measured, early vs late never; as shares of joint's gain over features, early ≈ half (0.45 of 0.96, ablation), late ≈ four-fifths (0.97 of 1.25, full data) — fits the expectation, not one scale; KeyFact: joint over late 0.28 points ≈ a fifth of the gain, an engineering budget; 90% of redundant transaction features dropped (recalls limits); large bank = frozen encoder + small network on the frozen embedding trained with a tabular network (between early and joint) → 0.787 / 0.792 / 0.801 recalled — ### Two experiments, two references
- Public cut, as a TABLE (vs the tree on 114 engineered features, mean ROC-AUC over four product targets): logistic head on the frozen embedding alone 0.787 vs 0.816 (one test fold); embedding as extra tree columns level or lower (0.815 → 0.808 in one variant); *rank average* (tree + logistic head on embedding, profile fields, full-history token counts; equal weights fixed in advance) +0.014 to +0.018; control (same average, no embedding; one-hot profile fields + token counts) +0.001 to +0.008; embedding's own share 0.007 to 0.016 on each of 5 folds × 2 seeds; columns = early fusion as defined; the rank average fuses nothing inside a model (fitted apart, only rankings averaged); reading: the embedding earned its place as a second ranking, not as tree columns — ### A frozen embedding beside a tree on public data: extra columns or a second ranking (reading-foundation-model-claims §169 Refs this anchor)
- Cost card (table + cost.svg): public model 23M, one L4, 1.5–2 h ≈ 0.06–0.08 GPU-days; digital bank 10M 16 H100 ~2 days ≈ 32; 100M 16 H100 ~2 weeks ≈ 224; 1B 32 H100 ~2 weeks ≈ 448; adapters ~1/8 ≈ 4–56 on the same GPUs; lender joint run 8 A100 × 7 days = 56; lender daily scoring of 100M+ customers 60 A100 × ~5 h ≈ 12.5 per day; GPU types not one currency; readings: pretraining once per institution/architecture (40 adapters ≈ 5 pretrainings, 40 probes = minutes); wall-clock not ∝ parameters (1B = 100M time on 2× GPUs: runs differed in passes, utilisation or both); adapters' 4–56 GPU-days only if run on the same H100s (not stated by the source); 6ND estimate (generative ex. 10: 4.8 days) vs 224 GPU-days reported → plan from measured wall-clock; scoring recurring (daily pass ≈ a fifth of a joint run) — §What it costs / ### The cost card
- Scale: large bank 2M / 8M / 42M (contexts 256 / 1,024 / 2,048 events, confounded): alone 0.750 / 0.774 / 0.787; with features 0.792 / 0.796 / 0.801; features alone 0.792 (2M adds nothing); context alone at 8M 256 → 1,024: 0.790 → 0.795; digital bank, explicitly framed as a DIFFERENT question (each size vs that task's existing model, so it cannot separate alone from beside features; it shows size gains differ by task), 10M → 1B: credit PR-AUC +70.3 → +130.2%; fraud P +0.3 / +12.3 / +16.7 and R +33.4 / +66.4 / +64.7 at 10M / 100M / 1B (nearly all fraud gain reached by 100M); LTV −1.2 → +1.8; recurring flat +5–6; lender 24M / 330M always beside features, joint fusion, +0.37 / +0.62% relative AUC, each pretrained and fine-tuned on 20M rows, over the tree on features fitted on all 203M rows (a quarter point for ~14× parameters); KeyFact: scale pays alone, a hundredth or less beside mature features — ### Scale, alone and beside the features (figure scale.svg)
- Serving by task clock (Ref point-in-time two clocks): encode at scoring time for fraud (digital bank reads recent events from an event bus; card network 56M model 0.27 ms vs fine-tuned 7B text model 84.9 ms on one A100, heavier variant 2.5× latency within SLA; local attention recalled by back-reference, no wE restated); encode ahead and store for credit/marketing (lender daily batch 5 h on 60 A100s); GRU state advanced per event (Ref contrastive) chosen by a payment processor for this reason; transformer has no state — §Serving the embedding / ### Two clocks, two designs
- *Delta scoring*: re-encode clients with a new event or a changed now token (Ref generative "now" event); worked in two steps with φ(Δ) = 8 ln(1 + Δ/8), Δ = 86,400 g s: one more day adds 8 ln((g+1)/g) ≈ 8/g to φ (client B, 3 → 4 days: +2.3, 83.1 → 85.4); for g > 8 the increment is < 1 and the floor changes only when φ crosses an integer, on ~8/g of days (g = 30: 8 ln(31/30) = 0.26 → about one day in four; client C at 45 days: +0.18, stays 104); public data 57% new event + 32% changed token = 90% rescored (79% transactions only: 31% + 48%); reproduces a full pass exactly; saving grows with silent customers — ### Delta scoring (figure delta.svg: A dt=74 → 63, B 3 → 4 days dt=83 → 85, C 45 → 46 days dt=104)
- Event-bus staleness test: drop events younger than the bus's 99.9th-percentile delivery delay (size not given) → external fraud P/R ≤ 0.2% relative, credit ≤ 0.9%; covers a delivery lag, not a day-old embedding (stream features carry the hours; measure) — ### Stale by a delivery delay: the event-bus test
- Stored row contract: as-of time = history's cut-off (now event's date), not job time; checkpoint id + vocabulary fingerprint (public model refuses mismatched vocabulary; one feature set per encoder version; a head valid only on its version); parity extended to histories: present transactions as of score date, diff against snapshots → buy-now-pay-later prepayments rewrote earlier timestamps (leak); labels mature in 6 months → newest 6 months cannot enter the supervised fine-tune (whether pretraining reads them is not claimed) — ### What the stored row must carry

## Notation
- E events in a history; k tokens per event (8.6; 8 in the public model); w local-attention width
- W frozen weight matrix, d_out × d_in; A (r × d_in), B (d_out × r) adapter matrices; r rank (8); d model width (192 / 512 / 1,024 for 10M / 100M / 1B)
- L, L_e, L_h, L_t layer counts (exercise 4 only; L_t = token-decoder layers)
- φ(Δ) = 8 ln(1 + Δ/8) (recalled from generative, used in delta scoring)
- g days of silence (delta scoring); Δ gap in seconds (as before)
- Token names: [USR] (profile vector / embedding position), [EVT] (event vector)

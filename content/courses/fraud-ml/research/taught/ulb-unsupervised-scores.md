# ulb-unsupervised-scores — ledger

**Problem.** A coursework k-means run on the ULB card set reports a cluster
that is 71% fraud on its test split (base rate 0.18%), yet the rule built on
it alerts 29% of the test payments: where do the 71% and the flood come
from, and what do the module's label-free scores deliver on real card data
under AP and P@100? Answer: the 71% exists because SMOTE made frauds 43% of
the training set (k-means becomes a nearest-centroid classifier on labels;
the elbow is the resampler's); the flood exists because the test split was
standardised with its own statistics (its own mean moves the genuine cloud
from the genuine centre to the resampled set's mixed mean beside a fraud
centre, the main cause; its own spread then stretches it across); on a
day-1 → day-2 split (the first forward test of the module's scorers: earlier
ULB runs scored the whole file in place, with no supervised baseline), label-free distance and
isolation scores tie the logistic regression's AUC (0.96) at a tenth to a
third of its AP; the small-cluster reading of k-means finds a pure fraud
group (P@100 0.69) only for K 5–18, a window only labels can choose.

NOTE (syllabus): the course.yaml `opening` sentence 2 ("Alerting every
member of that cluster still floods the queue") and the `goal` ("explain
why a cluster that is 71% fraud still floods the queue") are contradicted
by the source run: the 71% cluster alone is 166 test payments (~280/day of
the full file, under 3× the budget); the flood is the rule that alerts
every cluster whose training rows were mostly fraud (24,924 test payments).
The lesson opens with a corrected sentence 2 ("The rule built around it,
which alerts every payment in the clusters whose training rows were mostly
fraud, still floods the queue."; validate warns `opening-first`); the human
should update course.yaml `opening` sentence 2 and the `goal` to that wording.

## Explained
- The coursework pipeline in eight steps (figure pipeline.svg): random 70/30 split (199,364 / 85,443; run's test 154 frauds, training 338); SMOTE (DMwR defaults: 2 synthetic per fraud, keep 2× as many genuine as synthetic: 338 → 1,014 fraud, 199,026 → 1,352 genuine, 2,366 rows, 43% fraud); ROSE defined (new training set of the split's size, half each class, each row = random real row of the drawn class + Gaussian noise with per-column width ∝ the class's spread; every row synthetic); drop Time/Class; standardise resampled set by its own mean/sd; elbow defined (bend of within-cluster SS vs K): K = 3 SMOTE, 4 ROSE, 25 starts; name clusters by majority class of training rows; standardise test split by its own mean/sd; assign to nearest centre; alert fraud-named clusters — §The coursework pipeline, run as written / ### Eight steps from a split to an alert
- The run's per-cluster test table (SMOTE A 24,730/28, B 47/119 = 71.7%, C 60,512/7; ROSE 1 193/10, 2 57/112 = 66.3%, 3 43,334/5, 4 41,705/27); a cluster's fraud share = precision of a rule alerting all of it; size decides budget fit — ### What the run reported
- Worked Example: B alone 166 alerts, precision 0.72, recall 0.77, ≈ 280/day of the full file; rule A+B 24,924 alerts, 147 frauds, precision 0.0059, recall 0.95, ≈ 41,500/day = 29% of ~142,000/day; conversion: test count / (0.3 × 2) = per day of full file. In-body exercise ROSE: cluster 2 169 alerts 0.66 / 0.73; rule 42,104 alerts, 149 frauds, 0.0035, 0.97, ≈ 70,000/day (half the stream). (No KeyFact here.) — same ###
- Five reruns (Python, other random splits): own-scaling purest cluster 68–80% on 122–163 test payments; rule flags 16,000–25,000 in four of five, 237 in the fifth — ### The run is not a fluke
- Without resampling (K = 3): purest test cluster 6,138 payments / 37 fraud (0.6%, 3.5× base rate); across splits 0.3–0.7%; ≈ 10,000 alerts/day — §Where the 71% comes from / ### Without resampling, no cluster is mostly fraud
- Elbow figure (elbow.svg, the rerun whose training split holds 349 frauds → 1,047 SMOTE fraud rows, named in the text): no resampling ≈ −3% WSS per added cluster, no elbow; SMOTE first split −30% cuts off 334 pure-fraud rows (of 1,047); ROSE −22%; bend = where fraud groups have centres; elbow is the resampler's — ### The elbow belongs to the resampler
- Resampled k-means + naming = nearest-centroid classifier fitted on labels (supervised regime); the 71% measures labelled centres, not unlike-normal. KeyFact: resampling is a use of labels; any score fitted after it (or after label-cleaning the sample, e.g. the genuine-row AE) belongs in the supervised rows of a comparison — ### A classifier trained on labels
- Flood mechanism, two statistics undone one at a time (a different rerun, named in the text as the split whose test part holds 139 frauds; split seed 2; 353 training frauds → 1,059 SMOTE fraud rows, 2,471 rows): (1) MEAN — standardising puts the subtracted mean at the origin; the resampled set's mean is a genuine/fraud mix, so in training coordinates genuine rows sit off the origin away from frauds: G centre (0.6, 0.5), F2 (−1.0, −0.6), F1 (−1.7, −2.4) on V14 × V17 in training sds; test split mean (99.8% genuine) at (0.68, 0.52) next to G; own-mean centring moves the cloud to the origin, ≈ 0.7 / 0.5 sd toward F2; in all 29 columns the cloud centre goes from 0.2 from G to 2.0 from G / 2.3 from F2 (near the boundary) — ### The mean: the genuine cloud is moved toward the frauds. (2) SPREAD — test sd = 0.218× training on V14, 0.156× on V17 → ×4.6, ×6.4; stretches the re-centred cloud across the boundary — ### The spread: the cloud is stretched around its new centre. FigureSequence shift-1..4 (key image shift-4): training G 1,412 genuine + 227 fraud, F1 0 + 223, F2 0 + 609 (2,471 rows); training scaling G 85,310/33, F1 39/31, F2 94/75 (133 alerts, 106 fraud); own mean only G 63,764/11, F1 48/39, F2 21,631/89; own mean + spread G 60,139/6, F1 152/107 (run's B counterpart, stretch pushes frauds outward), F2 25,152/26 (the flood); own spread only around training mean: 134 alerts (= training). Five splits: in the four that flood, centring alone 11,000–22,000 alerts, spread alone 134–150. Task: predict where the test mean goes (frame 3) and what the smaller spread does (frame 4)
- Repair = scaler fitted on training block, applied unchanged (Ref neural-tabular): five splits, SMOTE rule alerts 81–156 test payments, 75–82% fraud, recall 43–83%; ROSE 129–152 at ~80%. KeyFact: a test payment must be placed in the coordinates its model was fitted in (~25,000 false alerts). Repaired rule = supervised, ~80% precision on 135–260 alerts/day, unordered inside — ### Placing the test split with the training ruler
- Forward test framed in the opening: earlier ULB results (density: fraud's 10 nearest rows 59% fraud; isolation-forest: whole-file ψ sweep AP 0.20–0.28, AUC 0.95) scored the file in place, AP only, no supervised baseline; AE and small-cluster results came from simulator/PaySim
- Day split SET UP (later lessons Ref `ulb-unsupervised-scores#the-split-the-inputs-the-metrics`): section opens on which split is honest: random split has two leaks (later payments in training; one card on both sides, Ref delayed-labels shuffled split); keeping cards apart impossible (no card column); a cut in time removes the first leak and needs no card; day 1 = Time < 86,400 s: 144,786 payments / 281 frauds (0.19%); day 2: 140,021 / 211 (0.15%); no delay block (no label dates) → supervised slightly optimistic; inputs V1–V28 + log(1 + Amount), standardised with day-1 mean/sd; Time dropped (day-2 values beyond day-1 range); metrics ROC-AUC, AP, P@100 on payments (no cards), ceiling 1; F1 at a threshold = one cut nobody chose — §Scores at the budget / ### The split, the inputs, the metrics

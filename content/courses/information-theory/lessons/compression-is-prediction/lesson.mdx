A predictive model defines a compressor and a compressor defines a
predictive model; cross-entropy on a stream equals achievable compressed
size in bits.

The course's seventh move prices a wrong model. <Ref lesson="kl-divergence"/>
charged the mismatch between a source $p$ and a model $q$ at $D(p\,\|\,q)$
extra bits per symbol, and <Ref lesson="cross-entropy-loss"/> identified the
sum of that charge and the source's own entropy, $H(p,q) = H(p) +
D(p\,\|\,q)$, with the training loss of a probabilistic model. Both results
are expectations quoted in bits, with no file anywhere in them, so what
stands open is whether "bits" is an accounting unit or a measurement: whether
the number printed at the end of a training run is the size of something.
This lesson closes that with two constructions, one in each direction, and
prices what each costs.

The route: the model-to-compressor direction and its two-bit guarantee, the
compressor-to-model direction and the wasted bits it exposes, the per-symbol
accounting that links them, the price of learning a model while coding with
it, the ladder measured on English, and what a compression ratio is and is
not evidence of.

## Direction one: a model and a coder make a compressor

The training loss of the previous lesson is a sum of surprisals. To turn it
into a file, something must convert those surprisals into bits at the rate
the model quotes them, without rounding.

For the rest of this lesson a *model* is anything that answers one question:
given the symbols already sent, what is the probability of each possible next
symbol? Write the answer $q(x_t \mid x_{<t})$, a distribution over the
alphabet, strictly positive on every symbol. A table of letter frequencies
answers that question (ignoring the context), a running count of what has
followed each letter so far answers it, and so does a network with seventy
billion parameters. The coder never asks where the numbers came from.

That indifference is a property of the coder built in
<Ref lesson="arithmetic-coding"/>, which represents a whole message as a
subinterval of $[0,1)$: at step $t$ it subdivides the current interval in
proportion to the distribution the model supplies and keeps the piece
belonging to the symbol that occurred. Nothing about the subdivision requires
the distributions at different steps to be related, so the model is a
replaceable module sitting beside a fixed coder.

<Theorem title="the coding cost of a model (Cover &amp; Thomas 13.3)">
Let $q$ assign a positive conditional probability $q(x_t \mid x_{<t})$ to
every symbol at every step, and let $x_{1:n}$ be any stream. The arithmetic
coder driven by $q$ emits a decodable binary string of length

$$
\ell(x_{1:n}) \;\le\; -\log_2 q(x_{1:n}) + 2
\;=\; \sum_{t=1}^{n} -\log_2 q(x_t \mid x_{<t}) \;+\; 2 \quad \text{bits.}
$$

<Proof>
Each step multiplies the width of the current interval by the probability of
the symbol taken, so after $n$ steps the width is
$w = \prod_t q(x_t \mid x_{<t}) = q(x_{1:n})$, and the equality on the right
is the chain rule with a logarithm applied.

For the bound, put $k = \lceil -\log_2 w \rceil + 1$, so that
$2^{-k} \le w/2$. The dyadic cells $[m2^{-k}, (m+1)2^{-k})$ tile $[0,1)$ and
have width at most half the final interval's, so at least one of them lies
entirely inside it; transmit the $k$ bits of that cell's left endpoint. Then
$k < -\log_2 w + 2$.

Decodability: the transmitted cell lies inside the final interval, hence
inside every interval along the walk, so a receiver running the same model
reproduces the subdivisions and reads off each symbol in turn. Termination is
handled by an end-of-stream symbol, which costs its own surprisal and nothing
more. Finite-precision arithmetic adds $O(n2^{-B})$ bits at $B$ bits of
precision, negligible at $B = 32$; the renormalization that achieves it is in
<Ref lesson="arithmetic-coding"/>.
</Proof>
</Theorem>

The right-hand side is the model's log-loss on the stream. Two bits are paid
once for the whole file, not once per symbol, which is what makes the
identity useful: on a megabyte of text the overhead is $2$ bits against
several million.

### A compressor built from counts, in four steps

The smallest model that is not fixed in advance counts what it has seen.
Laplace's rule adds one to every count before normalizing, so that no symbol
is ever assigned probability zero:

$$
q(a \mid x_{<t}) = \frac{F_a + 1}{(t-1) + |\mathcal{X}|},
$$

where $F_a$ is the number of times $a$ has occurred among the first $t-1$
symbols and $|\mathcal{X}|$ is the alphabet size.

<Example title="coding `aaba` with an add-one model">
Alphabet $\{a, b\}$, so $|\mathcal{X}| = 2$. Before any symbol arrives both
counts are $0$ and the rule gives $q(a) = q(b) = \tfrac12$.

| $t$ | counts $(F_a, F_b)$ | prediction $q(a)$ | symbol | its $q$ | bits charged |
| --- | --- | --- | --- | --- | --- |
| 1 | $(0,0)$ | $\tfrac{0+1}{0+2} = \tfrac12$ | $a$ | $\tfrac12$ | $\log_2 2 = 1.000$ |
| 2 | $(1,0)$ | $\tfrac{1+1}{1+2} = \tfrac23$ | $a$ | $\tfrac23$ | $\log_2 \tfrac32 = 0.585$ |
| 3 | $(2,0)$ | $\tfrac{2+1}{2+2} = \tfrac34$ | $b$ | $\tfrac14$ | $\log_2 4 = 2.000$ |
| 4 | $(2,1)$ | $\tfrac{2+1}{3+2} = \tfrac35$ | $a$ | $\tfrac35$ | $\log_2 \tfrac53 = 0.737$ |

Total: $4.322$ bits. The product of the four probabilities is
$\tfrac12 \cdot \tfrac23 \cdot \tfrac14 \cdot \tfrac35 = \tfrac{1}{20}$, and
$\log_2 20 = 4.3219$, which is the same number: the charges are the
surprisals of one sequence probability, split across four steps. By the
theorem the emitted file is at most $6$ bits.
</Example>

Four symbols coded in $4.32$ bits is worse than four symbols coded in $4$
bits, which is what a fixed uniform model would have spent. The learning
model has not yet learned anything worth its cost. This is not an artifact of
the example: an estimator that starts from no information must pay for the
information it acquires, and the size of that payment is computed in the
adaptivity section below.

## Direction two: a compressor is a model

The first direction needed a coder to be supplied. The second needs nothing
at all: the model is already present inside any lossless compressor, in its
output lengths, and reading it out requires no cooperation from whoever wrote
the program.

Fix an input length $n$. A lossless compressor $C$ assigns each of the
$|\mathcal{X}|^n$ possible inputs an output $C(x)$ of length $\ell_C(x)$, and
distinct inputs must get distinguishable outputs or reconstruction would be
impossible. McMillan's theorem (<Ref lesson="kraft-inequality"/>, which
extended the codeword-length budget from prefix codes to every uniquely
decodable code) therefore applies to those lengths:

$$
c \;=\; \sum_{x \in \mathcal{X}^n} 2^{-\ell_C(x)} \;\le\; 1 .
$$

The quantities $2^{-\ell_C(x)}$ are non-negative and sum to at most one, so
they are a probability distribution up to a deficit. That is the implied
distribution of a code from <Ref lesson="source-coding-theorem-lite"/>, now
read off a whole program rather than a codeword table:

$$
q_C(x) \;=\; \frac{2^{-\ell_C(x)}}{c} .
$$

Files the compressor shrinks are files its implied model rates probable, and
the deficit $1 - c$ is not a rounding detail. Every file pays
$\log_2 \tfrac1c$ bits for the unclaimed budget, on top of whatever its model
gets wrong.

<Example title="reading the model out of a four-file compressor">
A compressor is queried on the four one-character files over
$\{A, B, C, D\}$ and returns outputs of $1$, $3$, $3$ and $3$ bits.

Budget: $c = \tfrac12 + \tfrac18 + \tfrac18 + \tfrac18 = \tfrac78$, which is
below $1$, so the code is incomplete and $\tfrac18$ of the budget buys
nothing.

Implied model: divide by $c$, giving
$q_C = (\tfrac47, \tfrac17, \tfrac17, \tfrac17)$. The compressor is betting
four to three that the file is `A`.

Slack: $\log_2 \tfrac87 = 0.193$ bits are wasted on every file regardless of
its contents. A code with lengths $(1,2,3,3)$ over the same alphabet has
$c = 1$ and wastes nothing, so the slack is a defect of this compressor, not
a cost of compression.

Conditionals: the model extends to next symbols through length increments.
If appending to the file `A` gives $\ell_C(AA) = 2$, $\ell_C(AB) = 3$ and
$\ell_C(AC) = \ell_C(AD) = 4$, the increments over $\ell_C(A) = 1$ are
$\Delta = (1, 2, 3, 3)$ and

$$
q_C(\cdot \mid A) \;\propto\; 2^{-\Delta}
= \left(\tfrac12, \tfrac14, \tfrac18, \tfrac18\right),
$$

which sums to $1$ and needs no normalization. A continuation that compresses
well is a continuation the compressor expects.
</Example>

### The bet a real compressor makes is visible in its ratio

The construction is not confined to toy tables. Take a file of $10^6$
characters, each independently `0` with probability $0.99$ and `1` with
probability $0.01$. Its entropy is $H_2(0.01) = 0.0808$ bits per character,
so an ideal coder stores it in $10^6 \times 0.0808 / 8 \approx 10{,}100$
bytes, about $1.01\%$ of the raw size. gzip produces $20{,}646$ bytes, or
$2.1\%$: it spends $0.165$ bits per character where $0.0808$ would do.

Read through the correspondence, that measurement prices gzip's model. Its
implied distribution is wrong, or wasteful, or both, by
$0.165 - 0.081 = 0.084$ bits per character, which is more than the entropy of
the source itself: over half of every bit gzip spends on this file pays for
its own model error rather than for the file's content.

Two limits on the reverse direction have to be stated. The first is
practical: $q_C$ is defined for every lossless compressor but computable for
almost none, since evaluating $q_C(x)$ exactly requires the normalizer $c$,
a sum over all $|\mathcal{X}|^n$ inputs. Next-symbol conditionals avoid the
normalizer and are cheap, which is how gzip has been driven as a generative
sequence model, one candidate byte at a time; the unconditional model is a
proof of existence, not an extraction procedure.

The second is structural: the construction consumes losslessness at its first
step, where distinct inputs were required to get distinguishable outputs. A
lossy codec maps many inputs to one output, so its lengths describe
equivalence classes of inputs rather than files, and the Kraft sum runs over
the classes. Two photographs that compress to the same JPEG file are assigned
the same $2^{-\ell_C}$, and nothing in the lengths says how the class divides
its probability between them, at any normalization. The reverse direction is
not degraded by lossiness; it is absent.

<KeyFact>
The forward direction survives lossiness applied to what quantization keeps:
the quantized representation is coded losslessly and the identity prices those
bits exactly, which leaves the discarded remainder to be priced against
distortion instead, by the curve of <Ref lesson="rate-distortion"/>.
</KeyFact>

## The accounting: bits per symbol is a floor plus a mismatch

Two constructions establish that models and compressors are the same object.
What they cost follows from a decomposition the course already has.

<Ref lesson="source-coding-theorem-lite"/> split the expected length of any
prefix code into three terms: the source's entropy, the divergence of the
code's implied bet from the truth, and the Kraft slack. The arithmetic coder
has no slack to speak of and no integer-length rounding, so for an i.i.d.
source $p$ coded under a fixed model $q$ the accounting collapses to two
terms plus the fixed overhead:

$$
\frac{\mathbb{E}[\ell(x_{1:n})]}{n}
\;=\; \underbrace{H(p)}_{\text{the source's}}
\;+\; \underbrace{D(p\,\|\,q)}_{\text{the model's}}
\;+\; \underbrace{O(1/n)}_{\text{the coder's}} .
$$

The first two terms are $H(p,q)$, the cross-entropy, by the decomposition of
<Ref lesson="cross-entropy-loss"/>. For a stationary source with memory, and
a model that uses context, the same computation runs per symbol in the
long-stream limit with the *entropy rate* of <Ref lesson="entropy-of-english"/>
in place of $H(p)$: the per-symbol cost of a model with unlimited context,
which for English is near $1$ bit per character.

Every term has an owner. The entropy rate belongs to the source and no
compressor moves it. The divergence belongs to the model, is zero only when
the model is exactly right, and is precisely what training on log-loss
shrinks. The overhead belongs to the coder and vanishes with stream length.

### The equality is an expectation, and files are finite

The identity above is an expectation over streams, and one stream is a
sample. Take the $99/1$ source again, with $H = 0.0808$ bits per character.
A ten-character stream of all zeros costs
$10 \times \log_2 \tfrac{1}{0.99} = 0.145$ bits under the true model, well
below the $0.808$ bits the expectation predicts for ten characters; a stream
containing two ones costs $13.4$ bits, sixteen times the prediction. Both are
coded by the same model with the same guarantee.

The fluctuation is the sum of $n$ per-symbol surprisals, so its standard
deviation grows like $\sqrt{n}$ while the mean grows like $n$: the measured
bits per character converge on the cross-entropy at rate $1/\sqrt{n}$. Here
the per-symbol surprisal has standard deviation $0.660$ bits, so the measured
rate scatters by $\pm 0.21$ bits per character at $n = 10$ and by
$\pm 0.0007$ at $n = 10^6$. This is why compression benchmarks are run on
files of megabytes and why a compression ratio measured on a single short
file is not a measurement of anything.

## Adaptivity: a model learned from the data need not be shipped with it

A model estimated from the file being compressed would seem to have to travel
with the file, since the decoder cannot use counts it has never seen. It does
not, and the reason is a one-line constraint on when the counts are read.

If the distribution used at step $t$ depends only on $x_{<t}$, the symbols
already transmitted, then the decoder can compute it too. The decoder decodes
symbol $1$ using the initial distribution, applies the identical update rule,
obtains the distribution for step $2$, decodes symbol $2$, and so on. Encoder
and decoder run the same program on the same data in the same order, so no
part of the model has to be transmitted. The add-one coder above is exactly
this arrangement, and its counts were never sent.

The alternative is a two-pass scheme: read the file, estimate the model, send
the model, then send the file coded under it. That header is a real cost, and
for short files it dominates.

that model's $4.03$ bits per character costs $806$ bits, so the two-pass
total is $1{,}238$ bits, against $952$ bits for a fixed code that assumes
nothing and spends $\log_2 27 = 4.76$ bits per character. Sending the model
does not pay until the data saved, $0.73$ bits per character, covers the
header: $432 / 0.73 \approx 592$ characters. The third bar is an adaptive
coder over the same alphabet: the same data cost, no header, and instead a
regret of order a hundred bits on this message, sized in the next
subsection.

### What adaptivity costs instead

Dodging the header is not free; the price is paid inside the data, as bits
spent on early symbols while the counts are still poor. The add-one coder
makes this exactly computable.

<Example title="the regret of the add-one coder">
For a binary stream with $F_a$ occurrences of $a$ and $F_b$ of $b$, the
add-one coder's probabilities telescope. At the step where $a$ occurs for
the $k$-th time the numerator is $k$; the denominators run
$2, 3, \ldots, n+1$ over the whole stream. Hence

$$
q(x_{1:n}) = \frac{F_a!\,F_b!}{(n+1)!},
\qquad
\ell \approx \log_2 \frac{(n+1)!}{F_a!\,F_b!} \ \text{bits.}
$$

Compare that with an *oracle*: the fixed model that already knows the final
frequencies, $q(a) = F_a/n$, which costs $n H_2(F_a/n)$ bits. At the fixed
ratio $F_a : F_b = 3 : 1$:

| $n$ | add-one coder | oracle model | difference | $\tfrac12 \log_2 n$ |
| --- | --- | --- | --- | --- |
| $4$ | $4.32$ | $3.25$ | $1.08$ | $1.00$ |
| $16$ | $14.92$ | $12.98$ | $1.94$ | $2.00$ |
| $64$ | $54.82$ | $51.92$ | $2.90$ | $3.00$ |
| $256$ | $211.57$ | $207.69$ | $3.89$ | $4.00$ |

Quadrupling the stream adds one bit to the difference, so the excess grows
like $\tfrac12 \log_2 n$ and its share of the file, $\log_2 n / 2n$, goes to
zero. One parameter is being learned, and it costs half a logarithm. A model
with $k$ free parameters costs about $\tfrac{k}{2} \log_2 n$ bits by the same
argument applied coordinate by coordinate.
</Example>

The two schemes are therefore the same size to leading order: a header
transmitting $k$ parameters to the precision the data supports also costs
about $\tfrac{k}{2}\log_2 n$ bits. Adaptivity wins on short files, where a
crudely coded header is pure overhead, and the two converge on long ones.

The construction has one debt, and it is not small. Replay works only when
the model is a function of the past. A pretrained network is not: its
parameters were fixed before the file existed, so either both parties already
hold it, or its description is part of the message. Charging float16
parameters against the file, a 70-billion-parameter language model scores an
adjusted compression rate of $14{,}008\%$ on a one-gigabyte corpus, meaning
the model outweighs the data it compresses by a factor of $140$. Which
accounting is the honest one is a live question, and this course takes it up
twice: <Ref lesson="minimum-description-length"/> makes model bits plus data
bits the object of study, and <Ref lesson="language-models-as-compressors"/>
measures the rates that are being argued over.

<KeyFact>
Adaptivity replaces a header with a regret of about
$\tfrac{k}{2}\log_2 n$ bits for $k$ parameters. That quantity is not an
artifact of the add-one rule: it reappears as the parameter cost of a
two-part code in <Ref lesson="minimum-description-length"/> and as the
per-model penalty in every description-length model selection.
</KeyFact>

## ★ The add-one coder is a mixture over models

The telescoped total of the last example has a second reading, which explains
where the $\tfrac12 \log_2 n$ comes from. The Beta integral gives

$$
\int_0^1 p^{F_a}(1-p)^{F_b}\,dp = \frac{F_a!\,F_b!}{(n+1)!} = q(x_{1:n}) .
$$

The add-one coder is coding under a *mixture*: it assigns the stream the
average of the probabilities that every fixed Bernoulli model would assign
it, weighted by a uniform prior over the parameter. It never commits to a
value of $p$, and its excess over the oracle is the cost of that hedge. After
$n$ symbols the models that fit the data occupy a parameter range of width
about $1/\sqrt{n}$, so the mixture assigns the stream a factor of roughly
$\sqrt{n}$ less probability than the oracle does, and $\log_2 \sqrt{n}$ is
the half-logarithm observed in the table.

The uniform prior is not the best choice. Minimizing the worst-case excess
over all Bernoulli sources selects the Jeffreys prior $\propto
1/\sqrt{p(1-p)}$, whose sequential form is the Krichevsky-Trofimov rule: add
$\tfrac12$ rather than $1$ to each count. Its worst-case redundancy is
$\tfrac{d}{2}\log_2 \tfrac{n}{2\pi e} + O(1)$ for $d$ free parameters, which
is the same leading term with the best constant. Nothing later in this course
depends on the constant.

## The ladder, measured

The correspondence and its accounting are general. The ladder of models for
English gives them numbers, and each rung is now a file size rather than a
bound.

space. Attaching an arithmetic coder to each of those models turns the column
of rates into a column of file sizes; a paragraph of $1{,}200$ characters
gives the scale.

| uniform over the 27 symbols | $4.76$ | $714$ bytes |
| letter frequencies | $4.03$ | $605$ bytes |
| one letter of context | $3.32$ | $498$ bytes |

## The scoreboard: what a compression ratio measures

The ladder priced models the course built. The same number prices models it
did not build, which is what makes compression a measurement instrument
rather than a piece of engineering.

A compression ratio has properties an evaluation metric rarely has. It is
held out by construction: the decoder must reproduce the file exactly, so
nothing can be smuggled into the score by fitting the test data, unless the
fit is also transmitted, in which case it is charged. It has no free
parameters of its own, no threshold, no averaging convention, no choice among
several defensible summaries. And it is stated in the same unit as the
training loss, which is what the first section established.

### A ratio is an upper bound, not an estimate

What it is not is an estimate of the entropy rate. The accounting gives
bits per symbol $\ge$ entropy rate, with the gap equal to the model's
divergence plus slack, so a ratio is an upper bound and nothing more. gzip's
$2.1\%$ on the sparse file above sits at twice the source's true rate. Any
inference from a compression ratio to the information content of a source
runs the inequality backwards.

### The instrument measures a pair, not a compressor

A ratio reports the fit between a model class and a source, so the ranking of
compressors moves when the source moves.

<Figure
  src="./figures/benchmark-flip.svg"
  alt="Two grouped bar charts: on a 20,942-byte text file gzip reaches 39 percent against the count-based arithmetic coder's 61 percent, while on the sparse binary file gzip reaches 2.1 percent against the arithmetic coder's 1.4 percent, with the ideal at 1.01 percent"
  caption="The same two compressors, two sources, opposite rankings: gzip's repeated-string model fits prose and misses a skewed coin, and the count-based coder does the reverse."
/>

On a $20{,}942$-byte text file, gzip compresses to $39\%$ and the count-based
arithmetic coder of this lesson only to $61\%$: repeated words and phrases
are structure that letter counts cannot represent. On the sparse binary file
the ranking inverts, gzip reaching $2.1\%$ against the count-based coder's
$1.4\%$, because there are no repeated strings to find and the whole of the
structure is a single skewed frequency. Neither result is a fact about the
programs alone.

<KeyFact>
Two compression ratios are comparable only when both sides account for the
model the same way. A ratio that excludes a shipped model's own bits is
measuring a different quantity from one that includes them, which is why the
same language model can be reported as the best compressor ever measured and
as far worse than gzip.
</KeyFact>

What is established: a model and an arithmetic coder form a lossless
compressor whose output length is the model's log-loss on the stream plus two
bits; every lossless compressor carries an implied model $q_C \propto
2^{-\ell_C}$, so there is no model-free compression, only unstated models;
the expected size per symbol is the entropy rate plus the model's divergence;
and a model may be learned during coding at a cost of about
$\tfrac{k}{2}\log_2 n$ bits rather than a header. What is not established is
any floor below the entropy rate. <Ref lesson="kolmogorov-complexity"/> takes
up what happens when the model is allowed to be any program at all and the
shortest-program length replaces the distribution;
<Ref lesson="language-models-as-compressors"/> runs the first direction of
this lesson on a trained network and reports the rates.

## Exercises

<Exercise>
A memoryless model over $\{A, B, C\}$ assigns $q = (0.5, 0.3, 0.2)$ at every
step. A 12-symbol message contains six $A$s, four $B$s and two $C$s. Compute
the total coding cost from the surprisals, compute the model's cross-entropy
against the message's empirical distribution, and check that the emitted file
length agrees with both to within two bits. Use $\log_2 \tfrac{1}{0.3} =
1.737$ and $\log_2 \tfrac{1}{0.2} = 2.322$.

<Solution>
Surprisals: $6 \times 1 + 4 \times 1.737 + 2 \times 2.322 = 6 + 6.948 +
4.644 = 17.59$ bits.

Cross-entropy: the empirical distribution is
$\hat p = (\tfrac12, \tfrac13, \tfrac16)$, and

$$
H(\hat p, q) = \tfrac12(1) + \tfrac13(1.737) + \tfrac16(2.322)
= 0.500 + 0.579 + 0.387 = 1.466 \ \text{bits per symbol,}
$$

so $12 \times 1.466 = 17.59$ bits over the message. The two computations are
the same sum grouped differently: the per-symbol average of the charges is
the cross-entropy against the empirical distribution, whatever the order of
the symbols.

File length: $\lceil 17.59 \rceil + 1 = 19$ bits, which is within the
theorem's $17.59 + 2 = 19.59$. Every symbol order with these counts gives the
same $17.59$, because the model ignores context.
</Solution>
</Exercise>

<Exercise>
Consider the model that assigns probability $1$ to whichever symbol actually
occurs, at every step. Report the file size the construction produces for a
stream of $n$ symbols. Then explain what such a model implies about the
source, and why no model can behave this way on a source with a positive
entropy rate. Name the constraint that rules it out.

<Solution>
Size: $q(x_{1:n}) = 1$, so the coder's interval never narrows and the bound
gives $\ell \le -\log_2 1 + 2 = 2$ bits. The file is empty apart from
framing.

What it implies: a decoder holding this model reconstructs the stream from
nothing, so the stream is a constant of the model. That is consistent only if
the model was chosen after the data was known, in which case the choice
itself is the description and has not been counted. The stream has been moved
into the model, not compressed.

Why no source with positive entropy rate admits it: a model is a
distribution, so $\sum_{x} q(x) = 1$ over all $|\mathcal{X}|^n$ streams of
length $n$. Assigning $1$ to one stream forces $0$ on every other, and any
stream that then occurs costs infinitely many bits. At most one stream per
model can be free. Against an actual source the expected cost is
$\mathbb{E}[-\log_2 q] \ge n H_{\text{rate}} > 0$, by the same non-negativity
of divergence that puts the entropy floor under every code.

The constraint that rules it out is normalization, $\sum_x q(x) = 1$, which is
the Kraft budget of <Ref lesson="kraft-inequality"/> in probability form:
giving one outcome more probability takes it from the others, exactly as
shortening one codeword lengthens another.
</Solution>
</Exercise>

<Exercise>
Break this claim. "gzip compresses this file to $30\%$ of its size, so the
file's entropy rate is about $2.4$ bits per byte." Give two reasons the
inference fails, one about the direction of an inequality and one about what
gzip's model can represent, and support the first with a number from this
lesson.

<Solution>
**The inequality runs the other way.** Achieved bits per symbol equals the
entropy rate plus the model's divergence plus its Kraft slack, and the last
two terms are non-negative. So $2.4$ bits per byte is an *upper bound* on the
entropy rate, and treating it as an estimate assumes the divergence is zero,
which is the assumption that gzip's model is exactly right. The sparse binary
file of this lesson shows the size of the error available: gzip reaches
$2.1\%$, implying $0.165$ bits per character, where the true entropy is
$0.0808$. The bound overstates the rate by a factor of two, and there is no
general bound on how bad the overstatement can be.

**gzip's model class is narrow.** gzip is LZ77 matching over a 32-kilobyte
window followed by Huffman coding of the resulting literals and match
lengths, so the only structure it can represent is repeated byte strings
within that window, plus per-block symbol frequencies. A source with any
other kind of structure is invisible to it. A file of the digits of $\pi$, or
of a slowly ramping counter, is highly predictable and nearly incompressible
by gzip; its ratio would report a high entropy rate for a source with a very
low one.

**What the claim presumes.** An entropy rate is a property of a source, that
is, of a distribution over files. One file has no entropy rate, and any such
figure quoted from a single file is a statement about the model that produced
it.
</Solution>
</Exercise>

<Exercise>
The lesson asserted that no compressor beats the entropy in expectation and
used the assertion in the accounting. Prove it. Let $C$ be any uniquely
decodable lossless compressor on inputs of length $n$ from a source $p$.
(a) Show that $\sum_x 2^{-\ell_C(x)} \le 1$. (b) Deduce
$\mathbb{E}[\ell_C] \ge H(p_{1:n})$, and identify the two earlier results
each part relies on.

<Solution>
**(a)** Unique decodability means the map from input sequences to output
bitstrings is injective and stays injective under concatenation, which is
exactly the hypothesis of McMillan's theorem
(<Ref lesson="kraft-inequality"/>): every uniquely decodable code's lengths
satisfy the Kraft budget $\sum_x 2^{-\ell(x)} \le 1$. Nothing about the
compressor being a program rather than a table enters; the argument counts
sequences of codewords. A whole-file compressor is a code on the finite
alphabet $\mathcal{X}^n$, so the theorem applies verbatim with $x$ ranging
over the $|\mathcal{X}|^n$ possible files.

**(b)** Set $c = \sum_x 2^{-\ell_C(x)} \le 1$ and $q(x) = 2^{-\ell_C(x)}/c$,
a genuine distribution. Then $\ell_C(x) = -\log_2 q(x) + \log_2 \tfrac1c$
and, taking expectations under $p$,

$$
\mathbb{E}[\ell_C]
= \sum_x p(x)\log_2 \tfrac{1}{q(x)} + \log_2 \tfrac1c
= H(p) + D(p\,\|\,q) + \log_2 \tfrac1c .
$$

Both correction terms are non-negative: $D(p\,\|\,q) \ge 0$ by Gibbs'
inequality (<Ref lesson="kl-divergence"/>), with equality only when $q = p$,
and $\log_2 \tfrac1c \ge 0$ because $c \le 1$. Hence
$\mathbb{E}[\ell_C] \ge H(p)$.

Part (a) rests on McMillan's theorem, which converts "is decodable" into an
arithmetic budget; part (b) rests on Gibbs' inequality, which converts "is a
distribution" into non-negativity of the mismatch. Equality needs both
$c = 1$ (no wasted budget) and $q = p$ (the right bet), and the second
requires $-\log_2 p(x)$ to be an integer for every $x$, which is why an
arithmetic coder rather than a symbol code is needed to approach the floor.
</Solution>
</Exercise>

<Exercise>
Build the ladder yourself. Take an English text file of at least $10$
kilobytes. Compute the total coded size, in bytes, under (a) a uniform model
over the byte values, (b) a letter-frequency model estimated from the file,
and (c) a bigram model estimated from the file with add-$\alpha$ smoothing at
$\alpha = 0.1$. Report those three numbers alongside (d) the size gzip
produces, and state which two rungs gzip's result falls between. State what
would count as agreement with this lesson's numbers.

<Solution>
**Method.** Coded size is $\sum_t -\log_2 q(x_t \mid \text{context})/8$
bytes; there is no need to run a coder, since the theorem says the file is
within two bits of that sum. Case folding and the treatment of punctuation
change every number, so fix one convention and state it. Smoothing is not
optional in (c): an unsmoothed bigram model assigns probability zero to any
pair absent from its own training text, and if the model is estimated from
the same file this shows up as a spuriously small size rather than as an
error.

**Expected values** on ordinary English prose, letters and spaces:

- (a) exactly $8.00$ bits per character, so the size equals the raw size.
- (b) about $4.0$ to $4.3$ bits per character, so roughly half.
- (c) about $3.3$ to $3.6$ bits per character. It should beat (b) by a few
  tenths of a bit and not more; a bigram model with $676$ cells estimated
  from $10$ kilobytes has a few hundred characters per cell at best.
- (d) gzip on $10$ kilobytes of English typically lands between $40\%$ and
  $45\%$, that is $3.2$ to $3.6$ bits per character, improving on longer
  files as its window fills: $39\%$ on the $21$-kilobyte file quoted in this
  lesson.

**Where gzip sits.** At this size, level with or just below the bigram model,
and between the letter-frequency rung and the entropy rate. Report which side
of (c) your file falls on and how the answer moves when you double the file
length, since gzip's advantage is repeated whole words, which a
two-character model cannot see and which need length to accumulate.

**What counts as agreement.** Rungs in the stated order, (a) $>$ (b) $>$ (c),
with (b) within a few tenths of $4.03$ bits per character; a bigram result
below $3$ bits per character on a file this small is evidence that the model
is scoring its own training data, not a prediction. Repeat with $\alpha = 1$
and $\alpha = 0.01$: the bigram number should move by a few tenths of a bit,
which is the honest size of the modelling choice.
</Solution>
</Exercise>

<Exercise>
You are given two memoryless models over $\{a, b, c, d\}$, $M_1 =
(\tfrac12, \tfrac14, \tfrac18, \tfrac18)$ and $M_2 = (0.4, 0.3, 0.2, 0.1)$,
and one test stream of $20$ symbols containing ten $a$, five $b$, three $c$
and two $d$. Decide which model compresses the stream to fewer bits
*without* coding it, then compute both totals and check. State which quantity
your decision compared and why the shortcut is available here.

<Solution>
**The decision.** The empirical distribution of the test stream is
$\hat p = (0.5, 0.25, 0.15, 0.10)$. Because both models are memoryless, the
coded length depends on the stream only through these counts, so compare the
cross-entropies $H(\hat p, M_i)$:

$$
\begin{aligned}
H(\hat p, M_1) &= 0.5(1) + 0.25(2) + 0.15(3) + 0.10(3) = 1.750 \ \text{bits/symbol},\\
H(\hat p, M_2) &= 0.5(1.322) + 0.25(1.737) + 0.15(2.322) + 0.10(3.322) = 1.776 .
\end{aligned}
$$

$M_1$ wins, narrowly.

**The check.** Totals over $20$ symbols: $35.0$ bits against $35.5$ bits, a
margin of half a bit, which is less than the coder's own two-bit overhead. On
this stream the two models are indistinguishable in practice, and a
conclusion about which is better would need a longer stream.

**What was compared, and why it was available.** The comparison is between
cross-entropies of the same empirical distribution against two models, which
is the same as comparing divergences: $H(\hat p) = 1.743$ bits, so
$D(\hat p\,\|\,M_1) = 0.007$ and $D(\hat p\,\|\,M_2) = 0.033$. The
shortcut exists because both models are memoryless, so the coded length is a
function of the counts alone. Given a model with context, two streams with
identical counts can cost very different amounts, and the sum must be taken
symbol by symbol in the actual order.
</Solution>
</Exercise>

<Exercise>
Your bigram model over a 26-letter alphabet needs a table of $26 \times 26$
counts, and it is not adaptive: the table is estimated in a first pass and
must be transmitted. Charge $16$ bits per count and compute the header size.
Then, taking the bigram model to cost $3.32$ bits per character and the
letter-frequency model $4.03$ bits per character with a negligible header,
find the file length in characters at which the bigram scheme's total first
beats the letter-frequency scheme's, and give both totals at $10{,}000$
characters.

<Solution>
**Header.** $26 \times 26 = 676$ counts at $16$ bits is $10{,}816$ bits,
about $1.35$ kilobytes.

**Break-even.** The bigram model saves $4.03 - 3.32 = 0.71$ bits per
character, so it must cover the header:

$$
n \;=\; \frac{10{,}816}{0.71} \;\approx\; 15{,}200 \ \text{characters.}
$$

Below roughly $15$ kilobytes of text the simpler model produces the smaller
file, despite being a worse predictor of every single character.

**At $n = 10{,}000$.** Bigram: $10{,}816 + 33{,}200 = 44{,}016$ bits. Letter
frequencies: $40{,}300$ bits. The better model loses by $3{,}716$ bits.

**What this is.** The total just computed, model bits plus data bits, is a
*two-part code*, and choosing the model that minimizes it is model selection
by description length, developed in
<Ref lesson="minimum-description-length"/>. Two refinements from that lesson
change the numbers but not the shape. Sixteen bits per count is wasteful: the
counts only need the precision the data supports, which brings the header
down to about $\tfrac{k}{2}\log_2 n$ bits with $k = 650$ free parameters,
around $4{,}300$ bits at $n = 10^4$ and a break-even near $5{,}500$
characters. And an adaptive bigram model pays that same
$\tfrac{k}{2}\log_2 n$ as regret instead, without a header, which is why
practical compressors are adaptive.
</Solution>
</Exercise>

Cross-entropy decomposes as H(p,q) = H(p) + KL(p||q); minimizing
cross-entropy loss minimizes the divergence of the model from the data
distribution.

The coding module established that a set of codeword lengths is a bet on a
distribution and that a wrong bet costs exactly $D(p\,\|\,q)$ extra bits per
symbol (<Ref lesson="kl-divergence"/>). What that leaves open is the object
machine learning actually minimizes, which is not a code length averaged over
a known source but a number computed from one observed label at a time. This
lesson closes the gap: the training loss of every probabilistic classifier and
language model is the expected code length of the previous lesson, unchanged,
so the number a practitioner watches fall during training is a compressed file
size and the only part of it an optimizer can move is the divergence. The
identity is an equality, not an analogy, and
<Ref lesson="compression-is-prediction"/> turns it into a working compressor.

The route: the loss on one example as the model's surprisal at the truth; the
average of that loss under the data, which is the cross-entropy; the
decomposition into an entropy floor plus a divergence and what it says about
the minimizer; the collapse to negative log-likelihood under one-hot labels;
the unbounded penalty on confident errors and the bounded gradient it
produces; and which comparisons a reported loss value permits.

## The loss on one example: the model's surprisal at the truth

Training begins with a bill charged for a single prediction, so that is where
the accounting starts. A three-class image classifier ends its forward pass in
a probability distribution over labels; on one input it outputs
$q = (0.70,\ 0.20,\ 0.10)$ over $\{\text{cat}, \text{dog}, \text{fox}\}$. The
true label is then revealed, and the *log-loss* on that example is
$-\log_2 q(\text{truth})$ bits. Nothing else in $q$ is billed.

<Example title="one prediction, three possible bills">
The output is $q = (0.70,\ 0.20,\ 0.10)$; the loss depends on which label
turns out to be true.

- Truth = cat: $-\log_2 0.70 \approx 0.51$ bits. Confident and right, so
  nearly free.
- Truth = dog: $-\log_2 0.20 \approx 2.32$ bits.
- Truth = fox: $-\log_2 0.10 \approx 3.32$ bits. The model rated the true
  label least likely and pays the most.

Three different bills for one unchanged prediction. The loss is small exactly
when the model put high probability on what happened.
</Example>

<Figure
  src="./figures/one-example-loss.svg"
  alt="A three-bar prediction with the true class marked, and an arrow carrying that single probability to a loss axis where minus log base two of 0.20 stands as a 2.32-bit column"
  caption="The loss reads one number off one bar: −log₂ of the probability the model gave the label that occurred."
/>

The function is not new. <Ref lesson="what-is-surprise"/> fixed the
information content of an event of probability $p(x)$ as its *surprisal*
$I(x) = -\log_2 p(x)$, the unique measure that adds over independent events;
the log-loss is that same function evaluated at the **model's** probability
for the outcome that occurred. In the first lesson the argument of the
logarithm was the world's probability; here it is the model's claim about it.
Nothing else changed, which is why the loss inherits the unit: a log-loss of
$2.32$ is $2.32$ bits, and by <Ref lesson="kl-divergence"/> those bits are the
length of the codeword this model's code would have spent on this label.

<KeyFact>
The loss reads exactly one coordinate of $q$: the true label's. The other
coordinates enter only through the normalization that forces $q$ to sum to
one, which is why a model can lower its loss while getting fewer labels right
(the loss-versus-accuracy counterexample in the exercises): the loss scores
the probability attached to the truth, not the ranking.
</KeyFact>

## Cross-entropy: the expected log-loss, and the price of a wrong code

One example gives one bill. Averaging the bill over the distribution the
examples are drawn from gives the quantity training actually minimizes, and
that average is already in the course. <Ref lesson="kl-divergence"/> computed
the expected cost of coding $p$-data with the exact code for $q$ as
$\sum_x p(x)\bigl(-\log_2 q(x)\bigr)$; on the running source
$p = (.5, .25, .15, .1)$ the uniform model
$q = (\tfrac14, \tfrac14, \tfrac14, \tfrac14)$ paid $2.000$ bits per symbol
against an entropy of $1.743$. That expected cost now gets its name.

<Definition title="cross-entropy">
For probability distributions $p$ and $q$ on a finite set $\mathcal{X}$, the
**cross-entropy** of $q$ relative to $p$ is

$$
H(p, q) = -\sum_{x \in \mathcal{X}} p(x) \log_2 q(x) \quad \text{bits,}
$$

the expected surprisal under the model $q$ when outcomes are drawn from $p$,
with the conventions of <Ref lesson="kl-divergence"/> at the edges: a term
with $p(x) = 0$ contributes nothing, and $H(p,q) = +\infty$ if some outcome
has $q(x) = 0 < p(x)$.
</Definition>

Three readings of the one sum, in the three settings the course uses it in:

- **Coding.** The expected codeword length when $p$-data is sent with $q$'s
  code (<Ref lesson="kl-divergence"/>).
- **Learning.** The expected log-loss of the model $q$ on examples drawn from
  the data distribution $p$.
- **The matched case.** $H(p, p) = -\sum_x p(x)\log_2 p(x) = H(p)$: a model
  that matches the truth pays exactly the entropy, and nothing pays less.

### Two speakers, two codes, four bills

The two arguments do different jobs, and the cleanest demonstration uses one
pair of distributions in all four combinations of data and code.

<Example title="four cross-entropies on one pair">
Two speakers use the same four words $\{\text{dog}, \text{cat},
\text{fish}, \text{bird}\}$ at different rates. Bob says
$p = (\tfrac12, \tfrac14, \tfrac18, \tfrac18)$; Alice says
$q = (\tfrac18, \tfrac12, \tfrac14, \tfrac18)$. Both distributions are
dyadic, so each has an exact matched code
(<Ref lesson="prefix-codes"/>): Bob's lengths are $(1, 2, 3, 3)$ in word
order, Alice's are $(3, 1, 2, 3)$.

The two entropies are equal: $H(p) = H(q) = 1.75$ bits. The two mismatches
are not.

$$
H(q, p) = \tfrac18(1) + \tfrac12(2) + \tfrac14(3) + \tfrac18(3) = 2.25
\text{ bits (Alice's words, Bob's code),}
$$

$$
H(p, q) = \tfrac12(3) + \tfrac14(1) + \tfrac18(2) + \tfrac18(3) = 2.375
\text{ bits (Bob's words, Alice's code).}
$$

The overheads are $0.500$ and $0.625$ bits per word. The larger one is Bob's,
and the reason is visible term by term: his commonest word, said half the
time, is the one Alice's code gives a 3-bit codeword. Alice's commonest word
gets 2 bits under Bob's code, and she says it half the time, so her penalty is
smaller.
</Example>

**Direction convention.** Cross-entropy is not symmetric, and the example is
the proof: $H(p,q) = 2.375 \ne 2.25 = H(q,p)$. The first argument supplies
the weights, because reality decides how often each outcome occurs; the second
supplies the surprisals, because the model decides what each outcome costs.
The training loss is always $H(\text{data}, \text{model})$, data first, in the
same order as $D(p\,\|\,q)$ in <Ref lesson="kl-divergence"/>.

<Solution>
The shared code's lengths are the surprisals under $m$:
$-\log_2 0.3125 = 1.678$, $-\log_2 0.375 = 1.415$,
$-\log_2 0.1875 = 2.415$, $-\log_2 0.125 = 3$.

$$
H(p, m) = \tfrac12(1.678) + \tfrac14(1.415) + \tfrac18(2.415) + \tfrac18(3)
= 1.870 \text{ bits,}
$$

$$
H(q, m) = \tfrac18(1.678) + \tfrac12(1.415) + \tfrac14(2.415) + \tfrac18(3)
= 1.896 \text{ bits.}
$$

Overheads: $0.120$ bits for Bob, $0.146$ for Alice. Both are far below the
$0.625$ and $0.500$ they paid under each other's codes, and the order between
them has reversed. Bob's mass is concentrated on one word, so he loses on that
word ($0.5 \times 0.678$ bits) and is refunded on the two words where $m$ is
more generous than he needs; Alice's mass sits on two words, both of which $m$
dilutes, and she is refunded only on the word she almost never says.

The transferable move: a code (or model) fitted to a mixture serves every
component of the mixture at a bounded cost, whereas a code fitted to one
component can be arbitrarily bad on another. This is the accounting behind
using one model for several sources at once.
</Solution>
</Exercise>

## The decomposition: a floor the model cannot move

Every mismatched pair in the grid cost strictly more than the entropy, and the
excess was exactly the divergence computed in the previous lesson. That
accounting is general, and it is this lesson's headline identity.

<Theorem title="cross-entropy decomposition">
For probability distributions $p$ and $q$ on a finite set,

$$
H(p, q) = H(p) + D(p \,\|\, q).
$$

<Proof>
Direct, by splitting one logarithm. For every $x$ with $p(x) > 0$,

$$
\log_2 \frac{1}{q(x)} = \log_2 \frac{1}{p(x)} + \log_2 \frac{p(x)}{q(x)} .
$$

Multiply by $p(x)$ and sum over $x$:

$$
-\sum_x p(x) \log_2 q(x)
= \underbrace{-\sum_x p(x) \log_2 p(x)}_{H(p)}
+ \underbrace{\sum_x p(x) \log_2 \frac{p(x)}{q(x)}}_{D(p \,\|\, q)} .
$$

The conventions of <Ref lesson="kl-divergence"/> cover the edges: terms with
$p(x) = 0$ contribute $0$ to all three sums, and a $q(x) = 0$ with
$p(x) > 0$ makes both sides $+\infty$.
</Proof>
</Theorem>

### The minimizer: training targets the divergence

The two terms have different owners. $H(p)$ is a property of the data
distribution alone, and no choice of $q$ moves it. $D(p\,\|\,q)$ is the
model's mismatch, and Gibbs' inequality (<Ref lesson="kl-divergence"/>, proved
there from the concavity of the logarithm) gives $D(p\,\|\,q) \ge 0$ with
equality if and only if $q = p$. Therefore

$$
\arg\min_q H(p, q) = \arg\min_q D(p \,\|\, q) = p .
$$

Minimizing the loss and minimizing model–data divergence are the same
optimization, and its unique solution is the data distribution itself. The
statement is stronger than a shared minimizer: the two objectives differ by a
constant, so for a model $q_\theta$ with parameters $\theta$,

$$
\nabla_\theta H(p, q_\theta) = \nabla_\theta D(p \,\|\, q_\theta)
$$

at every $\theta$, not merely at the optimum. Every gradient step a trainer
takes on the loss is, step for step, a gradient step on the divergence.

<KeyFact>
$H(p)$ is not observable from a training log. A loss of $0.9$ bits is
consistent with a perfect model on noisy labels and with a bad model on clean
ones, so an absolute loss value carries no information about model quality:
only differences between models scored on the same data with the same labels
do. The quantity that would answer the question, $D(p\,\|\,q)$, is exactly the
one that requires knowing $p$.
</KeyFact>

## ★ Why the logarithm and not some other penalty

The identity says what minimizing $-\log q(\text{truth})$ achieves. It does
not say why that penalty rather than another; this section answers that and is
not used later.

### Honesty: the log score is strictly proper

<Definition title="proper scoring rule">
A *scoring rule* charges a forecaster $S(r, x)$ when they report the
distribution $r$ and the outcome $x$ occurs. The rule is **proper** if every
forecaster whose actual belief is $p$ minimizes their expected charge
$\mathbb{E}_{x \sim p}[S(r,x)]$ by reporting $r = p$, and **strictly proper**
if $r = p$ is the only report attaining that minimum.
</Definition>

<Theorem title="the log score is strictly proper">
The rule $S(r, x) = -\log_2 r(x)$ is strictly proper on any finite outcome
set.

<Proof>
The expected charge is the cross-entropy, which the decomposition splits:

$$
\mathbb{E}_{x \sim p}\bigl[-\log_2 r(x)\bigr] = H(p, r) = H(p) + D(p\,\|\,r)
\;\ge\; H(p) .
$$

The first term does not depend on the report, so the charge is minimized
exactly when $D(p\,\|\,r) = 0$, which by Gibbs' inequality
(<Ref lesson="kl-divergence"/>) happens only at $r = p$.
</Proof>
</Theorem>

A model rewarded this way has no strategy available except honesty: hedging
away from its own belief always costs it bits.

### Locality: the bill reads one coordinate

Properness alone does not single out the logarithm. The Brier score
$S(r,x) = \sum_y \bigl(r(y) - \mathbf{1}[y = x]\bigr)^2$ is also strictly
proper. What separates them is **locality**: the log score depends only on
$r(x)$, the probability assigned to the outcome that happened, while the Brier
score also charges for how the remaining mass was distributed among outcomes
that did not happen.

<Example title="two reports the log score cannot tell apart">
Three classes $\{\text{cat}, \text{dog}, \text{fox}\}$, truth = cat.
Prediction A is $(0.70,\ 0.20,\ 0.10)$ and prediction B is
$(0.70,\ 0.05,\ 0.25)$.

Log score, both: $-\log_2 0.70 = 0.515$ bits.

Brier score, A: $(0.70-1)^2 + 0.20^2 + 0.10^2 = 0.09 + 0.04 + 0.01 = 0.140$.

Brier score, B: $0.09 + 0.0025 + 0.0625 = 0.155$.

The two reports differ only in outcomes that did not occur, and only the
non-local rule charges for the difference.
</Example>

<Figure
  src="./figures/locality.svg"
  alt="Two three-bar predictions sharing an identical 0.70 bar on the true class cat and differing on dog and fox, with the same log score of 0.515 bits under each and Brier scores of 0.140 and 0.155"
  caption="Locality: the log score reads only the true class's bar, so A and B cost the same; the Brier score charges 0.140 against 0.155."
/>

For sample spaces with at least three outcomes, the only smooth local proper
scoring rules are $a \log r(x) + b(x)$ with $a > 0$, affine relabelings of the
log score
([Bernardo 1979](https://projecteuclid.org/journals/annals-of-statistics/volume-7/issue-3/Expected-Information-as-Expected-Utility/10.1214/aos/1176344689.full)).

So the first section's observation that the loss bills exactly one coordinate
of $q$ was not a quirk of the definition. Demanding a penalty that is honest
and that looks only at what actually happened forces the logarithm, in the
same way that demanding additivity over independent events forced it in
<Ref lesson="what-is-surprise"/>. A locality-violating alternative such as the
Brier score is a legitimate loss with different behaviour: it is bounded, so
it cannot produce the blowup of the section after next, and it therefore
tolerates a confidently wrong prediction that the log score treats as a
catastrophe.

## One-hot labels: three names for one number

Classification datasets rarely ship a distribution over labels. The recorded
target is a single class $c$, which as a distribution is the point mass
$p = (0, \ldots, 1, \ldots, 0)$ with the $1$ in position $c$. Every term of
the general sum with $p(x) = 0$ vanishes, leaving

$$
H(p, q) = -\log_2 q(c) ,
$$

the log-loss of the first section. The decomposition sharpens too: a point
mass is the certain distribution, so $H(p) = 0$
(<Ref lesson="entropy-as-average-surprise"/>, where entropy was shown to
vanish exactly at certainty), and therefore

$$
H(p, q) = D(p \,\|\, q) = -\log_2 q(c) .
$$

For hard labels the cross-entropy **is** the divergence: no floor, minimum
loss $0$, attained only at $q(c) = 1$. One number carries three names:
cross-entropy loss, KL divergence from the label, negative log-likelihood.

### Over a dataset: the loss is the likelihood in another unit

Training averages the per-example loss over examples $x_1, \ldots, x_N$.
Grouping identical values turns that average into a cross-entropy against the
*empirical distribution* $\hat{p}(x) = \tfrac{1}{N}\#\{i : x_i = x\}$, the
fraction of the dataset equal to $x$:

$$
\mathcal{L} = \frac{1}{N} \sum_{i=1}^{N} \bigl(-\log_2 q(x_i)\bigr)
= \sum_{x} \hat{p}(x) \bigl(-\log_2 q(x)\bigr) = H(\hat{p}, q) .
$$

The same sum is $-\tfrac{1}{N}\log_2 \prod_i q(x_i)$, so minimizing the
average log-loss is maximizing the likelihood $\prod_i q(x_i)$ of the dataset.
Cross-entropy minimization, KL minimization and maximum-likelihood estimation
are one procedure in three vocabularies; the maximum-likelihood exercise below
does the derivation and identifies the independence assumption that licenses
the product.

The empirical distribution in the first slot is not a technicality. The
theorem's minimizer is whatever sits in that slot, and on finite data that is
$\hat{p}$ rather than $p$: a model with enough capacity minimizes the training
loss by reproducing the empirical distribution exactly, which for one-hot
labels means driving the training loss to $0$ while its divergence from the
real $p$ stays large. That gap is what regularization, early stopping and the
description-length penalty of <Ref lesson="minimum-description-length"/>
address, and none of it is visible inside the identity.

<KeyFact>
Whether the training loss says anything about $p$ is a condition on the model
class, not on the loss. On a fixed finite alphabet $\hat{p} \to p$ as $N$
grows, so a class fixed in advance and too small to fit the sample's noise has
its training minimizer converge to the minimizer against $p$. A class rich
enough to realize any assignment of labels to the $N$ training inputs drives
$H(\hat{p}, q)$ to $0$ whatever $p$ is, and the training loss then carries no
information about $D(p\,\|\,q)$. The missing term is the cost of naming which
member of the class was selected: <Ref lesson="minimum-description-length"/>
charges it explicitly, at about $(k/2)\log_2 N$ bits for $k$ parameters.
Overfitting is not a failure of the loss: it is the loss working correctly on
the wrong first argument.
</KeyFact>

## Confident and wrong: the price, and the gradient it produces

The logarithm is gentle near $q(\text{true}) = 1$ and violent near $0$. The
table that priced rare events in <Ref lesson="what-is-surprise"/> now prices
predictions.

<Example title="the price of confidence">
Per-example loss $-\log_2 q(\text{true})$ as the model's probability on the
truth falls:

| $q(\text{true})$ | loss (bits) |
| ---------------- | ----------- |
| $0.9$            | $0.152$     |
| $0.5$            | $1$         |
| $0.1$            | $3.32$      |
| $0.01$           | $6.64$      |
| $10^{-6}$        | $19.93$     |

Each factor of ten costs $\log_2 10 = 3.32$ bits, whatever the starting
point. One consequence is arithmetical: $131$ predictions at
$q(\text{true}) = 0.9$ cost about as much in total as a **single** prediction
at $q(\text{true}) = 10^{-6}$, since $131 \times 0.152 \approx 19.9$.

Two models on ten test examples with one-hot labels make the effect concrete.
Model A assigns $0.9$ to the true class on nine examples and $10^{-6}$ on the
tenth: average loss $(9 \times 0.152 + 19.93)/10 \approx 2.13$ bits. Model B
assigns $0.6$ to the true class on all ten: average loss
$-\log_2 0.6 \approx 0.737$ bits. Model B wins by a factor of nearly three
while being far less often confidently correct.
</Example>

### The gradient: unbounded loss, bounded step

An unbounded loss suggests an unbounded gradient, and a training run in which
one catastrophic example destroys the parameters. That is not what happens,
and the reason is where the loss meets the output layer.

<Example title="the gradient of a logistic neuron (MacKay 39.3)">
A binary classifier outputs $y = \sigma(a) = 1/(1 + e^{-a})$ from a scalar
*logit* $a$ — the unnormalized real-valued score the last layer emits, which
$\sigma$ squashes into a probability — and the target is $t \in \{0, 1\}$. In
nats, the loss is

$$
\mathcal{L} = -\bigl[\,t \ln y + (1-t) \ln (1 - y)\,\bigr] .
$$

Differentiate in two pieces. The logistic derivative is
$\mathrm{d}y/\mathrm{d}a = y(1-y)$, and

$$
\frac{\partial \mathcal{L}}{\partial y}
= -\frac{t}{y} + \frac{1-t}{1-y}
= \frac{y - t}{y(1-y)} .
$$

The product cancels exactly:

$$
\frac{\partial \mathcal{L}}{\partial a}
= \frac{y - t}{y(1-y)} \cdot y(1-y) = y - t .
$$

Numbers. A confidently wrong prediction, $y = 0.999$ with $t = 0$, costs
$-\log_2 0.001 = 9.97$ bits and produces a gradient of $0.999$. A
well-fitted example, $y = 0.9$ with $t = 1$, costs $0.152$ bits and produces
$-0.1$. The loss ratio is about $65$; the gradient ratio is about $10$, and no
output can push the logit gradient past $1$.
</Example>

The same computation runs on the multi-class output layer. A *softmax* is the
$k$-class counterpart of the logistic function, the map that turns a vector of
logits $z$ into a distribution by exponentiating and normalizing,
$q_j = e^{z_j} / \sum_i e^{z_i}$; it gives
$\partial \mathcal{L} / \partial z_j = q_j - p_j$, prediction minus target,
per logit (the softmax-gradient exercise below derives it). Two facts follow,
and they pull in opposite directions. The loss on one example is unbounded, so
a single confidently wrong prediction dominates the reported value of a
batch's loss. The gradient on one example is bounded by $1$ per logit, so that
same prediction contributes at most about ten times the pull of a mildly wrong
one. Confident errors dominate the reported number far more than they dominate
the update.

The cancellation is what makes the pairing work. The derivative of the loss
with respect to the probability, $\partial \mathcal{L}/\partial q = -1/q$,
does blow up as $q \to 0$; the softmax Jacobian contributes precisely the
factor that removes it. Replace the log-loss with squared error on the same
sigmoid output and the cancellation fails: the gradient picks up a factor
$y(1-y)$, which vanishes for exactly the confidently wrong predictions that
most need correcting.

Same setup as the worked example: a logistic neuron with logit $a$ and target

Compute this example's loss in bits and its gradient. Then take a batch of

### The endpoint: an exact zero costs everything

At $q(\text{true}) = 0$ the loss is $+\infty$. That is the missing-outcome
failure of <Ref lesson="kl-divergence"/>, a model whose support fails to cover
the data's, arriving inside a training loop. One example on which the model
assigned probability zero to what happened makes the average loss infinite,
and no accuracy elsewhere compensates.

Two mechanisms keep it from happening. A softmax cannot emit an exact zero in
exact arithmetic, since $e^{z}$ is positive for every finite logit; it can
underflow to zero in float32 below about $10^{-38}$, which is why the loss is
computed as $\log q = z_c - \log \sum_j e^{z_j}$ rather than by taking the
logarithm of a computed probability. That is the log-domain discipline of
<Ref lesson="what-is-surprise"/> in its numerical form: surprisals stay
representable where probabilities do not. Count-based models have no such
guarantee: an $n$-gram table assigns zero to every unseen symbol, so it must
be smoothed explicitly, as the previous lesson's mixing bound quantified.

<KeyFact>
Support coverage is a condition on the model, not a tuning parameter: the loss
is finite only if $q(x) > 0$ at every outcome the data can produce. The same
condition returns as a hard requirement in
<Ref lesson="compression-is-prediction"/>, where the coder must reserve a
nonzero interval for every symbol it might have to write, which is why the
compressor built there smooths its counts before coding a single bit.
</KeyFact>

## Reading a loss number: floors, label schemes and units

The identity makes the loss interpretable, and it also limits what may be
compared. Two loss values are comparable when they are computed on the same
data, against the same labels, in the same unit; published numbers routinely
differ in the second and third of those, and the decomposition says exactly
what changes.

### The floor is the label noise

Labels are not always certain. Where annotators genuinely disagree, the target
on an input is a distribution: with $p = (0.7, 0.3)$ on a binary task, the
best possible model $q = p$ still pays

$$
H(p) = 0.7 \log_2 \tfrac{1}{0.7} + 0.3 \log_2 \tfrac{1}{0.3} \approx 0.881
\text{ bits,}
$$

and a hedging model $q = (\tfrac12, \tfrac12)$ pays $1.000$ bit, of which only
$0.119$ is its own fault. A loss that stops falling at $0.9$ bits on this task
is a model that has finished learning, not one that has stalled.

The floor also moves on purpose. *Label smoothing*
([Szegedy et al. 2016](https://arxiv.org/abs/1512.00567), §7) replaces the
one-hot target with $(1-\varepsilon)$ on the true class and the remaining
$\varepsilon$ spread over the others; *distillation* replaces it with a
teacher model's output distribution. Both give the target a positive entropy,
and the reported loss inherits it.

<Example title="the same prediction, scored two ways">
A three-class model predicts $q = (0.70,\ 0.20,\ 0.10)$ and class 1 is
correct. Score it against a one-hot label and against a smoothed label with
$\varepsilon = 0.1$, that is $p = (0.90,\ 0.05,\ 0.05)$.

**One-hot.** $H(p) = 0$ and the loss is $-\log_2 0.70 = 0.515$ bits, all of it
divergence.

**Smoothed.** The floor is

$$
H(p) = 0.9 \log_2 \tfrac{1}{0.9} + 2 \times 0.05 \log_2 \tfrac{1}{0.05}
= 0.137 + 0.432 = 0.569 \text{ bits,}
$$

and the loss is

$$
H(p,q) = 0.9(0.515) + 0.05(2.322) + 0.05(3.322) = 0.745 \text{ bits.}
$$

The divergence is the difference, $0.745 - 0.569 = 0.176$ bits, which is also
what the direct sum gives:

$$
D(p\,\|\,q) = 0.9\log_2\tfrac{0.9}{0.7} + 0.05\log_2\tfrac{0.05}{0.2}
+ 0.05\log_2\tfrac{0.05}{0.1} = 0.326 - 0.100 - 0.050 = 0.176 .
$$

The prediction never changed. The reported loss rose by $45\%$ and the
model's own mismatch fell by $66\%$.
</Example>

<Figure
  src="./figures/soft-label-floor.svg"
  alt="Two horizontal cost bars for one unchanged prediction: against a hard label the whole 0.515-bit bill is divergence, and against a smoothed label a 0.569-bit floor is followed by only 0.176 bits of divergence for a total of 0.745"
  caption="One prediction, two label schemes: smoothing raises the reported loss to 0.745 bits while cutting the model's own excess to 0.176. The numbers are not comparable."
/>

At realistic scale the floor is large. Smoothing a $1000$-class problem with
$\varepsilon = 0.1$ gives the target entropy

$$
H(p) = 0.9 \log_2 \tfrac{1}{0.9} + 0.1 \log_2 \tfrac{999}{0.1}
\approx 1.47 \text{ bits} = 1.02 \text{ nats,}
$$

so a smoothed ImageNet classifier that predicts its target perfectly still
reports about one nat. A published loss of $1.3$ nats with smoothing and one
of $0.9$ nats without describe models whose divergences are $0.3$ and $0.9$
nats: the ordering of the reported numbers is the reverse of the ordering of
the models.

<KeyFact>
Smoothing and distillation change the training target, not the model, so two
such models are compared by scoring both against the same targets, which is
why validation loss is normally computed on hard labels even when training
used soft ones. The quantity that would be comparable across schemes,
$D(p\,\|\,q)$, needs the floor, and the floor is only known when the labels
were constructed rather than collected.
</KeyFact>

### Units: nats, bits per token, bits per byte

Frameworks compute the loss with natural logarithms and report **nats**. One
nat is $1/\ln 2 \approx 1.443$ bits (<Ref lesson="what-is-surprise"/>, where
the base was shown to be a choice of unit and nothing more), so a language
model at $2.1$ nats per token is at $3.03$ bits per token.

Bits per token is still not comparable across models, because the token is a
property of the tokenizer: a model with a larger vocabulary spends more bits
on each of fewer tokens for the same text. The comparable unit divides by
something the text has and the model does not choose, its length in characters
or bytes:

$$
\text{bits per byte}
= \frac{\text{bits per token} \times \text{number of tokens}}
       {\text{number of bytes}} .
$$

That is the unit in which a model's loss can be set beside a compressor's
output on the same file, which is what <Ref lesson="compression-is-prediction"/>
does with an arithmetic coder and what
<Ref lesson="language-models-as-compressors"/> measures on real corpora. The
last exercise runs the conversion on a reported training loss.

What is established: the training loss of a probabilistic classifier is the
cross-entropy $H(p,q)$, which splits into an entropy floor set by the labels
and a divergence owned by the model; minimizing it is minimizing that
divergence, is maximizing likelihood, and on one-hot labels is charging the
model its own surprisal at the truth. What is not yet built is the coder. The
identity says a model's loss equals a code length, but not how to obtain the
bits; <Ref lesson="compression-is-prediction"/> supplies the construction, and
the file it produces is the loss of this lesson written out.

## Exercises

<Exercise>
Two models are evaluated on the same five-class test set. Model A's framework
log reports $0.85$ nats per example, scored against smoothed targets carrying
$0.8$ on the true class and $0.05$ on each of the other four. Model B's log
reports $1.05$ bits per example, scored against hard one-hot labels. Decide
which model has the smaller mismatch with the target it was scored against,
giving the number that decides it; check that model A's reported value is
even admissible; and state what would have to be recomputed before the two
can be ranked as models of the same thing.

<Solution>
**One unit.** $0.85$ nats $\times\, 1.443 = 1.226$ bits per example for A,
against $1.05$ bits for B. On the reported numbers B is ahead by $0.18$ bits.

**The floors differ.** A's target has

$$
H(p) = 0.8\log_2\tfrac{1}{0.8} + 4 \times 0.05\log_2\tfrac{1}{0.05}
= 0.258 + 0.864 = 1.122 \text{ bits,}
$$

while B's one-hot target has $H(p) = 0$. Subtracting: $D(p\,\|\,q) = 1.226 -
1.122 = 0.104$ bits for A and $1.05 - 0 = 1.05$ bits for B. A's own mismatch
is about a tenth of B's, and the ranking by reported loss is the reverse of
the ranking by divergence.

**Admissibility.** $H(p,q) \ge H(p)$ always, so any value below $1.122$ bits
($0.778$ nats) reported against A's targets would be arithmetically
impossible: a bug in the loss, in the logging, or in the targets as described.
A's $1.226$ clears the floor, and clears it by little.

**What is still not comparable.** The two divergences are measured against
two different targets, so "A is ten times closer" is a statement about
different questions. Ranking them as models of the same thing requires
scoring both against one target — in practice the hard labels, which is why
validation loss is normally computed on hard labels even when training used
soft ones. Rescored that way A's number falls, because the $1.122$-bit floor
it was carrying disappears and only $-\log_2 q(\text{true})$ remains: a model
holding exactly the $0.8$ it was trained to hold on the true class reports
$0.322$ bits. That is the number to set beside B's $1.05$.
</Solution>
</Exercise>

<Exercise>
Consider the per-example loss $-\log_2 q(\text{true})$ as $q(\text{true})$
approaches each end of $[0, 1]$. State both limits. Then consider the standard
implementation guard, clipping $q(\text{true})$ to $[\varepsilon, 1]$ with
$\varepsilon = 10^{-7}$: give the largest loss it permits, and state what the
guard does to the objective being minimized, specifically whether $q = p$ is
still the unique minimizer of the clipped loss.

<Solution>
**Limits.** As $q(\text{true}) \to 1$ the loss $\to 0$: a certain and correct
model is free. As $q(\text{true}) \to 0^+$ the loss $\to +\infty$, and at
exactly $0$ it is $+\infty$, matching the convention of
<Ref lesson="kl-divergence"/> and the fact that a code for $q$ reserves no
codeword for an outcome $q$ calls impossible.

**With clipping.** The largest permitted loss is
$-\log_2 10^{-7} = 7 \log_2 10 \approx 23.3$ bits per example, so no single
example can contribute more than that.

**What it changes.** Below $\varepsilon$ the clipped loss is constant, so its
derivative there is zero: a model that assigns $10^{-9}$ to an outcome that
occurs receives no gradient pushing it up, and the failure is invisible to the
optimizer. Uniqueness of the minimizer goes too. If $p$ has a component below
$\varepsilon$, then every $q$ that agrees with $p$ above $\varepsilon$ and is
arbitrary below it achieves the same expected loss, so $q = p$ is still a
minimizer but no longer the only one. The decomposition's equality case no
longer applies either, because the clipped loss is not $H(p,q)$. The guard
buys numerical safety by flattening exactly the region where the log score
does its distinctive work. Flooring the model instead, as with the mixture
$q_\lambda = (1-\lambda)q + \lambda u$ bounded in
<Ref lesson="kl-divergence"/>, leaves the objective itself intact and keeps
$q_\lambda = p$ the unique optimum whenever $p$ is reachable.
</Solution>
</Exercise>

<Exercise>
"Model A has lower average cross-entropy than model B on the same dataset, so
model A puts the highest probability on the correct class more often." Give a
two-example binary dataset with one-hot labels on which the two orderings
disagree, and name the property of the loss that permits it.

<Solution>
**A counterexample.** Two examples, one-hot labels, binary classes; report
each model's probability on the true class.

- Model A: $0.51$ and $0.51$. Correct top class on both examples, so accuracy
  $100\%$. Average loss: $-\log_2 0.51 = 0.971$ bits.
- Model B: $0.90$ and $0.30$. Correct top class on the first only, so accuracy
  $50\%$. Average loss: $(0.152 + 1.737)/2 = 0.944$ bits.

Model B has the lower loss and half the accuracy.

**Why it is possible.** Accuracy sees only whether $q(\text{true})$ clears
$\tfrac12$: a threshold crossing and nothing else. The loss is a
function of $q(\text{true})$ itself, grows without limit as that probability
falls, and is averaged. A model can therefore buy a large improvement on one
example by being very confident and correct there, and pay only a bounded
penalty for falling just under the threshold elsewhere. The step that fails in the claim is the
move from "smaller average of a nonlinear function of $q(\text{true})$" to
"more frequent $q(\text{true}) > \tfrac12$"; nothing connects the two, and
this is the same one-coordinate reading noted in the first section.

Practical form: loss and accuracy can move in opposite directions during
training, and a model tuned for one is not tuned for the other.
</Solution>
</Exercise>

<Exercise>
A network produces logits
$z = (z_1, \ldots, z_k)$, the model is $q_j = e^{z_j} / \sum_i e^{z_i}$, and
the target is a distribution $p$ over the $k$ classes (one-hot or not). With
the loss in nats, $\mathcal{L} = -\sum_j p_j \ln q_j$, show that

$$
\frac{\partial \mathcal{L}}{\partial z_j} = q_j - p_j .
$$

Then state what the expression gives for a confidently wrong one-hot
prediction, and what it gives once the model is correct and certain.

<Solution>
Write $Z = \sum_i e^{z_i}$, so $\ln q_i = z_i - \ln Z$ and

$$
\mathcal{L} = -\sum_i p_i (z_i - \ln Z) = -\sum_i p_i z_i + \ln Z ,
$$

using $\sum_i p_i = 1$. Differentiate the two pieces with respect to $z_j$.
The first gives $-p_j$. For the second,

$$
\frac{\partial}{\partial z_j} \ln Z = \frac{1}{Z} \frac{\partial Z}{\partial
z_j} = \frac{e^{z_j}}{Z} = q_j .
$$

Hence $\partial \mathcal{L}/\partial z_j = q_j - p_j$, and in vector form the
gradient is $q - p$: the prediction minus the target.

**Confidently wrong, one-hot.** Say the truth is class $c$ and $q_c = 10^{-6}$
with the mass sitting on some class $m$. Then
$\partial \mathcal{L}/\partial z_c \approx -1$ and
$\partial \mathcal{L}/\partial z_m \approx +1$: the update pushes the true
logit up and the wrongly favoured one down, both at essentially the maximum
rate the loss can ask for. The loss itself is $19.93$ bits, but the gradient
is bounded by $1$ per coordinate.

**Correct and certain.** $q \to p$ makes the gradient vanish componentwise, so
a converged model receives no update, which is $q = p$ being the unique
minimizer, read one logit at a time. Note also that the components of
$q - p$ sum to zero: the update never changes the total logit mass, which is
the gradient-level counterpart of the fact that adding a constant to all
logits leaves $q$ unchanged.
</Solution>
</Exercise>

<Exercise>
A dataset $x_1, \ldots, x_N$ is
drawn and a model $q$ scores it. Show that minimizing the average log-loss
$\tfrac{1}{N}\sum_i (-\log_2 q(x_i))$ over $q$ is exactly maximizing the
likelihood $\prod_i q(x_i)$, and identify the assumption that licenses writing
the dataset's probability as that product. State one modelling situation in
which the assumption fails and what replaces the product there.

<Solution>
Group the sum by distinct values: each value $x$ occurs $N\hat{p}(x)$ times,
so

$$
\frac{1}{N}\sum_{i=1}^{N}\bigl(-\log_2 q(x_i)\bigr)
= \sum_x \hat{p}(x)\bigl(-\log_2 q(x)\bigr) = H(\hat{p}, q).
$$

For the likelihood, $-\log_2 \prod_i q(x_i) = \sum_i (-\log_2 q(x_i)) = N
\cdot H(\hat{p}, q)$. Since $-\log_2$ is strictly decreasing and $N > 0$ is
constant, the $q$ minimizing $H(\hat{p}, q)$ is the $q$ maximizing
$\prod_i q(x_i)$.

**The assumption.** Writing the dataset's probability as $\prod_i q(x_i)$
requires the examples to be independent under the model. Only then does the
joint probability factor into per-example terms, and only then is the total
loss a sum.

**Where it fails.** In sequence modelling the examples are the successive
tokens of one text and are emphatically not independent. What replaces the
product is the chain rule of probability,

$$
q(x_{1:n}) = \prod_{t=1}^{n} q(x_t \mid x_{<t}) ,
$$

a product of conditional probabilities. The total loss is again a
sum of per-token surprisals, which is why the accounting survives, and the
conditioning is what <Ref lesson="joint-and-conditional-entropy"/> priced when
it replaced $H(X)$ with $H(X \mid Y)$.
</Solution>
</Exercise>

<Exercise>
A source emits $p = (0.4,\ 0.3,\ 0.2,\ 0.1)$ over
$\{A, B, C, D\}$ and a model claims $q = (0.5,\ 0.25,\ 0.125,\ 0.125)$.
Compute $H(p)$, $H(p, q)$ and $D(p\,\|\,q)$, then build the Huffman code for
$q$ (<Ref lesson="huffman-by-hand"/>) and compute its expected length on
$p$-data. Report all four numbers, say which two coincide, and say why the
coincidence would fail for a non-dyadic $q$. Use $H(p) = 1.846$ bits.

<Solution>
**Cross-entropy.** The surprisals under $q$ are $1, 2, 3, 3$ bits, so

$$
H(p,q) = 0.4(1) + 0.3(2) + 0.2(3) + 0.1(3) = 1.900 \text{ bits.}
$$

**Divergence.** $D(p\,\|\,q) = H(p,q) - H(p) = 1.900 - 1.846 = 0.054$ bits.
Direct check:

$$
0.4\log_2 0.8 + 0.3\log_2 1.2 + 0.2\log_2 1.6 + 0.1\log_2 0.8
= -0.129 + 0.079 + 0.136 - 0.032 = 0.054 .
$$

**The Huffman code for $q$.** Merge the two smallest, $0.125 + 0.125 = 0.25$;
merge that with $0.25$ to get $0.5$; merge with $0.5$. Codeword lengths
$(1, 2, 3, 3)$ for $(A, B, C, D)$. Expected length on $p$-data:
$0.4(1) + 0.3(2) + 0.2(3) + 0.1(3) = 1.900$ bits.

**Which coincide.** $H(p,q)$ and the Huffman code's expected length, both
$1.900$ bits. $H(p) = 1.846$ is lower, since no code for the wrong
distribution reaches it, and $D = 0.054$ is the difference.

**Why the coincidence is special.** Every probability in $q$ is a power of
$\tfrac12$, so each ideal length $-\log_2 q(x)$ is already a whole number and
Huffman assigns exactly that. For a non-dyadic $q$ the code must round, its
lengths differ from the surprisals, and its expected length on $p$-data
differs from $H(p,q)$ by up to one bit per symbol
(<Ref lesson="source-coding-theorem-lite"/>). The cross-entropy is the
fractional-length idealization; the Huffman code is what integers permit.
</Solution>
</Exercise>

<Exercise>
A language model reports an average loss of $2.1$ nats per token on a test set
of $10{,}000$ tokens covering $46{,}000$ bytes of text. Convert to bits per
token and bits per byte, compute the size in bytes of the file an ideal coder
driven by this model would produce, and compare it with gzip, which reaches
roughly $2.6$–$3.0$ bits per byte on English prose. State what the comparison
does not charge for.

<Solution>
**Units.** $2.1 \times 1.443 = 3.03$ bits per token. Total:
$10{,}000 \times 3.03 = 30{,}300$ bits. Per byte:
$30{,}300 / 46{,}000 = 0.659$ bits per byte.

**File size.** $30{,}300$ bits $= 3{,}788$ bytes, against $46{,}000$ bytes of
raw text: a ratio of about $12{:}1$.

**Against gzip.** At $2.8$ bits per byte gzip produces about
$46{,}000 \times 2.8 / 8 \approx 16{,}100$ bytes, a ratio near $2.9{:}1$. The
model's file is roughly four times smaller.

**What is not charged.** The decoder needs the identical model to reproduce
the probabilities, and none of the above counts the model's own description
length. Under an accounting that does count it, a large model stops winning on
a test set this small.

This exercise computed a compressed file size from a training loss and nothing
else, which is the whole content of
<Ref lesson="compression-is-prediction"/>: an arithmetic coder driven by the
model realizes $-\log_2 q$ bits, within two bits for the entire stream, and
<Ref lesson="language-models-as-compressors"/> measures the result on real
corpora, including the two-part accounting that charges for the model.
</Solution>
</Exercise>

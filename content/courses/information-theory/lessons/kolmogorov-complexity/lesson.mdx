The Kolmogorov complexity of a string is the length of the shortest program
that prints it: the single number under which no compressor, however clever,
can push the string.

Every floor this course has derived was quoted against a distribution. The
source coding theorem fixed the fewest bits per symbol *for a known source*
(<Ref lesson="source-coding-theorem-lite"/>), and the previous lesson turned
any predictive model into a compressor whose output size is that model's own
log-loss on the stream (<Ref lesson="compression-is-prediction"/>). What
stands open is the case with no distribution in it: one fixed file, one
genome, one photograph, where there is no source to average over and no
ensemble the file was drawn from. This lesson removes the last assumption.
The shortest-program length is defined for an individual string, sits below
the output length of every computable compressor, cannot be computed, and
still averages to the entropy.

The route: three strings and their programs, the definition and the constant
that comes with it, the counting argument that makes incompressibility the
rule, Berry's paradox and uncomputability, a sequence that is trivial to
describe and impossible for a real machine to compress, and the theorem that
returns the whole construction to entropy.

## Three strings: regularity is a short program

The quantity is easier to see computed than defined. Take three strings of
$n = 10^6$ bits each:

- $x_1 = $ `000000…0`: one million zeros.
- $x_2 = $ `010101…01`: the pair `01` repeated $500{,}000$ times.
- $x_3 = $ `110100…1`: one million flips of a fair coin, recorded faithfully.

All three occupy the same megabit of storage. They differ in how short a
**description** suffices to regenerate them.

### The programs

<Example title="three program lengths">
A program printing $x_1$ is a loop: emit `0`, $10^6$ times. Its text is a
fixed few dozen bytes of loop code, a constant independent of the count, plus
the number $10^6$ itself, which takes
$\lceil \log_2 (10^6 + 1) \rceil = 20$ bits to state. Description length:
$20 + c$ bits.

A program for $x_2$ is the same loop with the two-character body `01` and
the count $500{,}000$, a $\lceil \log_2 (5 \times 10^5 + 1) \rceil = 19$-bit
numeral: $19 + c'$ bits, with $c'$ exceeding $c$ only by the cost of the
one extra body character.

For $x_3$ no pattern is available to exploit; the only general recipe is
`print "1101000110…"` with the million bits included verbatim, a program of
$10^6 + c''$ bits.

Per output bit: $x_1$ and $x_2$ cost on the order of $10^{-5}$ bits of
program per bit of output; $x_3$ costs $1$. Three strings of identical
length, and the shortest known descriptions differ by five orders of
magnitude.
</Example>

The gap is not about loops specifically. Any regularity, whether repetition,
symmetry, a formula or a grammar, is a handle some program can grip, and a
string with no computable regularity leaves nothing to grip. Shortest-program
length is therefore a measure of total structure, and the three questions the
rest of the lesson answers are the ones any such measure has to survive: is
it a property of the string or of the language, how many strings have any
structure at all, and can the number be computed.

## The definition: the shortest program that prints x

The three programs above were written in no particular language, and the
lengths quoted were whatever that language happened to charge. The definition
fixes the language first and then pays for the choice.

Fix a programming language $U$ that is *universal*: it can express an
interpreter for any other language. Python, C, and the universal Turing
machine all qualify. Programs are finite binary strings (source text at 8
bits per character); $\ell(p)$ denotes the length of program $p$ in bits.

<Definition title="Kolmogorov complexity">
The **Kolmogorov complexity** of a binary string $x$ with respect to a
universal language $U$ is
$$
K_U(x) = \min \{\, \ell(p) : U(p) = x \,\},
$$
the length in bits of the shortest program that outputs $x$ and halts,
run on empty input.
</Definition>

The minimum is over a non-empty set: the literal program `print "x"` always
qualifies, so $K_U(x) \le n + c$ for every $n$-bit string, where $c$ is the
fixed cost of the quoting code. Four cases fix what the definition covers.

- **The canonical case.** $K_U(0^n) \le \log_2 n + c$: the program carries the
  count and a constant amount of loop code, as computed above.
- **A case with a different surface.** The first $10^6$ bits of the binary
  expansion of $\pi$ pass every standard statistical test for randomness, and
  a fixed spigot program plus the count $n$ prints them, so
  $K_U \le \log_2 n + c$ again. Apparent disorder does not certify high
  complexity; only the absence of **any** computable regularity does.
- **The degenerate case.** For the empty string, the program that prints
  nothing gives $K_U(\lambda) = O(1)$. At this end of the range the constant
  is the entire value, which is the first sign that single-string statements
  will need care.
- **The near miss.** A program that emits the bits of $x$ and then runs
  forever can be shorter than any halting program for $x$, and it does not
  count: the clause it violates is $U(p) = x$, which demands halting with
  exactly $x$ on the output. That one clause is what makes the shortest
  program impossible to identify by running candidates, and the
  uncomputability proof below is built on it.

<Task>
Take a file from your own disk and write down two descriptions of it: the
file itself, and any rule that regenerates it. State which clause of the
definition decides whether your rule counts as a program for the file, and
what the rule would have to output for the file's *last* byte to be covered.
</Task>

<Remark title="a property of one string">
$K_U(x)$ is defined for an **individual string**. Every measure so far in
this course, entropy and mutual information and cross-entropy alike, required
a probability distribution before it could assign a number. $K_U$ assigns a
number to `0101…01` itself, with no source, no ensemble, and no probabilities
in sight. This is the point of the algorithmic definition, and the reason it
can serve as the limit concept under all compression.
</Remark>

### Every compressed file is a program

<Ref lesson="compression-is-prediction"/> treated a compressed file $z$ and
its decoder as a pair. Bundle them: the program "run the following decoder
on the following bits", with the decoder's code and $z$ inlined, prints $x$.
Its length is $\ell_C(x)$ plus the fixed size of the decoder: a
self-extracting archive, and by construction an upper bound on $K_U(x)$.

<Theorem title="K undercuts every compressor">
For every computable lossless compressor $C$ there is a constant $c_C$,
independent of $x$, such that
$$
K_U(x) \;\le\; \ell_C(x) + c_C \quad \text{for all strings } x,
$$
where $\ell_C(x)$ is the length of $C$'s output on $x$.

<Proof>
Let $D$ be $C$'s decoder, a fixed program. For any $x$, the program
$p_x$ = "run $D$ on $z$", with $z = C(x)$ included literally, outputs $x$
and halts. Its length is $\ell_C(x) + c_C$, where $c_C$ covers $D$'s code
and the glue that delimits $z$. The shortest program for $x$ is no longer
than this particular one.
</Proof>
</Theorem>

gzip, a block Huffman code, and a language model driving an arithmetic coder
are each one program family, and $K_U(x)$ sits at or below the output length
of every one of them, up to that family's fixed constant. The floor is
therefore not a competitor to those systems but a statement about all of them
at once, which is exactly why the constant in the theorem, and the language
hiding in the subscript $U$, have to be pinned down before the quantity means
anything.

## Invariance: switching languages costs one interpreter

The subscript $U$ looks like a defect. A "Python complexity" and a "C
complexity" could disagree, and a quantity that depends on a taste in
languages would not be a property of the string. The rescue is concrete: a
Python interpreter can be written in C, once, as a fixed file of $c$ bits.
Prepending that interpreter to any Python program $p$ yields a C program of
length $\ell(p) + c$ with identical output. Whatever Python saves, C recovers
at a one-time cost of $c$.

<Theorem title="invariance (Solomonoff–Kolmogorov)">
Let $A$ and $B$ be universal languages. There is a constant $c_{AB}$,
depending on the pair of languages but not on $x$, with
$$
K_A(x) \;\le\; K_B(x) + c_{AB} \quad \text{for all } x .
$$
Applying the statement in both directions,
$\lvert K_A(x) - K_B(x) \rvert \le \max(c_{AB}, c_{BA})$ for all $x$.

<Proof>
$A$ is universal, so some $A$-program $I_B$ of fixed length $c_{AB}$
interprets $B$: given a $B$-program $p$ appended to its own code (with a
fixed self-delimiting framing, absorbed into $c_{AB}$), it simulates $B$
running $p$. For the shortest $B$-program $p^*$ printing $x$, the
$A$-program $I_B\,p^*$ prints $x$ and has length $K_B(x) + c_{AB}$; the
$A$-minimum is at most that.
</Proof>
</Theorem>

<Figure

  caption="Invariance: language A runs B's shortest program behind one fixed interpreter, so the two complexities differ by at most a constant that does not depend on x."

The constant is real and can be large. An interpreter for a rich language is
megabytes of code, so for one specific short string the choice of language
can dominate the value completely: a 500-bit string can be assigned almost
any complexity between $O(1)$ and $500 + c$ by a language built to favour it.
Invariance is an **asymptotic** guarantee. As strings grow, a fixed $\pm c$
becomes negligible against $K(x)$, and every statement in this lesson holds
up to such a constant. For the rest of the lesson the subscript is dropped,
a universal $U$ is fixed and understood, and claims carry $+O(1)$.

<KeyFact>
What survives the constant is the only form worth quoting: per-symbol rates,
ratios on long strings, and comparisons whose gap exceeds the interpreter
constants. This is why every compression figure later in the course is a
rate — bits per byte in <Ref lesson="language-models-as-compressors"/>,
compressed size over raw size in the exercises below — and never a complexity
value attached to one named file.
</KeyFact>

## Counting: almost every string is incompressible

The three-strings opener suggests that compressibility is common, since two
of the three strings had it. Arithmetic says the opposite, and the argument
is a pigeonhole count on a scale worth stating in bytes rather than in
symbols.

<Example title="how many 1 KB files compress by 10 bits?">
A 1 KB file is a binary string of $n = 8 \times 1024 = 8192$ bits, and there
are $2^{8192}$ of them. Ask how many can be regenerated by a program of
fewer than $8182$ bits, which is a saving of 10 bits.

Programs are binary strings, so the ones shorter than $8182$ bits number
$$
1 + 2 + 4 + \cdots + 2^{8181} = 2^{8182} - 1 < 2^{8182},
$$
and each program prints at most one file. So fewer than $2^{8182}$ files have
one, a fraction below
$$
\frac{2^{8182}}{2^{8192}} = 2^{-10} = \frac{1}{1024}.
$$

Fewer than one 1 KB file in a thousand can be shortened by even 10 bits, and
the same count at 20 bits gives fewer than one in a million. Halving the file
is worse by an amount with no physical comparison: the fraction is
$2^{-4096}$, or about $10^{-1233}$, against roughly $10^{80}$ atoms in the
observable universe.
</Example>

<FigureSequence
  name="counting"

  caption="The census for a 1 KB file: short programs are outnumbered 1,024 to 1, so fewer than one file in a thousand compresses by 10 bits. Watch the amber square, which is drawn to scale."

<Theorem title="incompressibility is the rule">
For every $n$ and every $c \ge 1$, the fraction of $n$-bit strings with
$K(x) < n - c$ is less than $2^{-c}$. In particular, at least one $n$-bit
string satisfies $K(x) \ge n$ for every $n$.

<Proof>
There are fewer than $2^{n-c}$ binary programs of length below $n - c$,
and each outputs at most one string, so fewer than $2^{n-c}$ of the $2^n$
strings have such a program: a fraction below $2^{-c}$. For the second
claim take $c = 0$: programs of length below $n$ number $2^n - 1$, one
short of the $2^n$ strings, so some string has no program shorter than
itself.
</Proof>
</Theorem>

Nothing in the proof mentions a probability distribution, but the fraction
converts into one the moment the string is drawn at random. For $X^n$ a
sequence of fair coin flips, every $n$-bit string has probability $2^{-n}$,
so the theorem reads $\Pr[K(X^n \mid n) < n - c] < 2^{-c}$: the chance that a
recorded coin sequence compresses by 10 bits is under one in a thousand, and
it is under one in a million at 20. This is the precise sense in which the
word *random* means two things in this lesson. A coin flip sequence is
random in the process sense and, with overwhelming probability, also
incompressible; but a specific string on a disk either has a short program or
does not, and no experiment on the string reveals which.

<Definition title="incompressible string">
An $n$-bit string $x$ is **$c$-incompressible** if $K(x) \ge n - c$, and
**incompressible** (algorithmically random) if $K(x) \ge n$.
</Definition>

<Exercise>
Run the same census one step further. For $n$-bit strings, bound the number
with $K(x) < n - c$ for $c = 1$ and for $c = n/2$, and then answer the
question the compressor version raises: a lossless compressor may emit
outputs of *any* length up to $n - c$, not just length $n - c - 1$ exactly,
so how many inputs can it shorten by at least $c$ bits, and by what factor
does that differ from the bound above? Write the count of strings of length
at most $m$ before opening the solution.

<Solution>
**The two bounds.** At $c = 1$, fewer than $2^{n-1}$ strings have
$K(x) < n-1$: at most half. At $c = n/2$, fewer than $2^{n/2}$ of the $2^n$
strings have $K(x) < n/2$, a fraction $2^{-n/2}$, which for $n = 8192$ is
$2^{-4096}$.

**The compressor version.** The number of binary strings of length at most
$m$ is $1 + 2 + \cdots + 2^m = 2^{m+1} - 1$. A lossless compressor is
injective, since two inputs with the same output could not both be recovered,
so the inputs it maps to length $\le n - c$ number fewer than $2^{n-c+1}$: a
fraction below $2^{-c+1}$, exactly twice the bound on $K$. The factor of 2 is
the sum of the geometric series, and it never grows: whichever version is
quoted, the fraction still halves with every extra bit of saving.

The transferable move is that both bounds come from counting *descriptions*,
never from any property of the data. Nothing about the inputs was assumed.
</Solution>
</Exercise>

<KeyFact>
Because compression is injective, a compressor that shortens some inputs must
lengthen others by at least as much: the counting bound applies to the
compressor's own outputs. A product advertised as shrinking any data is not
merely unproven, it is arithmetically excluded, and the honest version of the
claim names the family of inputs the model was built for.
</KeyFact>

## Uncomputability: the ideal compressor cannot be run

The counting theorem says most strings are incompressible without exhibiting
one, and the natural next step is a program that computes $K(x)$ and settles
the matter for any given string. No such program exists, and the obstruction
is a sentence.
[Berry's paradox](https://en.wikipedia.org/wiki/Berry_paradox), published by
Russell in 1908 as a puzzle about naming, asks for "the least integer not
nameable in fewer than nineteen syllables", which is a phrase of eighteen
syllables that names it. Kolmogorov complexity makes "nameable in $k$
syllables" precise as "printed by a $k$-bit program", and the puzzle becomes
an impossibility proof.

Suppose a program $Q$, say $10^6$ bits long, computed $K(x)$ for every
$x$. Build the searcher $R$: "for each string $x$ in order of length,
compute $K(x)$ using $Q$; print the first $x$ with $K(x) > 10^9$ and
halt." $R$ contains $Q$, the threshold $10^9$ (30 bits), and fixed loop
code: about $10^6$ bits in total. The search terminates, because strings
with $K(x) > 10^9$ exist by the counting theorem. But then $R$ is a
$10^6$-bit program printing a string whose complexity exceeds $10^9$:
a contradiction three orders of magnitude wide.

<Theorem title="K is not computable">
No algorithm outputs $K(x)$ on input $x$ for all strings $x$.

<Proof>
Suppose $Q$ computes $K$, with $\ell(Q) = q$. For a threshold $L$, let
$R_L$ enumerate strings in length-lexicographic order, compute each
$K(x)$ by running $Q$, and print the first $x^*$ with $K(x^*) > L$. Such
a string exists (counting theorem), so $R_L$ halts and prints $x^*$;
hence $K(x^*) \le \ell(R_L) \le q + \log_2 L + c$, the length of $Q$
plus the binary threshold plus fixed glue. But $K(x^*) > L$ by the test
$R_L$ applied. For $L$ large enough that $L > q + \log_2 L + c$ (true
for all sufficiently large $L$), the two conclusions contradict.
No $Q$ exists.
</Proof>
</Theorem>

### What survives: bounds from one side only

<Remark title="uncomputable is not undefined">
$K(x)$ is a perfectly definite integer for every $x$: the minimum of a
non-empty set of program lengths, bounded above by $n + c$. What fails is
the existence of an algorithm that returns it. $K$ can even be approached
from above: run all programs up to the literal bound in parallel
(dovetailed), and record the shortest that has halted with output $x$ so
far. The record converges to $K(x)$, but certifying convergence would
mean certifying that no shorter program ever halts, which is the
[halting problem](https://en.wikipedia.org/wiki/Halting_problem). $K$ is
upper-semicomputable, never computable.
</Remark>

The one-sidedness organizes the whole compression stack. Running any
compressor on a file produces a program that prints it, hence a certificate
that $K$ is at most that size. Running every compressor ever written produces
no certificate at all in the other direction, because the next program might
be shorter. gzip's output is one upper bound, a language model driving an
arithmetic coder is a tighter one, and nothing runnable is the floor itself.

<KeyFact>
The asymmetry decides how $K$ is used in proofs. Since no computation ever
certifies a named file as incompressible, theorems about incompressible
strings are proved about a string nobody can exhibit: the counting argument
supplies one, and any regularity it had would contradict its own complexity.
The law of large numbers for incompressible sequences (Cover & Thomas 14.5.2)
runs exactly that way — the 0s and 1s of an incompressible string must
approach equal proportions, because an imbalance would admit a shorter
two-part description.
</KeyFact>

## Describable but incompressible: the sequence u

A small $K$ certifies that a short description exists, and it is natural to
read that as a promise to a compressor: a string with a two-line description
should be the easiest input any real program ever sees. One published
sequence breaks the implication completely, and it is not a contrived one.

Let $u(k)$ be the concatenation, in lexicographic order, of all $2^k$ binary
words of length $k$, and let $u = u(1)\,u(2)\,u(3)\cdots$ be the enumeration
of every binary word by increasing length:

$$
\underbrace{0\;1}_{u(1)}\;\;
\underbrace{00\;01\;10\;11}_{u(2)}\;\;
\underbrace{000\;001\;010\;011\;100\;101\;110\;111}_{u(3)}\;\cdots
$$

The prefix through $u(k)$ has
$n(k) = \sum_{i=1}^{k} i\,2^{i} = (k-1)2^{k+1} + 2$ bits, which is $34$ bits
at $k = 3$ and about $39.8$ million bits at $k = 20$. Its complexity is
minute: the program is two nested loops whose only data is the number $k$, so
$K(u_1^{n(k)}) \le \log_2 k + c$. At $k = 20$ that is a program carrying five
bits of data, up to the additive constant, for a $39.8$-megabit output.

### Every phrase is new, which is the worst case

Now run a real compressor on it. LZ78 (<Ref lesson="dictionary-coding"/>)
parses its input into phrases, each the shortest string not yet seen, and
codes each phrase as an index into the phrases before it plus one new symbol.
On $u$ the parse is forced, and it is exactly the block structure:

```
0 | 1 | 00 | 01 | 10 | 11 | 000 | 001 | 010 | 011 | 100 | 101 | 110 | 111
```

Those $14$ phrases consume the $34$ bits of $u_1^{n(3)}$, and $14 = 2^{4}-2$.
In general the prefix through $u(k)$ parses into $c = 2^{k+1} - 2$ distinct
phrases, which is the largest number of distinct phrases any string of that
length admits. The sequence is built out of the dictionary the parser is
trying to build.

Phrase number $j$ costs about $\log_2 j$ bits of index plus one bit of
symbol, so the output is about $c \log_2 c$ bits. At $k = 20$ the parse has
$c \approx 2.10$ million phrases at roughly $21$ bits each, for an output near
$43$ megabits against an input of $39.8$ megabits. The compressor expands the
file, and as $k$ grows the ratio falls to $1$ from above rather than dropping
below it:
$$
\frac{c \log_2 c}{n(k)} \;\longrightarrow\;
\frac{(k+1)\,2^{k+1}}{(k-1)\,2^{k+1}} \;=\; \frac{k+1}{k-1} \;\to\; 1 .
$$

This is not a defect of LZ78. The same phrase count lower-bounds every
encoder with a fixed finite memory.

<Theorem title="describable and incompressible (Ziv–Lempel 1978, Corollary 1)">
Let $\rho(x)$ be the best compression ratio attainable on the infinite
sequence $x$ by finite-state information-lossless encoders, in the limit of
unboundedly many states. Then
$$
\rho(x) \;\ge\; \limsup_{n \to \infty}
\frac{c(x_1^n)\,\log_2 c(x_1^n)}{n},
$$
where $c(x_1^n)$ is the largest number of distinct phrases whose
concatenation is $x_1^n$. For the sequence $u$ the right-hand side equals
$1$, so $\rho(u) = 1$: no finite-state encoder compresses $u$ at all.
</Theorem>

The property responsible belongs to the compressor, not to the string. A
machine with $s$ states can distinguish only $s$ histories, so it cannot
carry the counter that $u$'s rule needs; the shortest-program description
carries that counter in $\log_2 k$ bits because a Turing machine's tape is
unbounded. The gap between $K(x)$ and what an implementable compressor
achieves is not a rounding error to be absorbed into an additive constant.
It is unbounded on specific sequences, and it is the entire subject matter of
practical compression.

<KeyFact>
Every real compressor is defined by which regularities its bounded state can
represent, which is why enlarging that state is itself a compression result:
<Ref lesson="language-models-as-compressors"/> measures what a model with
$10^{11}$ parameters of state achieves on data no finite-state parser can
touch.
</KeyFact>

## Complexity meets entropy: E[K]/n is the entropy after all

Dropping the distribution is what let the last three sections speak about
individual files. Putting one back reconnects the algorithmic theory to
everything before it, and the connection is an equality in the limit rather
than an analogy.

<Example title="a two-part description at the entropy">
Let the source be the course's 90/10 coin ($H \approx 0.469$ bits per
flip) and draw $n = 10^4$ flips. A typical draw $x$ has about $k = 1000$
tails, and admits a **two-part description**:

1. State $k$: at most $\lceil \log_2 (n+1) \rceil = 14$ bits.
2. State which arrangement: an index into the
   $\binom{10^4}{1000}$ strings with exactly that many tails,
   $\log_2 \binom{10^4}{1000} \approx 4680$ bits.

A fixed decoder turns the pair into the string, so
$K(x) \le 14 + 4680 + c \approx 4700$ bits: about $0.47$ per flip, at the
entropy, for **every** string of typical composition, not on average but
individually. The general inequality behind step 2 is
$\log_2 \binom{n}{k} \le n\,H(k/n)$; here
$n\,H(1000/10^4) = 10^4 \times H(0.1) \approx 4690$ bits, so the index
term sits within 10 bits of that ceiling.
</Example>

<Exercise>
A run of $n = 10^4$ flips of the same 90/10 coin comes back with $k = 500$
tails, half the expected count. (a) Compute its two-part description length,
using $\log_2 \binom{10^4}{500} \approx 2860$. (b) Compute the length of its
codeword under a code matched to the true 90/10 model, which is its
surprisal (use $-\log_2 0.9 \approx 0.152$ and $-\log_2 0.1 \approx 3.322$).
(c) The two numbers differ by more than 200 bits. State which is larger,
and explain the direction using
<Ref lesson="entropy-as-average-surprise">entropy</Ref> and
<Ref lesson="source-coding-theorem-lite">the source coding theorem</Ref>.

<Solution>
(a) Count: $\lceil \log_2 (10^4 + 1) \rceil = 14$ bits. Index: about $2860$
bits, consistent with the ceiling $\log_2 \binom{n}{k} \le n H(0.05) = 2864$.
Two-part total: $14 + 2860 + c \approx 2874 + c$ bits, so
$K(x) \lesssim 2900$ bits, about $0.29$ per flip.

(b) Surprisal under the true model:
$9500 \times 0.152 + 500 \times 3.322 = 1444 + 1661 = 3105$ bits.

(c) The distribution-matched code is the longer of the two, by about 230
bits. The string is atypical for its source: its empirical tail rate is
$0.05$ against the source's $0.1$, and a fixed code pays the per-symbol
mismatch for every one of the $10^4$ flips. The two-part description instead
adapts to the individual string, paying $n H(\hat p) + O(\log n)$ at the
string's own empirical entropy, and $H(0.05) \approx 0.286$ is well below
$H(0.1) \approx 0.469$.

The transferable move: $K$ tracks the structure the string actually has,
distribution-based coding tracks the structure the source was expected to
have, and the theorem below shows the two agree once the average over draws
is taken.
</Solution>
</Exercise>

<Theorem title="complexity meets entropy (Cover & Thomas 14.3.1)">
Let $X_1, X_2, \ldots$ be i.i.d. draws from a computable distribution $f$
on a finite alphabet $\mathcal{X}$. Then there is a constant $c$ with
$$
H(X) \;\le\; \frac{1}{n}\, \mathbb{E}\left[ K(X^n \mid n) \right]
\;\le\; H(X) + \frac{(|\mathcal{X}|-1)\log_2 n}{n} + \frac{c}{n},
$$
so $\tfrac{1}{n}\mathbb{E}[K(X^n \mid n)] \to H(X)$. The conditioning on $n$
hands the machine the length for free, which removes the cost of framing it
and changes nothing in the limit.

<Proof>
*Upper bound.* Generalize the two-part description. First state the type of
$x^n$, the empirical frequency of each symbol, in $(|\mathcal{X}|-1)\log_2 n$
bits, the last frequency being determined by the others. Then state the index
of $x^n$ within its type class, which holds at most $2^{n H(\hat p)}$
sequences for empirical distribution $\hat p$. Hence
$K(x^n \mid n) \le n H(\hat p) + (|\mathcal{X}|-1)\log_2 n + c$. Take
expectations: $\mathbb{E}[H(\hat p)] \le H(\mathbb{E}[\hat p]) = H(f)$,
because entropy is concave and $\hat p$ is unbiased.

*Lower bound.* A halting program is never a prefix of another halting
program, since the machine stops reading once it halts, so program lengths
satisfy the Kraft budget of <Ref lesson="kraft-inequality"/>. The map from
$x^n$ to its shortest program is therefore a lossless code with codeword
lengths $K(x^n \mid n)$, and <Ref lesson="source-coding-theorem-lite">the
source coding theorem</Ref> floors any such code's expected length at
$H(X_1 \ldots X_n) = nH(X)$.
</Proof>
</Theorem>

<Remark title="which K the Kraft step needs">
Two versions of the definition circulate. The **plain** version admits any
binary string as a program. The **prefix-free** version, due to Chaitin,
requires that no valid program is a prefix of another, so the machine can
tell where the code ends without being told its length. Only the prefix-free
version satisfies $\sum_x 2^{-K(x)} \le 1$, and it is the one the lower bound
above and every universal-probability statement below assume. The two differ
by $O(\log n)$ on $n$-bit strings, which the division by $n$ erases, so no
asymptotic claim in this lesson depends on the choice.
</Remark>

Both hypotheses in the theorem earn their keep. *Computable source:* the
decoder in the upper bound has to work with $f$'s structure, and for sources
with no computable description the route fails. *Expectation:* the agreement
is an average over draws, and an individual string can sit far below it, as
the all-zeros draw does, or slightly above it. Where no distribution exists
at all, entropy is silent and $K$ is the measure that remains.

<KeyFact>
The first half of this course computed floors from distributions the reader
had to be handed, which left open whether the floors were artefacts of the
assumption. This theorem closes it: the assumption-free quantity lands on the
same number, within $O(\log n / n)$ bits per symbol, so entropy was the right
average and not merely a convenient one.
</KeyFact>

## ★ The prediction side: Solomonoff's mixture

<Ref lesson="compression-is-prediction"/> established that predictors and
compressors are one object in two interfaces, and the floor just derived is
the compression side. The prediction-side mirror is a fixed distribution over
strings, which is worth stating because it is the origin of the "universal
predictor" language used around large models, and worth bounding because that
language is routinely overstated.

Work on a universal machine whose valid programs are self-delimiting. Program
lengths then obey the Kraft budget, $\sum_p 2^{-\ell(p)} \le 1$, so the
weights $2^{-\ell(p)}$ are a prior over programs.

<Definition title="universal (Solomonoff) mixture">
For a binary string $x$, the **universal mixture** assigns
$$
M(x) \;=\; \sum_{p\,:\; U(p) \text{ outputs a string starting with } x} 2^{-\ell(p)},
$$
the total prior weight of all programs whose output begins with $x$.
Prediction is by conditioning:
$M(\text{next bit} = 1 \mid x) = M(x1)/M(x)$.
</Definition>

Every program is a hypothesis about the data's law, weighted by $2^{-\ell}$,
so short programs carry exponentially more prior weight than long ones. The
consequence is a domination argument in one line.

<Theorem title="the mixture's total regret is a constant">
Let $\mu$ be any computable distribution over binary streams, computed by
a program of length $K(\mu)$. For every string $x$,
$$
-\log_2 M(x) \;\le\; -\log_2 \mu(x) + K(\mu) + O(1) .
$$
Read through <Ref lesson="compression-is-prediction"/>: coding with the
mixture costs at most $K(\mu)$ more bits **in total**, not per symbol,
over coding with the true model, whatever the stream length.

<Proof>
The sum defining $M(x)$ includes the programs that compute $\mu$ and then
arithmetic-decode $x$'s $\mu$-code; through that family
$M(x) \ge 2^{-K(\mu) - O(1)}\, \mu(x)$, the true model's weight times its
probability. Taking $-\log_2$ of the domination gives the claim.
</Proof>
</Theorem>

Three limits keep the result from being a recipe. $M$ sums over all programs,
including the ones that never halt, so it is uncomputable for the same reason
$K$ is, and unlike $K$ it is not even approachable from above. The constant
$K(\mu)$ is a program length for the true law of the data, which for anything
resembling natural data is astronomically large, so the bound is compatible
with arbitrarily bad behaviour on any finite stream a reader will ever see.
And the bound is about total excess bits, not about accuracy at step $t$;
it says nothing about how the loss is distributed over the stream. The
mixture is a normative reference point, and treating it as an achievable
target is a category error, not an engineering roadmap. What is measurable
is the ladder: [Delétang et al. (2023)](https://arxiv.org/abs/2309.10668)
report bits per byte for trained models against gzip on data the models never
saw, and those are upper bounds on $K$ per byte, nothing more.

## What K prices, and the computable stand-in

The two-part description used twice above is the general shape of every
bound in this lesson, and writing it in full states both the ideal and the
reason nobody runs it.

For any computable model $\mu$, the program "decode the following arithmetic
code under model $\mu$", with $\mu$'s own code inlined, prints $x$ and halts,
so
$$
K(x) \;\le\; K(\mu) \;+\; \lceil -\log_2 \mu(x) \rceil \;+\; O(1) :
$$
bits to state the model, plus bits to state the data given the model. Both
terms are uncomputable, the first because $K$ is and the second because
finding the best $\mu$ means searching all programs. Replacing "all programs"
with a model class that can be enumerated, and $K(\mu)$ with a code length
for a parameter vector, turns the inequality into a selection rule that runs.

### The boundary: exact regeneration only

The entire construction
is lossless: $K$ prices exact regeneration of $x$ and says nothing about
reconstruction within a distortion tolerance, which is the separate trade-off
of <Ref lesson="rate-distortion"/>.

What is established: $K(x)$ is the shortest-program length of an individual
string, well defined up to an interpreter constant, below every computable
compressor's output, achieved by almost no string, uncomputable by Berry's
argument, unreachable in practice even where it is small, and equal to the
entropy in expectation. What is not established is any way to use it.
<Ref lesson="minimum-description-length"/> replaces the two uncomputable
terms of the ideal two-part code with a model class you can enumerate and a
parameter cost you can compute, and
<Ref lesson="language-models-as-compressors"/> reports what the best
computable stand-in achieves, in bits per byte, on data it was never trained
on.

<Exercise>
Order these five $10^6$-bit strings by Kolmogorov complexity, and justify
each comparison in one sentence: (a) one million copies of the bit `1`; (b)
the first $10^6$ bits of the binary expansion of $\sqrt{2}$; (c) $10^6$ bits
produced by a fair coin; (d) the first $10^6$ bits of the sequence $u$ that
enumerates all binary words by increasing length; (e) a $500{,}000$-bit
fair-coin string written down twice in a row.

<Solution>
Order: (a) $\approx$ (b) $\approx$ (d) $\;\ll\;$ (e) $\;\ll\;$ (c).

(a) A loop plus the count: $K \le \log_2 10^6 + c \approx 20 + c$ bits.

(b) $\sqrt{2}$ is computable, so a fixed digit-extraction routine plus the
count prints the prefix: $K \le 20 + c'$, the same order as (a), even though
the digits pass statistical randomness tests.

(d) Two nested loops plus the number of blocks: $K = O(\log \log n)$ once the
length is fixed, so smaller still, but not separable from (a) and (b) at this
resolution because all three sit inside the $O(1)$ that invariance leaves
open.

(e) The program "run the shortest program for the half, then print its output
twice" gives $K \le 5 \times 10^5 + c''$: about half of (c).

(c) With probability at least $1 - 2^{-c}$ a fair-coin string is not
compressible by $c$ bits, so $K \ge 10^6 - c$ except with probability
$2^{-c}$; the literal program gives the matching upper bound $10^6 + c'''$.

Every comparison above is asymptotic. The first three are indistinguishable
in the sense that a language can be chosen to reverse any of those three
orderings, while the gaps to (e) and (c) are hundreds of thousands of bits
and no interpreter constant touches them.
</Solution>
</Exercise>

<Exercise>
A vendor whose compressor "shrinks any file" retreats twice under the census.
(a) First retreat: "it never *expands* a file — the worst case is that a file
comes back at its original length." Taking this as a claim about inputs of
every length, show that it forces the compressor to be length-preserving, so
it never shortens a file either. (b) Second retreat: the format gains a
one-bit flag, `1` for "compressed" and `0` for "stored", and the compressor
either saves exactly 10 bits — output $n - 10$ bits, flag included — or falls
back to storing, at $n + 1$ bits. For 1 KB files, $n = 8192$, bound the
fraction that can carry the `1` flag, then compute the mean output length
over all $2^{8192}$ files when that whole fraction is compressed. (c) State
the compressible fraction the flagged format would need in order to break
even against sending the file untouched, and what must be true of the
*inputs* for a real compressor to reach it.

<Solution>
(a) Write $S_m$ for the set of binary strings of length at most $m$, of size
$2^{m+1} - 1$. The claim says $\ell_C(x) \le \ell(x)$ for every $x$, so $C$
maps $S_m$ into $S_m$, and losslessness makes $C$ injective, so on this finite
set $C$ is a bijection of $S_m$ onto itself — for every $m$. Apply that at $m$
and at $m-1$: $C$ maps $S_m$ onto $S_m$ and $S_{m-1}$ onto $S_{m-1}$, hence
maps the difference, the strings of length exactly $m$, onto itself. Every
input therefore comes out at exactly its own length. A compressor that never
expands is a permutation of each length class and compresses nothing.

(b) A compressed output is $n-10$ bits long and begins with `1`, so the
outputs available to the compressed branch number $2^{n-11}$, not $2^{n-10}$:
the flag halves the census as well as the file. By injectivity at most
$2^{n-11}$ of the $2^n$ files can be flagged `1`, a fraction of
$2^{-11} = 1/2048$. Compressing that whole fraction and storing the rest
gives mean output length
$$
(1 - 2^{-11})(n+1) + 2^{-11}(n-10) = n + 1 - \tfrac{11}{2048}
\approx n + 0.995 \text{ bits}.
$$
The flag costs a bit per file and the savings return about one two-hundredth
of it.

(c) Break-even needs $f(n-10) + (1-f)(n+1) \le n$, that is $11f \ge 1$, so
$f \ge 1/11$: about $9\%$ of files must compress, against the census ceiling
of $0.05\%$, a factor of 186 out of reach. What real compressors exploit is
that their inputs are not uniform over the $2^{8192}$ strings. Once the input
carries a distribution $p$, the quantity being bounded is the *expected*
output length, which <Ref lesson="source-coding-theorem-lite">the source
coding theorem</Ref> floors at $H(p)$ for any uniquely decodable format. For
the uniform distribution over 1 KB files that floor is $8192$ bits, which
reproduces the impossibility above; for any real file population it sits far
below $8192$, and the gap is what the vendor is actually selling. The honest
form of the advertisement names that population.
</Solution>
</Exercise>

<Exercise>
Break this claim. "The sequence $u$, which lists all binary words of each
length in order, has a two-line description. Its Kolmogorov complexity is
therefore tiny, so a good compressor will squeeze it to almost nothing."
Give the counter-result, and name the property of the compressor, not of the
string, that is responsible. Then state what a compressor would need in order
to compress $u$.

<Solution>
The first two sentences are correct and the conclusion does not follow.
$K(u_1^{n(k)}) \le \log_2 k + c$, yet the compression ratio attainable on $u$
by finite-state information-lossless encoders is exactly $1$: no such encoder
compresses it at all in the limit. The mechanism is visible in the LZ78
parse, whose phrases are $0,1,00,01,10,11,000,\ldots$, all distinct by
construction, giving $c = 2^{k+1}-2$ phrases for $n(k) = (k-1)2^{k+1}+2$
bits. Since the index for phrase $j$ costs about $\log_2 j$ bits, the output
is about $c \log_2 c \ge n(k)$ bits.

The responsible property is the compressor's **bounded memory**. A machine
with $s$ states distinguishes at most $s$ histories, and $u$'s regularity is
a rule about a counter that grows without bound: at block $k$ the machine
would need to know that it has finished all $2^k$ words of length $k$. The
string is not hiding its structure, and no statistical property of $u$ is
unusual; the block boundaries are simply beyond what a fixed finite state can
track.

To compress $u$ a compressor would need memory used as a counter over block
lengths, which is what the shortest-program description spends $\log_2 k$
bits on. The parsers of <Ref lesson="dictionary-coding"/> store phrases they
have seen, never the rule that generates them, which is why the one sequence
built to exhaust their dictionary defeats them.
</Solution>
</Exercise>

<Exercise>
Break this claim. "$K$ is uncomputable, so it is useless in practice." Name
precisely what *is* computable about $K$, state the direction of the
inequality that survives, and give one concrete use of that surviving
direction from this course.

<Solution>
What is computable is an **upper bound**, for any string, at any time.
Running any lossless compressor on $x$ and adding its decoder's size yields a
program that prints $x$, so $K(x) \le \ell_C(x) + c_C$ is a certificate
obtained by running one program once. What is unavailable is a lower bound:
no computation certifies that no shorter program exists, since that is the
halting problem. $K$ is upper-semicomputable.

The surviving direction is one-sided but not weak. It certifies
non-randomness: exhibiting a $30$-bit program for a megabit string proves
that string is not algorithmically random, and no counter-evidence can
overturn a program that runs. It ranks models on a common scale, which is
what makes bits per byte a measurement rather than a score, since a lower
number is a shorter program that provably exists. And it is the whole content
of the ideal two-part code: choosing the model that minimizes
$K(\mu) - \log_2 \mu(x)$ requires only computable *upper* bounds on both
terms, which is why the principle survives the uncomputability of the
quantity it approximates.

What the claim gets right is narrower than it sounds: no benchmark result
can be read as a statement about the data's information content, only about
the model that produced the bound.
</Solution>
</Exercise>

<Exercise>
Two bounds the lesson used without proving. (a) Prove $K(x) \le |x| + c$ for
every string $x$, exhibiting the program and identifying what the constant
covers. (b) Prove $K(xx) \le K(x) + c'$ for every $x$, with $c'$ independent
of $x$. (c) State what the two together say about the compressibility of
repeated data, and how the argument in (b) changes for $m$ copies rather
than two.

<Solution>
(a) Let $p_x$ be the program `print "x"` with the $|x|$ bits of $x$ carried
literally in the source. It halts and outputs $x$, so
$K(x) \le \ell(p_x) = |x| + c$. The constant covers the print instruction and
the framing that tells the machine where the literal data begins and ends;
it depends on the language and not on $x$, which is what makes it a constant.

(b) Let $p^*$ be a shortest program for $x$, of length $K(x)$. Build $q$:
"run $p^*$, capture its output as $s$, then print $s$ twice". Since $p^*$
halts with output $x$, $q$ halts with output $xx$, and
$\ell(q) = K(x) + c'$, where $c'$ covers the wrapper: the capture, the
doubling, and the self-delimiting framing that marks the end of $p^*$ inside
$q$. The minimum over programs for $xx$ is at most $\ell(q)$.

(c) A file concatenated with itself costs a constant more than the file, so
its shortest description is about half its length: exact repetition is free
in the limit, and a compressor that misses an exact duplicate is leaving a
factor of two on the table. For $m$ copies the same wrapper needs the number
$m$, giving $K(x^m) \le K(x) + \log_2 m + c''$, so a thousand copies cost ten
extra bits over one. The transferable move is that any computable
transformation with a fixed program cost adds only a constant to $K$, which
is why $K$ is invariant under reversal, complementation, and any other fixed
recoding.
</Solution>
</Exercise>

<Exercise>
Measure the gap this lesson claims. Generate the first $n$ bits of three

**Measured sizes**, in bytes, from the two commands above:

**What is being estimated.** All three sequences have $K = O(\log n)$: each
is printed by a short fixed program plus the count. The measurement therefore
estimates none of that. It estimates the finite-state compressibility

lesson's separation on three concrete files: a sequence can be maximally

**A caution about the negative result.** No number of failed compressions

current model classes find, which is the one-sided reading established above.

which builds model selection on exactly this arithmetic.

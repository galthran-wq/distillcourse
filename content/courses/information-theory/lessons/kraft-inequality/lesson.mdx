A codeword of length L claims the fraction 2^-L of a fixed budget of one,
and a prefix code exists with a given set of lengths exactly when those
fractions sum to at most one — the Kraft inequality.

<Ref lesson="prefix-codes"/> established that a code's cost depends on the
code only through its multiset of codeword lengths, and it left one question
unanswered: which multisets of lengths a prefix code can actually have. The
course's argument needs that answer now. Its next claim is that entropy is
not a metaphor for uncertainty but the exact floor on expected bits per
symbol, and a floor can only be proved by optimizing over the admissible
length sets, so the admissible sets have to be characterized first. This
lesson characterizes them exactly: one inequality, proved in both
directions, and then extended by McMillan's theorem to every uniquely
decodable code — every code whose bit streams have exactly one parse,
prefix or not — which is what lets the rest of the course reason about
prefix codes only. What stands open at the end is which admissible length
set a given source deserves, and <Ref lesson="huffman-by-hand"/> settles
that.

The route: pricing a single codeword by the share of the tree it consumes,
the two directions of the inequality (a count for one, a construction for
the other), what equality means, and how far the bound reaches beyond prefix
codes.

## A codeword owns its subtree: the cost of length ℓ

The code tree of <Ref lesson="prefix-codes"/>, whose root-to-leaf paths
spell out the codewords one bit per branch, turns the prefix condition into
a statement about position: no codeword lies on the path to another. That
condition has a price, and the price is measurable.

### The claim is the same fraction at every depth

Fix the codeword `10`. A binary string begins with `10` exactly when its
node lies in the subtree below `10`. At depth 3 that is 2 strings of 8
(`100` and `101`); at depth 4, 4 of 16; at depth $D \ge 2$, exactly
$2^{D-2}$ of the $2^D$ strings of that length. The fraction does not depend
on where the count is taken:

$$
\frac{2^{D-2}}{2^{D}} = 2^{-2} = \tfrac{1}{4}
\qquad \text{at every depth } D.
$$

The same count holds for any length: below a codeword of length $\ell$ sit
$2^{D-\ell}$ of the $2^D$ strings at each depth $D \ge \ell$, the fraction
$2^{-\ell}$. Call that fraction the codeword's **claim**. In a prefix code
no codeword is an ancestor or descendant of another, so no node belongs to
two claims: distinct codewords claim *disjoint* subtrees.

### One budget shared by all codewords

Disjoint fractions of one tree sum to at most 1, which is the whole content
of the inequality in one sentence. Read as an economy: the codewords spend
from a total budget of 1, and a codeword of length $\ell$ costs
$2^{-\ell}$. Short codewords are expensive — length 1 costs $\tfrac12$ of
everything, length 2 costs $\tfrac14$ — and long ones are nearly free, a
length-20 codeword costing under one millionth of the budget.

<Remark title="the budget bounds cost, not count">
$\sum_i 2^{-\ell_i} \le 1$ does not bound the number of codewords. Three
codewords of length 1 are already impossible, at a cost of $\tfrac32$,
while a million codewords of length 30 together cost
$10^6 \cdot 2^{-30} < 0.001$ and leave the budget essentially untouched.
What the budget rations is shortness, not quantity. This is why the
inequality has anything to say about compression: expected length is bought
with short codewords, and short codewords are exactly what is scarce.
</Remark>

## Spending the budget: (1, 2, 3, 3) fits, (1, 2, 2, 2) collides

Pricing one codeword prices a whole code by addition. The matched code of
<Ref lesson="prefix-codes"/>, which gave the running source
$p = (.5, .25, .15, .1)$ the codewords $A \mapsto \texttt{1}$,
$B \mapsto \texttt{01}$, $C \mapsto \texttt{001}$, $D \mapsto \texttt{000}$,
has lengths $(1, 2, 3, 3)$ and total claim

$$
2^{-1} + 2^{-2} + 2^{-3} + 2^{-3}
= \tfrac12 + \tfrac14 + \tfrac18 + \tfrac18 = 1.
$$

The budget is spent exactly. The four subtrees tile the tree with nothing
left over, and no fifth codeword of any length fits, because any fifth
claim is positive and the budget is already gone.

## Necessity: disjoint claims cannot outgrow the tree

The tree pictures above compared claims at different depths, which is
awkward to add up. Pushing every claim down to one common depth removes the
awkwardness, because at a fixed depth a claim is just a set of nodes, and
sets of nodes are counted rather than measured.

<Example title="the descendant count at depth 3">
Take a prefix code with lengths $(1, 2, 3, 3)$, say
$\{\texttt{0}, \texttt{10}, \texttt{110}, \texttt{111}\}$, and cut its tree
off at the deepest codeword, $\ell_{\max} = 3$. Depth 3 holds
$2^3 = 8$ nodes. Each codeword owns those depth-3 nodes lying below it:

- `0` (length 1) owns $2^{3-1} = 4$ of them: `000`, `001`, `010`, `011`;
- `10` (length 2) owns $2^{3-2} = 2$: `100` and `101`;
- `110` and `111` are already at depth 3 and own $2^{3-3} = 1$ node each,
  themselves.

The prefix condition makes the four sets disjoint: a shared node would be a
descendant of two codewords, and then one of those codewords would lie on
the path to the other. So the counts add without overlap,

$$
4 + 2 + 1 + 1 = 8 = 2^{3},
$$

and here they exhaust depth 3 exactly. Dividing through by $2^3$ turns the
count back into the budget: $\tfrac12 + \tfrac14 + \tfrac18 + \tfrac18 = 1$.
</Example>

<Figure
  src="./figures/depth-count.svg"
  alt="A depth-3 binary tree with codewords 0, 10, 110 and 111 marked, and brackets under the bottom row showing they own 4, 2, 1 and 1 of the eight depth-3 nodes"
  caption="Every claim counted at the deepest level: 4 + 2 + 1 + 1 = 8 nodes, and depth 3 has no more to give."
/>

The same count is what refuses $(1, 2, 2, 2)$. There $\ell_{\max} = 2$ and
depth 2 holds $2^2 = 4$ nodes, while the four codewords demand
$2^{2-1} + 1 + 1 + 1 = 5$ disjoint nodes. Five disjoint things do not fit
in four places, and no amount of cleverness in the placement changes the
count.

In general, a codeword of length $\ell_i$ owns exactly
$2^{\ell_{\max} - \ell_i}$ of the nodes at depth $\ell_{\max}$, the sets are
pairwise disjoint by the prefix condition, and depth $\ell_{\max}$ holds
$2^{\ell_{\max}}$ nodes in all:

$$
\sum_i 2^{\ell_{\max} - \ell_i} \le 2^{\ell_{\max}}
\quad\Longleftrightarrow\quad
\sum_i 2^{-\ell_i} \le 1.
$$

Dividing by $2^{\ell_{\max}}$ is the only step, and it is what makes the
statement independent of the depth at which the counting was done.

<Remark title="codes with infinitely many codewords">
The count uses $\ell_{\max}$, so it applies as written only to a finite
code. A prefix code with countably many codewords has no deepest codeword,
but every finite subcode of it is a prefix code and obeys the bound, so all
the partial sums of $\sum_i 2^{-\ell_i}$ are at most 1, and so is their
limit. The extension is not academic: Elias gamma coding, the standard
prefix code for an unbounded positive integer $n$, spends
$2\lfloor \log_2 n \rfloor + 1$ bits on $n$, and the
$2^k$ integers with $\lfloor \log_2 n \rfloor = k$ contribute
$2^k \cdot 2^{-(2k+1)} = 2^{-(k+1)}$ each block, so the claims sum to
exactly 1 over all $n \ge 1$.
</Remark>

## Sufficiency: shortest-first placement realizes the lengths

Necessity only rules length sets out. It gives no reason to believe that a
length set passing the test can be built, and passing an inequality is
weaker evidence than it looks: the budget is an accounting condition, while
building a code means finding actual disjoint nodes at prescribed depths.
The converse holds anyway, and the proof is an algorithm.

### The construction

Sort the lengths $\ell_1 \le \ell_2 \le \cdots \le \ell_m$. Place codeword
$i$ at the **leftmost** node of depth $\ell_i$ that lies in no claimed
subtree, then claim its subtree. Nothing about the source distribution
enters; the input is a sorted list of integers.

### Why it never gets stuck

At each step the question is whether a free node of the required depth
still exists, and that is again a count.

<Example title="the free-node count during construction">
For the lengths $(1, 2, 3, 3)$:

1. **Length 1.** No claims exist; take `0`.
2. **Length 2.** The claim of `0` blocks the depth-2 nodes `00` and `01`,
   which is $2^{2-1} = 2$ of the $4$ nodes at that depth; the leftmost free
   node is `10`.
3. **Length 3.** Blocked at depth 3 are the $2^{3-1} = 4$ nodes below `0`
   and the $2^{3-2} = 2$ below `10`, together $6$ of $8$; take `110`.
4. **Length 3.** Now $7$ of $8$ are blocked; take `111`, the last node.

The blocked count at step $i$ is
$\sum_{j<i} 2^{\ell_i - \ell_j} = 2^{\ell_i} \sum_{j<i} 2^{-\ell_j}$: the
budget already spent, rescaled to depth $\ell_i$. The budget still holds
$2^{-\ell_i}$ in reserve for codeword $i$ itself, so the spent part is at
most $1 - 2^{-\ell_i}$ and the blocked count is at most $2^{\ell_i} - 1$.
One node at depth $\ell_i$ survives, and often many more.
</Example>

The step to read twice is the rescaling
$\sum_{j<i} 2^{\ell_i - \ell_j} = 2^{\ell_i} \sum_{j<i} 2^{-\ell_j}$. It is
where the argument stops being about this example: the left side counts
nodes at one particular depth, the right side is the budget, and the
factor $2^{\ell_i}$ converts one into the other for any lengths whatsoever.

<Exercise>

with equality, then run the construction on them. List the codewords in
placement order, and for each placement after the first report how many
nodes of the required depth were already blocked.

<Solution>
**The sum.** $3 \cdot \tfrac14 + \tfrac18 + 2 \cdot \tfrac1{16}
= \tfrac34 + \tfrac18 + \tfrac18 = 1$: achievable, with no slack.

**Placement.** The three length-2 codewords take the leftmost depth-2
nodes: `00`, `01`, `10`. At depth 3 the three claims block
$3 \cdot 2^{3-2} = 6$ of the $8$ nodes, leaving `110` and `111`; the
leftmost free node is `110`. At depth 4 the length-2 claims block
$3 \cdot 2^{4-2} = 12$ nodes and `110` blocks $2^{4-3} = 2$ more, so
$14$ of $16$ are gone and the survivors are `1110` and `1111`.

**Code.** $\{\texttt{00}, \texttt{01}, \texttt{10}, \texttt{110},
\texttt{1110}, \texttt{1111}\}$. No codeword is a prefix of another, the
blocked counts $6$, $12$, $14$ never reached the total available at their
depth, and the claims sum to exactly 1.
</Solution>
</Exercise>

### Sorting is a hypothesis, not a convenience

Two properties of the construction come from the sort, and both fail
without it. First, every earlier codeword sits at depth $\le \ell_i$, so no
earlier codeword can lie strictly below the new node; combined with the
choice of a node outside every claim, this rules out a prefix relation in
either direction. Second, a deeper codeword placed early contaminates a
shallow node without consuming much budget, and the count above no longer
describes what is blocked.

<Figure
  src="./figures/out-of-order.svg"
  alt="Top: the lengths 1, 2, 3, 3 placed in the order 3, 3, 2, 1 at nodes 010, 101 and 00, leaving no legal depth-1 node for the last codeword. Bottom: the same lengths placed shortest-first at 0, 10, 110, 111"
  caption="Same lengths, sum exactly 1: placed longest-first the construction strands the length-1 codeword; placed shortest-first it never does."
/>

The failure is not marginal. Place the two length-3 codewords of
$(1, 2, 3, 3)$ at `010` and `101`, then the length-2 codeword at `00`:
every choice is legal when it is made, the sum is still exactly 1, and yet
both depth-1 nodes are now ancestors of placed codewords, so the length-1
codeword has nowhere to go. The theorem promises that *some* assignment
achieves a legal length set, not that every partial assignment extends to
one.

### The theorem

<Theorem title="Kraft inequality (Cover &amp; Thomas 5.2.1)">
A binary prefix code with codeword lengths $\ell_1, \dots, \ell_m$ exists
if and only if
$$
\sum_{i=1}^{m} 2^{-\ell_i} \le 1.
$$

<Proof>
The two directions are independent arguments: a count over the nodes at one
depth, and an induction on the construction above.

**Necessity.** Let a prefix code with lengths $\ell_1, \dots, \ell_m$ be
given and set $\ell_{\max} = \max_i \ell_i$. In the full binary tree of
depth $\ell_{\max}$, the codeword of length $\ell_i$ has exactly
$2^{\ell_{\max} - \ell_i}$ descendants at depth $\ell_{\max}$. If two
codewords shared such a descendant, one codeword would be a prefix of the
other, contradicting the prefix condition; so the descendant sets are
pairwise disjoint subsets of the $2^{\ell_{\max}}$ nodes at that depth.
Hence $\sum_i 2^{\ell_{\max} - \ell_i} \le 2^{\ell_{\max}}$, and dividing
by $2^{\ell_{\max}}$ gives the inequality.

**Sufficiency.** Assume $\sum_i 2^{-\ell_i} \le 1$ and sort
$\ell_1 \le \cdots \le \ell_m$. Assign codewords in this order, each to the
leftmost node of depth $\ell_i$ that is neither a claimed codeword nor a
descendant of one. When codeword $i$ is to be placed, each earlier codeword
$j < i$ has depth $\ell_j \le \ell_i$ and blocks exactly
$2^{\ell_i - \ell_j}$ of the $2^{\ell_i}$ nodes at depth $\ell_i$, namely
the depth-$\ell_i$ nodes in its subtree. The blocked total is

$$
\sum_{j<i} 2^{\ell_i - \ell_j}
= 2^{\ell_i} \sum_{j<i} 2^{-\ell_j}
\le 2^{\ell_i} \bigl(1 - 2^{-\ell_i}\bigr)
= 2^{\ell_i} - 1 < 2^{\ell_i},
$$

using $\sum_{j \le i} 2^{-\ell_j} \le 1$. A free node therefore exists.
Because all earlier codewords sit at depth $\le \ell_i$, none lies strictly
below the chosen node, and by the choice of node it lies below none of
them: no prefix relation arises in either direction. Induction over $i$
completes a prefix code with the prescribed lengths.
</Proof>
</Theorem>

The construction has a closed form worth seeing, because it is the same
arithmetic that <Ref lesson="arithmetic-coding"/> later runs on
probabilities instead of on powers of two.

<Example title="the same code, read off in binary">
Sort the lengths and let $a_i = \sum_{j<i} 2^{-\ell_j}$ be the budget spent
before codeword $i$. Writing $a_i$ in binary and keeping its first $\ell_i$
bits gives codeword $i$. For $(1, 2, 3, 3)$:

| $i$ | $\ell_i$ | $a_i$ | binary | first $\ell_i$ bits |
| --- | --- | --- | --- | --- |
| 1 | 1 | $0$ | $0.000\ldots$ | `0` |
| 2 | 2 | $\tfrac12$ | $0.100\ldots$ | `10` |
| 3 | 3 | $\tfrac34$ | $0.110\ldots$ | `110` |
| 4 | 3 | $\tfrac78$ | $0.111\ldots$ | `111` |

The result is the code the tree construction produced. It has to be: the
leftmost free node at depth $\ell_i$ is the one whose interval starts where
the previous claims stopped, and $a_i$ is that stopping point.
</Example>

<Aside>
The arithmetic twin of the tree picture. Read a codeword
$c = b_1 b_2 \dots b_\ell$ as the binary fraction $0.b_1 b_2 \dots b_\ell$;
the strings beginning with $c$ correspond to the half-open interval
$[0.c,\; 0.c + 2^{-\ell}) \subseteq [0, 1)$, of length $2^{-\ell}$. The
prefix condition says the intervals of distinct codewords are disjoint, and
the Kraft inequality says disjoint subintervals of $[0,1)$ have total length
at most 1, which is the tiling fact rather than a theorem about codes. The
table above is exactly this reading: $a_i$ is the left endpoint of
codeword $i$'s interval, and the interval of every codeword lies to the
right of every earlier one. Arithmetic coding keeps the intervals and drops
the requirement that their widths be powers of two.
</Aside>

<Remark title="existence of lengths, not quality of a code">
The theorem decides whether a length set is achievable; it says nothing
about which lengths a source deserves, and nothing about which symbol
should receive which length. On the running source $(.5, .25, .15, .1)$,
both the balanced lengths $(2, 2, 2, 2)$ and the matched lengths
$(1, 2, 3, 3)$ pass the test, with expected lengths $2.00$ and $1.75$ bits
(<Ref lesson="prefix-codes"/>). Kraft rules length sets in or out; choosing
the best admissible set for a distribution, and pairing it with the symbols,
is the Huffman algorithm of <Ref lesson="huffman-by-hand"/>.
</Remark>

## Equality: complete codes and the length trade-off

The running example spent its budget exactly, and the impossible one
overspent. The third case, a code that leaves money on the table, is the
one that says something about optimality.

<Definition title="complete code">
A prefix code is **complete** if its lengths satisfy
$\sum_i 2^{-\ell_i} = 1$.
</Definition>

In the tree, completeness means no waste: the claims tile the entire tree,
and no codeword can be added at any length. The codes
$\{\texttt{0}, \texttt{10}, \texttt{110}, \texttt{111}\}$ and
$\{\texttt{00}, \texttt{01}, \texttt{10}, \texttt{11}\}$ are complete;
$\{\texttt{0}, \texttt{10}, \texttt{110}\}$ is not, its sum being
$\tfrac78$. The unclaimed eighth of that tree is the subtree below `111`,
and it can be spent in either of two ways: on an extra codeword, or on
shortening `110` to `11`.

### Any slack buys a strictly shorter code

Every term $2^{-\ell_i}$ is an integer multiple of $2^{-\ell_{\max}}$, so
the sum is too. A sum below 1 is therefore below it by at least
$2^{-\ell_{\max}}$, which is precisely what one longest codeword adds to the
sum when it is shortened from $\ell_{\max}$ to $\ell_{\max} - 1$: its claim
doubles from $2^{-\ell_{\max}}$ to $2^{-\ell_{\max}+1}$, and the total
cannot pass 1. The shortened length set still satisfies the inequality, the
construction rebuilds a prefix code for it, and the expected length has
strictly decreased provided that symbol has positive probability. An
incomplete code is never optimal. The rebuild may relocate every codeword
in the tree, which is why the argument is about lengths and not about any
particular set of bit strings.

### At equality, lengths become zero-sum

For a complete code the trade is exact: shortening one codeword by a bit
doubles its claim, and the other codewords must jointly surrender the
difference by growing longer.

<FigureSequence
  name="tradeoff"
  alt="Three frames: four length-2 codewords cost 4 quarters and fill the budget; shortening one to length 1 overflows the budget to 1.25; lengthening two others to length 3 restores the sum to exactly 1"
  caption="Shortening one codeword overflows the budget; other codewords pay with extra bits."
/>

<Task>
Step through the three frames and track the bar: frame 2's overspend is
$\tfrac12 + 3 \cdot \tfrac14 = 1.25$, and frame 3 restores
$\tfrac12 + \tfrac14 + \tfrac18 + \tfrac18 = 1$. Total the codeword lengths
before and after: 8 bits become 9, so the one bit saved on the first
codeword cost two bits elsewhere.
</Task>

Which trade is worth making depends on the probabilities, and that is the
entire content of code design. A bit saved on a symbol of probability $.5$
pays for two bits added to symbols of combined probability $.25$; the same
trade at reversed probabilities loses.

<Remark title="the claims will read as probabilities">
At equality the claims $q_i = 2^{-\ell_i}$ are positive and sum to 1, which
is formally a probability distribution over the symbols. Nothing
probabilistic has happened: $q_i$ is a share of a tree, not a chance.
<Ref lesson="source-coding-theorem-lite"/> reads $q$ as the distribution the
code is implicitly designed for and prices the mismatch between $q$ and the
true source distribution, and that step turns the Kraft budget into the
entropy floor $H(X) \le L$ stated in <Ref lesson="prefix-codes"/>.
</Remark>

<KeyFact>
Because slack of any size can be converted into a shorter codeword, every
optimal code is complete: the Huffman trees of
<Ref lesson="huffman-by-hand"/> will never have an unused node, and a
compressed format whose code table does not sum to 1 has bits to recover.
</KeyFact>

## ★ A second proof: flip coins until a codeword appears

The counting proof of necessity treats the tree as a finite object and
needs its deepest level. A different argument reaches the same bound by
reading the sum $\sum_i 2^{-\ell_i}$ as a probability, and it needs no
deepest level at all. The core path does not use this section.

Generate independent fair bits and stop as soon as the string written so
far is a codeword. Each specific codeword $c$ of length $\ell$ is written
exactly when the first $\ell$ flips come out as its bits, an event of
probability $2^{-\ell}$. In a prefix code these events are mutually
exclusive, because the process stops at the first codeword it completes and
no codeword extends another, so no run of flips can complete two of them.
Their probabilities therefore add, and

$$
\sum_i 2^{-\ell_i} = \Pr[\text{the flipping ever stops}] \le 1 .
$$

<Figure
  src="./figures/coin-walk.svg"
  alt="A binary tree with codewords 0 and 10 marked; the highlighted path 1 then 0 reaches the codeword 10 with probability one half times one half, and the subtree under 11 is marked as never stopping with probability one quarter"
  caption="The incomplete code {0, 10}: the flipping stops with probability ¾, and the missing ¼ is the chance of walking forever into the unclaimed subtree."
/>

The slack acquires a meaning under this reading: $1 - \sum_i 2^{-\ell_i}$ is
the probability that the coin flips never complete a codeword, which
happens exactly when the walk descends forever through unclaimed nodes. A
complete code is one whose flipping stops with probability 1. Two things
follow that the counting proof does not give directly. The bound holds for
codes with infinitely many codewords with no change of argument, since
nothing referred to a maximum length. And the disjointness step names
exactly where the prefix condition is used: for the uniquely decodable but
non-prefix code $\{\texttt{0}, \texttt{01}, \texttt{011}\}$ the process
stops at the first `0` and never reaches `01`, so the three events are
nested rather than exclusive and their probabilities may not be added.

<Aside>
Repairing that step for uniquely decodable codes is
[an open problem](https://live.ocw.mit.edu/courses/6-441-information-theory-spring-2016/5d8f16adc3385c9ff2975b121bd620e4_MIT6_441S16_course_notes.pdf):
Polyanskiy and Wu record it in §6.2 alongside a second one, Ahlswede's
conjecture that any lengths with $\sum_i 2^{-\ell_i} \le \tfrac34$ admit a
*fix-free* code, one that is simultaneously prefix-free and suffix-free and
so decodable from either end. Existence is known only under the stronger
hypothesis $\sum_i 2^{-\ell_i} \le \tfrac58$. The gap between $\tfrac34$
and 1 is the price of demanding decodability in both directions, and unlike
the prefix restriction it is a real price.
</Aside>

## McMillan's theorem: the same budget for every uniquely decodable code

The bound has been proved for prefix codes twice over, and prefix codes are
a strict subclass of the codes that decode: the code
$\{\texttt{0}, \texttt{01}, \texttt{011}, \texttt{0111}\}$ from
<Ref lesson="prefix-codes"/>, in which every codeword is a `0` followed by
`1`s so that each `0` marks a fresh codeword, violates the prefix condition
yet decodes uniquely with lookahead. One would expect the larger class to
buy shorter codes. It does not. Those lengths $(1, 2, 3, 4)$ already cost
$\tfrac{15}{16} \le 1$, no subtree-disjointness argument applies to them
since `01` sits inside the subtree of `0`, and the bound holds anyway.

<Theorem title="McMillan (Karush's argument, Cover &amp; Thomas 5.5.1)">
Every uniquely decodable binary code with codeword lengths
$\ell_1, \dots, \ell_m$ satisfies $\sum_{i=1}^{m} 2^{-\ell_i} \le 1$.

<Proof>
A sketch: the counting is exact, and the limit step at the end is where the
full treatment in Cover &amp; Thomas §5.5 supplies the detail.

Let $C = \sum_i 2^{-\ell_i}$ and fix an integer $k \ge 1$. Raising the sum
to the $k$-th power expands over all $k$-tuples of codewords:

$$
C^k = \sum_{i_1, \dots, i_k} 2^{-(\ell_{i_1} + \cdots + \ell_{i_k})}
    = \sum_{n} N(n)\, 2^{-n},
$$

where $N(n)$ counts the $k$-tuples whose concatenation is $n$ bits long.
Unique decodability enters exactly once: distinct tuples concatenate to
distinct $n$-bit strings, so $N(n) \le 2^n$ and every term $N(n) 2^{-n}$ is
at most 1. Only lengths $n \le k \ell_{\max}$ occur, so
$C^k \le k \ell_{\max}$ and $C \le (k \ell_{\max})^{1/k}$ for every $k$.
The right side tends to 1 as $k$ grows, so $C > 1$ is impossible: the left
side would grow exponentially in $k$ against a linear bound.
</Proof>
</Theorem>

The consequence is structural rather than numerical. Whatever lengths a
uniquely decodable code achieves, those lengths pass the budget, and the
shortest-first construction realizes them as a prefix code. For
$\{\texttt{0}, \texttt{01}, \texttt{011}, \texttt{0111}\}$ the construction
returns $\{\texttt{0}, \texttt{10}, \texttt{110}, \texttt{1110}\}$: the same
four lengths, now decodable one bit at a time with no lookahead.

<KeyFact>
Minimizing expected length over all uniquely decodable codes gives the same
answer as minimizing it over prefix codes, so every impossibility proved
against the Kraft budget applies to every code that can be decoded at all.
This is the hook <Ref lesson="source-coding-theorem-lite"/> needs: a floor
proved for prefix codes is a floor for lossless compression.
</KeyFact>

Established: a codeword of length $\ell$ claims the fraction $2^{-\ell}$ of
the code tree; a prefix code with given lengths exists exactly when those
claims sum to at most 1, by a count in one direction and a shortest-first
construction in the other; equality marks a complete code, and any slack
converts into a strictly shorter code; and the same bound constrains every
uniquely decodable code. The set of admissible length sets is now known
exactly. <Ref lesson="huffman-by-hand"/> takes the next step and picks the
admissible set that minimizes expected length for a given distribution,
which turns the accounting constraint of this lesson into an algorithm.

## Exercises

<Exercise>
For each length set, compute the Kraft sum and state whether a binary
prefix code exists; for the achievable sets give a code and the slack
$1 - \sum_i 2^{-\ell_i}$: (a) $(2, 2, 2, 2)$; (b) $(1, 2, 3, 4)$;
(c) $(1, 1, 2)$; (d) $(2, 3, 3, 3, 3, 3)$.

<Solution>
(a) $4 \cdot \tfrac14 = 1$: achievable, slack $0$, complete. Code
$\{\texttt{00}, \texttt{01}, \texttt{10}, \texttt{11}\}$.

(b) $\tfrac12 + \tfrac14 + \tfrac18 + \tfrac1{16} = \tfrac{15}{16}$:
achievable, slack $\tfrac{1}{16}$. Code
$\{\texttt{0}, \texttt{10}, \texttt{110}, \texttt{1110}\}$, with the
subtree below `1111` unclaimed.

(c) $\tfrac12 + \tfrac12 + \tfrac14 = 1.25 > 1$: no prefix code. The two
length-1 codewords already take both depth-1 nodes and claim the whole
tree.

(d) $\tfrac14 + 5 \cdot \tfrac18 = \tfrac78$: achievable, slack $\tfrac18$.
Shortest-first gives
$\{\texttt{00}, \texttt{010}, \texttt{011}, \texttt{100}, \texttt{101},
\texttt{110}\}$, leaving `111` free.
</Solution>
</Exercise>

<Exercise>
A code has lengths $(1, 2, 3, 4, 5, 6, 7)$, so its Kraft sum is exactly
$1 - 2^{-7}$. (a) Describe the slack structurally: what is left over in the
tree? (b) You may add one more codeword. What lengths are available, and is
there a longest one? (c) The seven symbols turn out to be uniformly
distributed. Compute this code's expected length, compare it with the best
code for a uniform 7-symbol source, and say what the comparison shows about
using slack as a measure of quality.

<Solution>
**(a) The slack is one node.** Shortest-first places
`0`, `10`, `110`, `1110`, `11110`, `111110`, `1111110`. Every node of the
tree is claimed except the subtree below `1111111`, a single node at depth
7 together with everything under it. That subtree is worth $2^{-7}$, which
is the slack.

**(b) A minimum length, not a maximum.** A new codeword of length $\ell$
costs $2^{-\ell}$ and must fit in $2^{-7}$, so $\ell \ge 7$: exactly one
choice at length 7 (`1111111` itself), two available at length 8, four at
length 9, and so on without end. There is no longest addable codeword. The
budget constrains codewords from below in length, never from above, which
is the same asymmetry as the earlier remark that it rations shortness and
not quantity.

**(c) Slack is almost uninformative about cost.** Under the uniform
distribution each symbol has probability $\tfrac17$, so
$$
L = \tfrac17(1 + 2 + 3 + 4 + 5 + 6 + 7) = \tfrac{28}{7} = 4 \text{ bits.}
$$
The best legal code for 7 symbols has as many short codewords as the budget
allows: with $k$ codewords of length 2 and $7-k$ of length 3, the sum is
$\tfrac{k}{4} + \tfrac{7-k}{8} \le 1$, which forces $k \le 1$. Taking
$k = 1$ gives lengths $(2, 3, 3, 3, 3, 3, 3)$, a complete code, and
$$
L = \tfrac17(2 + 6 \cdot 3) = \tfrac{20}{7} \approx 2.857 \text{ bits,}
$$
against the entropy $\log_2 7 \approx 2.807$ bits. The chain code wastes
about $1.14$ bits per symbol while its slack is under 1% of the budget. A
nearly-spent budget says the code has few wasted nodes; it says nothing
about whether the lengths sit where the probability is.
</Solution>
</Exercise>

<Exercise>
Refute the claim: "a code satisfying Kraft with equality is optimal."
Exhibit a distribution and a complete code that is not optimal for it, give
both expected lengths, and state precisely what equality does guarantee.

<Solution>
**A counterexample.** Take the running source $p = (.5, .25, .15, .1)$ on
$A, B, C, D$ and the complete code
$A \mapsto \texttt{110}$, $B \mapsto \texttt{111}$, $C \mapsto \texttt{10}$,
$D \mapsto \texttt{0}$. Its lengths are $(3, 3, 2, 1)$, the same multiset as
the matched code, so the Kraft sum is exactly 1 and no node is wasted. Its
expected length is
$$
L = .5(3) + .25(3) + .15(2) + .1(1) = 1.5 + .75 + .3 + .1 = 2.65
\text{ bits,}
$$
against $1.75$ bits for the same lengths paired the other way round, and
$2.00$ bits for the balanced code $(2,2,2,2)$, which is also complete. Two
complete codes with expected lengths $2.65$ and $1.75$ settle the claim.

**What equality does guarantee.** Completeness is a statement about the
tree, not about the source: no codeword can be shortened without lengthening
another, and no codeword can be added. The converse of the false claim is
what actually holds, and it was proved in the body: every optimal code is
complete, since slack of any size can be spent on shortening a codeword.
Optimality additionally requires the pairing, giving short codewords to
probable symbols, and that is what Huffman's algorithm supplies.
</Solution>
</Exercise>

<Exercise>
Run McMillan's counting argument by hand at $k = 2$ for the uniquely
decodable code $\{\texttt{0}, \texttt{01}, \texttt{011}\}$. Expand
$(\sum_i 2^{-\ell_i})^2$ over the nine pairs, tally $N(n)$ (the number of
pairs whose concatenation has length $n$), verify the identity
$C^2 = \sum_n N(n) 2^{-n}$ numerically, and check $N(n) \le 2^n$ in every
case. Then state what bound on $C$ this value of $k$ actually delivers, and
why the argument needs $k \to \infty$.

<Solution>
**The code and the sum.** Lengths $(1, 2, 3)$, so
$C = \tfrac12 + \tfrac14 + \tfrac18 = \tfrac78$ and
$C^2 = \tfrac{49}{64} \approx 0.766$.

**The nine concatenations.**

| pair | string | length |
| --- | --- | --- |
| `0`+`0` | `00` | 2 |
| `0`+`01` | `001` | 3 |
| `01`+`0` | `010` | 3 |
| `0`+`011` | `0011` | 4 |
| `01`+`01` | `0101` | 4 |
| `011`+`0` | `0110` | 4 |
| `01`+`011` | `01011` | 5 |
| `011`+`01` | `01101` | 5 |
| `011`+`011` | `011011` | 6 |

All nine strings are distinct, which is unique decodability doing its one
job: a length-4 output such as `0110` has only one reading as a pair.

**The tally.** $N(2) = 1$, $N(3) = 2$, $N(4) = 3$, $N(5) = 2$, $N(6) = 1$,
and
$$
\sum_n N(n) 2^{-n} = \tfrac14 + \tfrac28 + \tfrac3{16} + \tfrac2{32}
+ \tfrac1{64} = \tfrac{16 + 16 + 12 + 4 + 1}{64} = \tfrac{49}{64} = C^2 .
$$
The counting bounds hold with room to spare: $1 \le 4$, $2 \le 8$,
$3 \le 16$, $2 \le 32$, $1 \le 64$.

**What $k = 2$ delivers.** Every term is at most 1 and only the lengths
$n = 2, \dots, k\ell_{\max} = 6$ occur, so $C^2 \le 6$ and
$C \le \sqrt{6} \approx 2.45$: true, and useless, since $C \le 2.45$ rules
out nothing. The bound $C \le (k\ell_{\max})^{1/k}$ improves with $k$
because the exponent $1/k$ crushes the polynomial factor: at $k = 100$ it
reads $C \le 300^{0.01} \approx 1.058$, and the limit is 1. The counting is
loose at every finite $k$; what the argument exploits is that $C^k$ would
grow exponentially if $C$ exceeded 1, while the number of available strings
grows only linearly in $k$.
</Solution>
</Exercise>

<Exercise>
Flip independent fair bits and stop as soon as the bits written so far form
a codeword of a given prefix code. (a) Show that
$\sum_i 2^{-\ell_i}$ is the probability that the process ever stops, naming
the property of prefix codes that makes the events addable. (b) Characterize
the codes for which the process stops with probability 1. (c) Exhibit a
prefix code under which the flipping runs forever with probability at least
$\tfrac14$, and give the exact probability. Write down what event you are
assigning probability $2^{-\ell}$ to before opening the solution.

<Solution>
**(a) The events.** For a fixed codeword $c$ of length $\ell$, the process
stops at $c$ exactly when the first $\ell$ flips spell $c$ and no earlier
prefix of that string was itself a codeword. In a prefix code the second
condition is automatic, so the event is just "the first $\ell$ flips spell
$c$", of probability $2^{-\ell}$. Two such events are disjoint: if runs of
flips completed two different codewords, the shorter would be a prefix of
the longer. Disjoint events have addable probabilities, so
$\Pr[\text{stop}] = \sum_i 2^{-\ell_i}$, and a probability is at most 1.

**(b) Stopping almost surely.** $\Pr[\text{stop}] = 1$ says
$\sum_i 2^{-\ell_i} = 1$, which is exactly completeness. Non-stopping
sequences are the infinite paths that avoid every claimed subtree, and a
complete code leaves no such path.

**(c) An incomplete code.** Take $\{\texttt{0}, \texttt{10}\}$, with sum
$\tfrac12 + \tfrac14 = \tfrac34$. The process stops only if the first flip
is `0`, or the first two are `1` then `0`. If the first two flips are `1`,
`1` the walk has entered the subtree below `11`, which contains no
codeword, and no later flip can help. The probability of running forever is
$\tfrac14$, exactly the slack.

The transferable move is that a bound of the form "these fractions sum to
at most 1" can often be proved by finding disjoint events with those
probabilities, rather than by counting anything.
</Solution>
</Exercise>

<Exercise>
For the running source $p = (.5, .25, .15, .1)$, list every set of four
codeword lengths that satisfies the Kraft inequality with equality and has
maximum length 3. For each, compute the smallest expected length achievable
by pairing it with the symbols, and identify the best code. Compare it with
the entropy $H(p) \approx 1.743$ bits computed in
<Ref lesson="prefix-codes"/>.

<Solution>
**Enumerate.** Let $a$, $b$, $c$ count the lengths equal to 1, 2, 3. Then
$a + b + c = 4$ and $\tfrac{a}{2} + \tfrac{b}{4} + \tfrac{c}{8} = 1$, that
is $4a + 2b + c = 8$. Subtracting the first equation from the second gives
$3a + b = 4$, whose non-negative solutions are $a = 0, b = 4, c = 0$ and
$a = 1, b = 1, c = 2$. Exactly two length sets qualify: $(2,2,2,2)$ and
$(1,2,3,3)$. ($a = 2$ would need $b = -2$; $a \ge 2$ is also blocked by the
budget alone, since two length-1 codewords already spend it all.)

**Expected lengths.** The balanced set gives $L = 2.00$ bits whatever the
pairing. For $(1,2,3,3)$ the pairing matters, and the smallest $L$ comes
from giving the shortest codeword to the most probable symbol:
$$
L = .5(1) + .25(2) + .15(3) + .1(3) = .5 + .5 + .45 + .3 = 1.75
\text{ bits.}
$$
Any other pairing is worse; the reversed one costs $2.65$ bits.

**The winner.** $(1,2,3,3)$ paired in decreasing order of probability, at
$1.75$ bits per symbol, which clears the entropy $1.743$ bits by $0.007$.
The margin is small because the claims $2^{-\ell}$ of this code,
$(\tfrac12, \tfrac14, \tfrac18, \tfrac18)$, differ from $p$ only on the two
rare symbols, and those carry $.25$ of the mass between them.
</Solution>
</Exercise>

<Exercise>
Given a prefix code with lengths $\ell(x)$, define
$q(x) = 2^{-\ell(x)}$. (a) Verify for the complete code
$\{\texttt{0}, \texttt{10}, \texttt{110}, \texttt{111}\}$ on symbols
$A, B, C, D$ that $q$ is a probability distribution. (b) With the running
source $p = (.5, .25, .15, .1)$, compute $\sum_x p(x)\ell(x)$ and
$\sum_x p(x) \log_2 \tfrac{1}{q(x)}$ and compare. (c) Subtract the entropy
$H(p) \approx 1.743$ bits from the expected length and report the
difference to three decimals. (d) Compute
$\sum_x p(x) \log_2 \tfrac{p(x)}{q(x)}$ and compare with (c). Use
$\log_2 1.2 \approx 0.263$ and $\log_2 0.8 \approx -0.322$.

<Solution>
**(a)** The lengths are $(1, 2, 3, 3)$, so
$q = (\tfrac12, \tfrac14, \tfrac18, \tfrac18)$: positive, and summing to 1
because the code is complete. Completeness is exactly the normalization
condition.

**(b)** Expected length:
$L = .5(1) + .25(2) + .15(3) + .1(3) = 1.75$ bits. And
$\log_2 \tfrac{1}{q(x)} = \ell(x)$ for every symbol, term by term, so
$\sum_x p(x)\log_2 \tfrac{1}{q(x)} = 1.75$ bits as well. The two
computations are the same computation: a codeword length is the surprisal
of the code's own claim.

**(c)** $1.75 - 1.743 = 0.007$ bits per symbol.

**(d)** Only $C$ and $D$ contribute, since $p = q$ on $A$ and $B$:
$$
.15 \log_2 \tfrac{.15}{.125} + .1 \log_2 \tfrac{.1}{.125}
= .15(0.263) + .1(-0.322) = 0.0395 - 0.0322 = 0.007 \text{ bits,}
$$
the same number as (c).

**What this is.** A prefix code is a bet on the distribution $q$ implied by
its own lengths, and the excess over entropy is the quantity computed in
(d), which measures how far the source $p$ is from the code's bet. It is
non-negative always, and zero only when $p = q$. The identity
$L = H(p) + (\text{that quantity})$ is proved in general in
<Ref lesson="source-coding-theorem-lite"/>, and the quantity is named and
studied as the KL divergence in <Ref lesson="kl-divergence"/>.
</Solution>
</Exercise>

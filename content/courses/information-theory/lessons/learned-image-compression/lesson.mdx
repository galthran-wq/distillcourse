A learned image codec trains an encoder, a quantizer, an entropy model and a
decoder against the single objective rate plus lambda times distortion, which
is the rate-distortion Lagrangian with neural networks standing in for the
test channel.

Every part of that objective is already established. Rate is a
cross-entropy, and coding with the wrong distribution costs exactly a
divergence (<Ref lesson="kl-divergence"/>); an arithmetic coder turns any
distribution into a bitstream at within two bits of the ideal
(<Ref lesson="arithmetic-coding"/>); giving up exact reconstruction turns the
coding floor into a curve $R(D)$ whose Lagrangian form is $R + \lambda D$
(<Ref lesson="rate-distortion"/>); and the last two lessons asked what to keep
rather than how to spend, but could only bound the quantity they wanted
(<Ref lesson="information-bottleneck"/>, <Ref lesson="infonce"/>). What stands
open is whether the whole construction runs as one system. This lesson takes
one apart: a codec in which every named quantity of this course is a term in a
single differentiable loss.

The route: the four stages of transform coding and where JPEG already has
them, the rate term as a cross-entropy, the trick that makes rounding
differentiable, the identity that makes an autoencoder's variational bound
equal to $R + \lambda D$, the side channel that prices the latents, the
measured cost of that side channel, and what the choice of distortion measure
does to the pictures.

## Four stages, and JPEG already has all four

Lossy image compression is older than any of the machinery in this course, and
its architecture has not changed. Start with the version that shipped in 1992.

### JPEG on one 8×8 block

A JPEG encoder cuts the image into blocks of $8 \times 8$ pixels and treats
each one separately. It applies a fixed linear map, the discrete cosine
transform, turning the 64 intensities into 64 coefficients that describe the
block as a sum of 64 fixed patterns, from flat to finely striped. It divides
each coefficient by an entry of a fixed table of 64 divisors, small for the
coarse patterns and several times larger for the fine ones, and rounds the
result to an integer. Most of the fine-pattern coefficients round to zero. The
surviving integers are read out in a fixed order and entropy coded with
Huffman tables (<Ref lesson="huffman-by-hand"/>). The decoder undoes each step
in reverse and gets an image back that is not the original.

Four things happened, in this order: a transform, a quantizer, an entropy
code, an inverse transform. That sequence is called *transform coding*, and
every lossy image and video codec in use is an instance of it.

### The same four boxes, all of them trained

The learned codec keeps the sequence and replaces the contents of every box.

<Definition title="nonlinear transform coding">
A lossy code in which an **analysis transform** $g_a$ maps the image $x$ to a
*latent representation* $y = g_a(x; \phi)$, a quantizer rounds $y$ to integers
$\hat y$, an entropy coder writes $\hat y$ to a bitstream under a probability
model, and a **synthesis transform** $g_s$ maps $\hat y$ back to a
reconstruction $\hat x = g_s(\hat y; \theta)$. The transforms are
parameterised nonlinear functions and $\phi, \theta$ are trained.
</Definition>

In the codec this lesson reads, $g_a$ is four convolutions each halving the
image in both directions, interleaved with a normalising nonlinearity, and
$g_s$ is its mirror image with upsampling convolutions. Sixteenfold
downsampling in each direction leaves one latent position per 256 pixels, and
in the lower-rate configurations the transform emits 192 channels at each
position, so a $768 \times 512$ photograph becomes
$48 \times 32 \times 192 = 294{,}912$ integers, exactly $0.75$ coefficients
per pixel. The file's entire job is to convey those integers.

  caption="Same four stages, different provenance for the numbers inside them: a standards committee, or gradient descent on one loss."

The difference is not that the learned transform is nonlinear, though it is.
It is that all four stages are fitted against the same objective. JPEG's
transform was chosen before its quantization table, and both before its
Huffman tables; nothing in the design lets a decision in one stage be paid for
by a saving in another. Here the analysis transform is free to produce latents
that are awkward to reconstruct if they are cheap to encode, because the same
gradient reaches both.

<KeyFact>
JPEG's entropy model is factorised into fixed groups of 64 coefficients, one
group per block, and that factorisation is a design decision no image can
override. Every rate saving in this lesson comes from letting the
factorisation depend on the image.
</KeyFact>

## The rate term is a cross-entropy

Of the four trained stages, only the third decides how large the file is. The
transforms and the quantizer settle which integers get written; the length of
the bitstream is then fixed by the probability model the encoder and decoder
agree on, because an arithmetic coder reaches the expected code length of
whatever distribution it is handed and no better
(<Ref lesson="arithmetic-coding"/>). File size is decided before the coder
runs. Call that model the *entropy model* $p_{\hat y}$, and call the
distribution the latents actually follow the *marginal* $m$. The two are
different objects: $m$ is whatever the analysis transform produces on real
photographs, and nobody knows it; $p_{\hat y}$ is a parametric density that
gets fitted.

The rate is then the cross-entropy of one against the other:

$$
R = \mathbb{E}_{\hat y \sim m}\bigl[-\log_2 p_{\hat y}(\hat y)\bigr]
  = H(m) + D\bigl(m \,\|\, p_{\hat y}\bigr) \quad \text{bits.}
$$

Nothing here is new. It is the identity of <Ref lesson="cross-entropy-loss"/>,
with the classifier's predicted label distribution replaced by a density over
integer latents, in the same units. The consequence is the one
<Ref lesson="kl-divergence"/> established: the entropy model's error is not a
figure of merit reported at the end of training, it is bytes on disk.

<Example title="what a mediocre entropy model costs">
Take one latent channel whose quantised values are mostly zero. Suppose the
true marginal is

$$
m = \{\,0: 0.60,\ \pm 1: 0.15 \text{ each},\ \pm 2: 0.05 \text{ each}\,\},
$$

and the entropy model, fitted a little too wide, is
$p = \{\,0: 0.40,\ \pm 1: 0.20,\ \pm 2: 0.10\,\}$.

The ideal cost is
$H(m) = 0.6(0.737) + 0.3(2.737) + 0.1(4.322) = 1.695$ bits per coefficient.
The actual cost is
$H(m, p) = 0.6(1.322) + 0.3(2.322) + 0.1(3.322) = 1.822$ bits.

The gap is $D(m \,\|\, p) = 1.822 - 1.695 = 0.126$ bits per coefficient. At
$0.75$ coefficients per pixel that is $0.095$ bits per pixel of file paid for
nothing: on a $768 \times 512$ photograph, about $4.7$ kilobytes.
</Example>

<Exercise>
Refit the entropy model in the other direction: $p' = \{\,0: 0.80,\
\pm 1: 0.08,\ \pm 2: 0.02\,\}$, against the same marginal $m$. Compute
$D(m \,\|\, p')$, compare it with the $0.126$ bits of the example, and state
which kind of mis-specification is the expensive one and why. Write down the
per-symbol log-ratios before opening the solution.

<Solution>
**Strategy.** The lengths change but $H(m)$ does not, so the divergence is the
new cross-entropy minus the same $1.695$ bits.

The model's lengths are $-\log_2 0.80 = 0.322$, $-\log_2 0.08 = 3.644$ and
$-\log_2 0.02 = 5.644$ bits. So

$$
H(m, p') = 0.6(0.322) + 0.3(3.644) + 0.1(5.644) = 1.851 \text{ bits},
$$

and $D(m \,\|\, p') = 1.851 - 1.695 = 0.156$ bits per coefficient, against
$0.126$ for the too-wide model. In bits per pixel: $0.117$ against $0.095$.

**Which direction is expensive.** The too-wide model is wrong everywhere by a
bounded amount: it overcharges the common value by $0.59$ bits and refunds
$0.42$ and $1.00$ bits in the tails, and its total mistake stays under a fifth
of a bit. The too-narrow model concentrates its mass on the value that is
already cheap and starves the tails, and a starved tail is charged
$\log_2 (1/p')$, which grows without bound as $p'$ falls. Halving $p'(\pm 2)$
again to $0.01$ would add another $0.1$ bits per coefficient on its own. This
is the asymmetry of <Ref lesson="kl-divergence"/> in its operational form: an
entropy model may be vague at no great cost and may not be confidently wrong.
</Solution>
</Exercise>

<KeyFact>
$R$ is an expectation under a distribution nobody has. The number reported
during training is $\mathbb{E}[-\log_2 p_{\hat y}]$ estimated on training
images; on a photograph from elsewhere the real file is larger, by exactly the
divergence between that photograph's latent statistics and the model, and that
divergence is never measured.
</KeyFact>

## Rounding has no gradient: the noise relaxation

The objective is $L = R + \lambda D$, and both terms are computed downstream of
the quantizer. That is fatal for training as stated: rounding is a step
function, its derivative is zero almost everywhere and undefined at the steps,
so no gradient reaches the analysis transform's parameters $\phi$. The
encoder would never learn anything.

The repair is to replace the quantizer during training with a perturbation of
comparable size that has a usable derivative. Rounding
to the nearest integer perturbs a value by an amount in $(-\tfrac12,
\tfrac12)$. So during training the codec adds a sample of exactly that:

$$
\tilde y_i = y_i + u_i, \qquad u_i \sim \mathcal{U}\bigl(-\tfrac12,
\tfrac12\bigr),
$$

independently per coefficient, and uses $\tilde y$ everywhere $\hat y$ would
appear. The perturbation does not depend on $y$, so $\partial \tilde y /
\partial y = 1$ and gradients pass straight through.

### One density serves both regimes

The substitution buys a second property that matters more than the gradient.
Under the relaxation the entropy model is a continuous density
$p_{\tilde y}$, and it is deliberately built as a base density $p^{*}$
convolved with a uniform of unit width. Evaluate that convolution at an
integer $k$ and what comes out is the base density's mass on
$[k - \tfrac12, k + \tfrac12]$, which is precisely the probability that
rounding produces $k$:

$$
p_{\hat y}(k) = p_{\tilde y}(k)
= \int_{k - 1/2}^{k + 1/2} p^{*}(t)\,\mathrm{d}t .
$$

The trained continuous model therefore *is* the deployed discrete model, read
at the integers. No separate probability table is fitted for the shipped
coder, and no mismatch is introduced between what was optimised and what the
arithmetic coder is handed.

<Task>

The relaxation is a real departure and the paper treats it as one. Training
minimises the loss of a codec that adds noise; deployment runs a codec that
rounds. The two agree on the entropy model by construction, and they do not
agree on the reconstruction: rounding is a worse perturbation than noise for
some latents and better for others, and nothing guarantees the trained optimum
is the deployed optimum.

<Aside>
The rate under the relaxation is a *differential* cross-entropy, an integral
against a density, while the deployed rate is a discrete one, a sum against a
probability mass function. These are not the same kind of object; a
differential entropy can be negative and has no interpretation as a count of
bits. They agree here because the noise is exactly one quantisation bin wide,
which makes the density piecewise close to constant over each bin, and the
predecessor paper verified the agreement empirically rather than proving it.
For a latent whose scale is much smaller than the bin, the approximation is
poor in both directions, which is one reason the trained models keep their
latents at scales comparable with 1.
</Aside>

## One objective, two derivations

Two literatures wrote down this loss independently and they are the same
expression. <Ref lesson="rate-distortion"/> reached
$R + \lambda D$ by taking the convex curve $R(D)$ and replacing its hard
fidelity budget with a price: each point of the curve solves an unconstrained
minimisation with $\lambda = -R'(D)$. Variational autoencoders reached it from
Bayes' rule, with no compression in view. The two meet exactly.

### The variational route

A variational autoencoder posits a generative model $p(x \mid z) p(z)$ and an
approximate inference model $q(z \mid x)$, and fits $q$ by pushing it toward
the true posterior. Kingma and Welling's first equation is the decomposition
that makes this tractable:
$\log p(x) = D\bigl(q(z\mid x) \,\|\, p(z \mid x)\bigr) + \mathcal{L}$, where
$\mathcal{L}$ is the evidence lower bound; since $\log p(x)$ does not involve
the fitted parameters, minimising the divergence to the posterior is
maximising $\mathcal{L}$. Their third equation splits $\mathcal{L}$ into a
reconstruction term and a divergence from the approximate posterior to the
prior.

Now make the codec's three choices: $q$ is the uniform noise, the prior is the
entropy model, and the likelihood is Gaussian around the decoder's output.

<Theorem title="the variational bound is the Lagrangian (Ballé et al. 2018, eq. 3)">
Let $y = g_a(x; \phi)$, let $q(\tilde y \mid x) = \prod_i
\mathcal{U}\bigl(\tilde y_i \mid y_i - \tfrac12,\, y_i + \tfrac12\bigr)$, let
the prior be a density $p_{\tilde y}$, and let the likelihood be
$p(x \mid \tilde y) = \mathcal{N}\bigl(x \mid g_s(\tilde y; \theta),\,
(2\lambda)^{-1} I\bigr)$. Then

$$
\mathbb{E}_{x \sim p_x}\, D\bigl(q(\tilde y \mid x) \,\|\,
p(\tilde y \mid x)\bigr)
\;=\; \underbrace{\mathbb{E}_{\tilde y \sim m}\bigl[-\log p_{\tilde y}(\tilde
y)\bigr]}_{R}
\;+\; \lambda \underbrace{\mathbb{E}\bigl[\lVert x - \tilde x
\rVert^2\bigr]}_{D}
\;+\; \text{const},
$$

where $m(\tilde y) = \mathbb{E}_{x}\, q(\tilde y \mid x)$ is the marginal of
the latents, $\tilde x = g_s(\tilde y; \theta)$, and the constant involves
neither $\phi$ nor $\theta$. Units are nats; dividing throughout by $\ln 2$
puts $R$ in bits.

<Proof>
Four steps: expand the divergence with Bayes' rule, kill the encoder's own
term, identify the likelihood term as squared error, identify the prior term
as the rate.

**Step 1, expand.** Bayes' rule gives $p(\tilde y \mid x) =
p(x \mid \tilde y)\, p_{\tilde y}(\tilde y) / p_x(x)$, so

$$
D\bigl(q \,\|\, p(\cdot \mid x)\bigr)
= \mathbb{E}_{\tilde y \sim q}\bigl[\log q(\tilde y \mid x)
- \log p(x \mid \tilde y) - \log p_{\tilde y}(\tilde y)\bigr]
+ \log p_x(x).
$$

Averaging over $x$ makes the last term $\mathbb{E}_x[\log p_x(x)]$, a property
of the source alone. That is the constant.

**Step 2, the encoder term is zero.** $q(\tilde y \mid x)$ is a product of
uniform densities of width exactly $1$, so its value is $1$ everywhere on its
support and $\log q = 0$ there. Hence $\mathbb{E}_{q}[\log q] = 0$, exactly
and not approximately. This is the step that the choice of unit-width noise
buys, and it is why the objective has two terms rather than three.

**Step 3, the likelihood term.** For
$\mathcal{N}\bigl(x \mid \tilde x, (2\lambda)^{-1} I\bigr)$ in $d$ dimensions,

$$
-\log p(x \mid \tilde y) = \lambda \lVert x - \tilde x \rVert^2
+ \tfrac{d}{2}\log \tfrac{\pi}{\lambda},
$$

whose second term is fixed once $\lambda$ is. So the middle term contributes
$\lambda$ times the expected squared error, up to a constant.

**Step 4, the prior term.** Averaging $\mathbb{E}_{\tilde y \sim q(\cdot \mid
x)}\bigl[-\log p_{\tilde y}(\tilde y)\bigr]$ over $x \sim p_x$ replaces the
per-image conditional by its mixture, which is the definition of $m$. The
result is $\mathbb{E}_{\tilde y \sim m}[-\log p_{\tilde y}(\tilde y)]$, the
cross-entropy of the entropy model against the true latent distribution: the
rate.

Collecting steps 2 to 4 gives $0 + \lambda D + R$ plus constants.
</Proof>
</Theorem>

### The rate the codec pays, against the rate the theory allows

Nothing in the theorem says the codec attains $R(D)$. It says the loss is the
Lagrangian. The gap has three named parts, and each is non-negative.

The encoder is deterministic, so $\hat y$ is a function of $x$ and
$I(X; \hat Y) = H(\hat Y)$; the file the coder writes is longer than that by
the entropy model's mismatch. The reconstruction is a function of $\hat y$, so
the data-processing inequality (<Ref lesson="data-processing-inequality"/>)
gives $I(X; \hat X) \le I(X; \hat Y)$. And $R(D)$ is the minimum of
$I(X;\hat X)$ over *all* conditional distributions meeting the distortion
budget, of which this codec's is one. Chaining these:

$$
R \;=\; \underbrace{R(D)}_{\text{the limit}}
\;+\; \underbrace{I(X;\hat X) - R(D)}_{\text{transform and quantizer}}
\;+\; \underbrace{H(\hat Y) - I(X;\hat X)}_{\text{bits the decoder cannot use}}
\;+\; \underbrace{D(m \,\|\, p_{\hat y})}_{\text{entropy model}} .
$$

<KeyFact>
Every engineering decision in a learned codec attacks one of those three
gaps and none of them attacks $R(D)$. Better transforms shrink the first,
better architectures the second, better entropy models the third; the limit
itself is fixed by the source and the distortion measure before any network
exists.
</KeyFact>

The correspondence with <Ref lesson="information-bottleneck"/> is now exact
rather than suggestive. That lesson derived a trainable loss consisting of a
decoder's cross-entropy plus a divergence from the encoder's output
distribution to a reference marginal, and observed that setting the target
equal to the input itself turns it into a variational autoencoder's objective.
This codec is that special case with a price attached: the target is the image,
and $\lambda$ is the multiplier that the bottleneck called $\beta$.

## The hyperprior: leftover structure has a price

A factorised entropy model treats every latent coefficient as independent of
every other. That is a modelling choice, and $R = H(m) + D(m \,\|\, p_{\hat
y})$ says what a wrong choice costs. The question is whether it is wrong.

### The structure is visible

It is wrong, and the failure is spatial. Rendering the latents of a trained
factorised-prior model as an image leaves the scene readable: large responses
cluster along edges and inside textured regions, near-zero responses
elsewhere. A factorised model cannot represent that: it assigns each
coefficient the same distribution wherever it sits, so it must be too wide in
the flat regions and too narrow at the edges, and it pays on both.

### JPEG's fixed blocks, HEVC's transmitted partition

Conventional codecs solved this problem decades ago and gave the solution a
name. JPEG factorises its entropy model into fixed groups of 64 coefficients,
one per $8 \times 8$ block, and cannot change that for any image. HEVC, the
video standard behind the still-image format BPG, partitions each frame into
blocks of *variable* size, sends the partition to the decoder before the
coefficients, and then codes the coefficients under a model chosen by that
partition. The extra bits describing the partition are called **side
information**, and the trade is explicit: they are worth sending if they save
more than they cost.

The hyperprior is that trade, learned. A second analysis transform $h_a$ reads
the latents $y$ and produces a second, much smaller latent $z$; $z$ is
quantised, entropy coded under its own factorised model, and written to the
file first. A second synthesis transform $h_s$ turns the decoded $\hat z$ into
a field of scales $\hat\sigma$, one per coefficient of $\hat y$, and the
entropy model for $\hat y$ becomes a zero-mean Gaussian of standard deviation
$\hat\sigma_i$ at coefficient $i$, convolved with the unit uniform as before.
The decoder reads $\hat z$, computes $\hat\sigma$, and only then has the
probabilities it needs to decode $\hat y$.

  caption="The codec is this course's contents page: a test channel, a fidelity price, an entropy model, an arithmetic coder, and a side channel that prices the rest."

The scales are not a refinement of the reconstruction. They change no pixel.
They change only the code lengths, and through them the file size.

<Remark title="a hyperprior is a side channel, not a belief">
The word "prior" is misleading here. In Bayesian usage a prior is a
distribution fixed before the data arrive; this one is computed *from* the
image being compressed and transmitted alongside it. Its content is the
sentence "for this photograph, the coefficient at this position has roughly
this magnitude", and its cost is charged to the same budget as the latents.
The name comes from the variational formalism, in which $\hat z$ sits above
$\hat y$ in the generative model, and not from any epistemic claim.
</Remark>

The model of $\hat z$ is itself fully factorised, so the same mismatch
reappears one level up, on a quantity a few per cent the size of the one below
it. Nothing in the construction is a solution in principle; it is a hierarchy
that is one level deeper than the previous one.

## The measurement: under four per cent of the file

Side information is only a good trade if it is cheap, and the paper measures
how cheap.

### What the side channel costs

On the 24 photographs of the Kodak test set, with the hyperprior model trained
for squared error, the bits spent on $\hat z$ grow with the total rate and
stay small in absolute terms throughout: about $0.008$ bits per pixel when the
file is $0.2$ bits per pixel in total, and about $0.025$ bits per pixel when
the file is $1.7$. As a fraction the side channel is dearest where the file is
smallest, and it never exceeds four per cent of it.

Under squared error the hyperprior comes close enough to BPG to change the

hundredths the side channel costs at that rate: a return near ten to one, and
the only thing that changed between the two models is the entropy model.

The bottom panel measures the same reconstructions with MS-SSIM, a perceptual

It reverses the ranking. The models trained on that index sit above every

codec, then the best published result on the index and a considerably more
complex system, and the hyperprior is above it at every rate. JPEG and BPG,
both built around squared error, fall to the bottom. The two panels order the
same codecs differently, and the next section takes that apart.

<KeyFact>
Those bits carry nothing about the image: $\hat z$ is computed from $\hat y$,
so it says only what the latents already say. They pay because the entropy
model is restricted, and only for that reason. Against an unrestricted joint
model over the latents, transmitting $\hat z$ first and coding $\hat y$
conditionally would cost exactly what coding $\hat y$ directly costs — no
saving and no loss.
</KeyFact>

## The distortion measure decides which details survive

Every number so far was reported against a distortion measure that somebody
chose. <Ref lesson="rate-distortion"/> flagged the choice as an unresolved
input to the theory and left it abstract. Here it is concrete, because a
codec trained under one measure and a codec trained under another produce
visibly different photographs at the same file size.

The comparison is a single frame of a propeller aircraft over grass,
compressed twice by the same architecture. The model trained on MS-SSIM, an
index built to track human contrast perception, produces $0.1864$ bits per
pixel at PSNR $27.99$ dB and MS-SSIM $0.9803$. The model trained on squared
error produces $0.1932$ bits per pixel at PSNR $32.26$ dB and MS-SSIM
$0.9713$. The rates differ by under four per cent. Each metric prefers the
model trained on it, by $4.3$ dB on PSNR and by $1.6$ dB when the MS-SSIM
values are put on the same logarithmic scale.

The difference is not overall sharpness. It is where the detail went. MS-SSIM
attenuates error in high-contrast regions and boosts it in low-contrast ones,
because that is how human contrast sensitivity behaves. Trained on it, the
codec spends bits on the grass and takes them from the lettering on the
fuselage. Trained on squared error, it does the reverse. Both photographs cost
the same to store, and the text is readable in only one of them.

### The claim to reject

A distortion number ranks reconstructions only with respect to the measure it
was computed with. The reading in circulation is different: that the
MS-SSIM-trained model, having a PSNR $4.3$ dB below its sibling, is the worse
codec.

That does not follow, and the reason is structural rather than a matter of
degree. The two models were given different objectives and each attained its
own; comparing them on one objective measures which model was told to optimise
that objective, and the answer is known in advance from the training
configuration. The comparison has no information in it.

What the numbers do support is narrower. Each model is better than the other
*under its own measure*, at essentially equal rate, so neither measure is a
proxy for the other and the pair of them does not determine a ranking. The
question "which codec is better" is a question about which errors a viewer
minds, and that is settled by human rating experiments, not by either index.
The paper's own conclusion is that no single metric should be used to compare
methods, and its evidence is the photograph: the metric that scores higher
deleted the text.

<KeyFact>
Neither PSNR nor MS-SSIM models image semantics, so both are indifferent to
whether the destroyed detail was a blade of grass or a word. A distortion
measure is a specification of what may be thrown away, written before the
codec exists, and every reconstruction is an obedient answer to it.
</KeyFact>

## What the objective never charges

Three departures from the idealisation have been named: the trained codec is
not the deployed one, the entropy model is factorised at every level, and the
distortion measure is stipulated. Two more are accounting failures rather than
approximations, and both were raised earlier in the course.

### The decoder is free

The rate reported is the length of the bitstream. It excludes the synthesis
transform, its trained weights, and the hyperprior's decoder, all of which the
receiver must already have. That is defensible for a codec shipped once and
used on millions of images, and it is exactly the accounting question
<Ref lesson="minimum-description-length"/> made precise: a two-part code pays
$L(H) + L(D \mid H)$, and a headline rate that reports only $L(D \mid H)$ is
comparing a model plus data against data alone. The same omission reversed a
ranking in <Ref lesson="language-models-as-compressors"/>, where charging a
language model its own parameter bits moved it below general-purpose
compressors on a single file. Here the network is fixed and small against any
realistic image corpus, so the adjustment is real but does not change the
verdict; a codec trained per image would be a different case entirely.

### R(D) is a limit for a source that does not exist here

The rate-distortion function is defined for a known distribution and attained
in the limit of long blocks. Neither condition holds. There is no distribution
of natural images, only a training set scraped from the web and a test set of
24 photographs, so $R(D)$ for this problem is not a number anybody can write
down; and the codec operates on one finite image at a time, with a transform
whose receptive field is bounded. The Lagrangian is being minimised over a
parametric family against an empirical average. Its optimum is a point on some
curve; whether that curve is near $R(D)$ is unknown and unmeasurable.

The paper reports that end-to-end optimisation does not produce independent
latents. One would expect it to: a transform free to choose its own
representation, trained under a factorised prior, has every incentive to
factorise what it emits, which would make the entropy model's assumption
harmless. Significant dependencies between neighbouring latent elements remain
anyway, and the authors attribute this to the objective: as $\lambda$ grows
the rate term
matters less relative to distortion, so the pressure toward a factorised
representation weakens. Rate-distortion optimality does not imply an
independent representation, which is why there is work left for a hyperprior
to do.

<KeyFact>
Both failures are in the accounting, not in the codec. The decoder's own bits
are omitted from a quantity that is otherwise a two-part code, and the limit
the objective is named after is undefined for the source it is trained on. A
reported rate-distortion point is therefore a measurement of one system, not a
distance from an optimum.
</KeyFact>

## ★ What came next

This codec is the paper that made the structure legible, not the state of the
art. Its immediate successor kept the hyperprior and added an autoregressive
context model: an entropy model for each latent conditioned on the latents
already decoded around it, in raster order, which is a second attack on the
same factorisation. Combining the two made it the first learned method to beat
BPG on both PSNR and MS-SSIM, with bitstreams about $8.4\%$ smaller than
BPG's. The cost is that decoding becomes serial, one coefficient at a time,
which is why the split between what a context model buys and what it costs in
latency has occupied the field since. None of that changes the objective; all
of it is a better $p_{\hat y}$.

## The chain, end to end

What is established: a learned codec is transform coding with all four stages
trained against $L = R + \lambda D$; its rate term is a cross-entropy, so the
entropy model's error is file size and nothing else; that objective is exactly
an autoencoder's variational bound under two stated assumptions about the
noise and the likelihood; a hyperprior transmits per-coefficient scales for
under four per cent of the file and prices every other bit with
them; and the distortion measure chosen before training decides which details
survive it. Read the loss backwards and it is this course.

A probability distribution gives every outcome a surprisal $-\log_2 p$
(<Ref lesson="what-is-surprise"/>), and averaging surprisal over a source
gives its entropy (<Ref lesson="entropy-as-average-surprise"/>). Codeword
lengths spend a budget of fixed size, which turns entropy from a description
of uncertainty into the exact floor on expected length
(<Ref lesson="kraft-inequality"/>, <Ref lesson="source-coding-theorem-lite"/>).
An arithmetic coder spends fractional bits, so any probability model whatsoever
becomes a file of the length that model predicts
(<Ref lesson="arithmetic-coding"/>). Using the wrong model costs a divergence
(<Ref lesson="kl-divergence"/>), which is the same quantity as a classifier's
loss above its floor (<Ref lesson="cross-entropy-loss"/>). Dropping the demand
for exact reconstruction turns the floor into the curve $R(D)$, and pricing
the fidelity budget instead of fixing it gives $R + \lambda D$
(<Ref lesson="rate-distortion"/>).

That expression is the codec's training loss. $R$ is a cross-entropy in bits,
$D$ is an expectation of a chosen distortion, $\lambda$ is the negated slope of
a curve nobody can compute, and the whole thing is minimised by gradient
descent because rounding was replaced with noise. Every symbol in it was
defined in this course, and the system is what happens when all of them are
differentiable at once.

<Exercise>
Push the price to both ends of its range. In $L = R + \lambda D$, describe the
codec produced by $\lambda \to 0$ and the codec produced by
$\lambda \to \infty$. For the first, state what the trained analysis transform
converges to and what the decoder emits. For the second, explain why the rate
does not converge to a finite value even though the quantizer's step size is
fixed at $1$.

<Solution>
**$\lambda \to 0$: rate only.** The distortion term vanishes from the
objective, so the minimiser is any configuration with $R = 0$. A rate of zero
means the entropy model assigns probability $1$ to a single value of $\hat y$,
which forces the analysis transform to map every image into the same
quantisation bin: it converges to a constant function, and its output carries
no information about $x$. The decoder then emits one fixed image for every
input, and the best fixed image under squared error is the mean image of the
training distribution. This is the zero-rate end of the $R(D)$ curve
(<Ref lesson="rate-distortion"/>), where $D$ equals the source's variance.

**$\lambda \to \infty$: distortion only.** The quantizer always rounds to the
nearest integer, so it would seem the finest achievable reconstruction is
fixed. It is not, because the analysis transform's scale is free. Multiplying
$g_a$ by $c$ and $g_s$ by $1/c$ leaves the reconstruction unchanged in the
absence of quantisation and makes the rounding error $1/c$ times as large
after it: the effective step size in image space is $1/c$, and $c$ is a
trainable gain. As $\lambda$ grows, training raises $c$, distortion falls
toward zero and the latents spread over more and more integers, so their
entropy and the rate both diverge. Distortion buys rate at the standard
exchange rate: doubling $c$ costs about one bit per coefficient and quarters
the squared error, which is the $6$ dB per bit rule of
<Ref lesson="rate-distortion"/>.

**The transferable move.** $\lambda$ has units of bits per unit of distortion,
so a codec with a fixed quantiser step and a free transform gain has exactly
one degree of freedom, and $\lambda$ sets it.
</Solution>
</Exercise>

<Exercise>
Redo the theorem's proof under two changed hypotheses, one at a time. Write
$n$ for the number of latent coefficients and $d$ for the number of image
pixels.

**(a) Noise of the wrong width.** Keep every hypothesis except the noise: let
$q(\tilde y \mid x) = \prod_i \mathcal{U}\bigl(\tilde y_i \mid y_i - \tfrac
w2,\, y_i + \tfrac w2\bigr)$ for a fixed $w \neq 1$. Recompute Step 2 and write
the loss Steps 1–4 now produce. Then substitute $\tilde y' = \tilde y / w$ and
show the extra term is exactly what that rescaling produces — so state what $w$
is a reparameterisation of, and what the deployed codec, whose quantizer still
rounds to the nearest integer, is handed at the integers.

**(b) A likelihood that is not Gaussian.** Replace the likelihood with a
Laplacian, $p(x \mid \tilde y) = \prod_{j=1}^{d} \tfrac{1}{2b} \exp\bigl(-\lvert
x_j - \tilde x_j \rvert / b\bigr)$. Redo Step 3 and state what the multiplier
multiplies now.

<Solution>
**(a) Step 2 with width $w$.** Each factor of $q$ is a uniform density of
height $1/w$ on its support, so $\log q = -n \log w$ there and
$\mathbb{E}_q[\log q] = -n \log w$ — a constant, but not zero. Steps 1, 3 and 4
are untouched, so the loss is

$$
L_w = R_w + \lambda D - n \log w + \text{const}, \qquad
R_w = \mathbb{E}_{\tilde y \sim m}\bigl[-\log p_{\tilde y}(\tilde y)\bigr].
$$

**What the extra term is.** Put $\tilde y' = \tilde y / w$, whose noise is
unit-width by construction. Coefficient by coefficient the densities are
related by $p_{\tilde y_i}(\tilde y_i) = w^{-1} p_{\tilde y_i'}(\tilde y_i')$,
so $-\log p_{\tilde y_i} = \log w - \log p_{\tilde y_i'}$, and summing over the
$n$ coefficients gives $R_w = n \log w + R'$ with $R'$ the rate of the rescaled
system. The $-n \log w$ in the loss cancels that term exactly. Taking
$g_s'(\tilde y') = g_s(w \tilde y')$ leaves the reconstruction and $D$
unchanged. So training with width $w$ and transform $g_a$ is the same
optimisation as training with unit width and transform $g_a / w$: $w$ is not a
new hypothesis but the encoder's gain under another name, and the trained
optimum is unchanged.

**What it costs at deployment.** The shipped quantizer still rounds to the
nearest integer, step $1$. Under width $w$ the trained prior evaluated at an
integer $k$ is the base density's mass on $[k - \tfrac w2, k + \tfrac w2]$,
which is not $P[\hat y = k]$; those numbers sum to $w$ over the integers rather
than to $1$, so they are not a distribution the arithmetic coder can use. The
relaxation matches the deployment only when the noise width equals the
quantizer step, and Step 2's exact zero is that same fact written in algebra.

**(b) Step 3 with a Laplacian.** Taking logs,

$$
-\log p(x \mid \tilde y) = \frac{1}{b} \lVert x - \tilde x \rVert_1
+ d \log 2b,
$$

whose second term is fixed once $b$ is. Steps 1, 2 and 4 do not involve the
likelihood, so with $\lambda = 1/b$ the objective is
$R + \lambda\, \mathbb{E}\bigl[\lVert x - \tilde x \rVert_1\bigr]$ plus
constants: the same Lagrangian, with $\lambda$ now pricing mean *absolute*
error.

**The transferable move.** Any likelihood of the form $p(x \mid \tilde y)
\propto \exp\bigl(-\lambda\, \rho(x, \tilde x)\bigr)$ with a normaliser that
does not depend on $\phi$ or $\theta$ gives $R + \lambda \mathbb{E}[\rho]$.
Choosing the distortion measure and choosing the likelihood are the same act,
which is why the choice cannot be postponed to evaluation time —
the point the section on metrics makes with photographs.
</Solution>
</Exercise>

<Exercise>
Break this claim. "The codec minimises rate plus $\lambda$ times distortion,
which is the Lagrangian form of $R(D)$, so a converged model achieves $R(D)$
for natural images." Give three distinct reasons the conclusion does not
follow: one about the source, one about the training relaxation, and one about
the entropy model. For each, say whether it makes the codec's rate too high,
its distortion too high, or the comparison undefined.

<Solution>
**The source.** $R(D)$ is defined relative to a known distribution $p_X$ and
attained asymptotically in blocklength. There is no known distribution of
natural images; there is a scrape of about a million web photographs used for
training and 24 photographs used for testing. So $R(D)$ for this problem is
not a computable quantity, and the claim compares the codec against a number
that does not exist. **Comparison undefined.**

**The relaxation.** Training minimises the loss of a system that adds uniform
noise; the shipped system rounds. The trained parameters are optimal for the
relaxed objective, and there is no theorem placing them at the optimum of the
deployed one. **Both terms possibly too high**, since the mismatch can move
either the rate or the distortion.

**The entropy model.** The rate paid is the cross-entropy
$H(m) + D(m \,\|\, p_{\hat y})$, and the divergence is zero only if the model
equals the true latent marginal. It does not: the model is factorised
conditional on the scales, while the latents retain dependencies, and the
hyperprior's own model is factorised outright. **Rate too high**, by exactly
the divergence.

A fourth reason is available from the section on the three gaps: even with a
perfect entropy model, the family of conditionals realisable as "round the
output of this convolutional network" is a strict subfamily of the
conditionals over which $R(D)$ minimises, so $I(X;\hat X)$ exceeds $R(D)$
before any modelling error is counted.
</Solution>
</Exercise>

<Exercise>
Break this claim too. "The MS-SSIM-trained model scores $27.99$ dB PSNR

<Exercise>
Derive the accounting the lesson asserted. Write $\hat y$ for the latents and
$\hat z = h_a(\hat y)$ for the hyperprior's latent, so $\hat z$ is a
deterministic function of $\hat y$. (a) Show that with an *unrestricted*
entropy model, transmitting $\hat z$ first and coding $\hat y$ conditionally
costs exactly as much as coding $\hat y$ directly, so the side channel cannot
help. (b) With *factorised* entropy models on both, write the saving and the
cost as information quantities and explain how the saving can exceed the cost
by a large factor even though part (a) says it cannot in the unrestricted
case.

<Solution>
**(a) Unrestricted models.** The two-stage scheme costs
$H(\hat Z) + H(\hat Y \mid \hat Z)$ bits, which is $H(\hat Y, \hat Z)$ by the
chain rule (<Ref lesson="joint-and-conditional-entropy"/>). Since
$\hat Z = h_a(\hat Y)$, knowing $\hat Y$ determines $\hat Z$, so
$H(\hat Z \mid \hat Y) = 0$ and $H(\hat Y, \hat Z) = H(\hat Y)$. The two-stage
cost equals the direct cost exactly. Side information computed from the data
is free and useless when the entropy model is unrestricted, which is why the
hyperprior is not a statement about information at all.

**(b) Factorised models.** With a factorised model the direct cost is
$\sum_i H(\hat Y_i)$, not $H(\hat Y)$, and the conditional cost is
$\sum_i H(\hat Y_i \mid \hat Z)$. So

$$
\text{saving} = \sum_i \bigl[H(\hat Y_i) - H(\hat Y_i \mid \hat Z)\bigr]
= \sum_i I(\hat Y_i ; \hat Z),
\qquad
\text{cost} = H(\hat Z).
$$

The saving is a sum of $n$ marginal mutual informations, one per coefficient,
and the cost is a single entropy. Part (a) bounds only the *joint* quantity:
$I(\hat Y; \hat Z) = H(\hat Z)$, and $\sum_i I(\hat Y_i; \hat Z)$ can exceed
$I(\hat Y;\hat Z)$ without limit, because the same side bits are counted once
in every coefficient they help.

Break-even is a unit conversion: the cost is quoted per pixel and the saving
accrues per coefficient. Near $1$ bit per pixel the side channel
costs about $0.02$ bits per pixel, which at $0.75$ coefficients per pixel is
$0.027$ bits per coefficient; the hyperprior pays only if the average marginal
saving $I(\hat Y_i ; \hat Z)$ exceeds that. The measured curves say it does by
about a factor of ten: at matched distortion the scales buy some $0.2$ bits
per pixel there, or $0.27$ bits per coefficient.

**The transferable move.** Sums of marginal mutual informations are not
bounded by the joint one. That inequality is the entire economic case for side
information in every codec that uses it, and it exists only because the
entropy models are restricted.
</Solution>
</Exercise>

<Exercise>
Close the account. (a) A codec's entropy model $p_{\hat y}$ is fitted once and
shipped. You encode a set of images whose quantised latents follow an
empirical distribution $\hat m$ different from the one the model was fitted
on. Write down the extra bits per image the mismatch costs, in the notation of
the divergence module, given $n$ coefficients per image. (b) Name, for each of
the three symbols in $L = R + \lambda D$, the single lesson of this course

honest total for a set of $N$ images and say at what $N$ the omission stops
mattering.

<Solution>
**(a)** Coding data distributed as $\hat m$ with a code built for $p_{\hat y}$

The excess over the best code for these images is the divergence alone, so the

$$
n \, D\bigl(\hat m \,\|\, p_{\hat y}\bigr) \text{ bits per image.}

With $n = 294{,}912$ and a divergence of $0.01$ bits per coefficient, that is

**(b)** $R$ is an expected code length under a model, defined as a

<Ref lesson="rate-distortion"/>, which is also where $\lambda$ was introduced,
as the negated slope $-R'(D)$ of the rate-distortion curve.

**(c)** The honest total for $N$ images is a two-part code
(<Ref lesson="minimum-description-length"/>):

$$
L_{\text{total}} = \underbrace{L(\text{decoder weights})}_{\text{once}}
+ \sum_{j=1}^{N} \bigl[R_j + L(\hat z_j)\bigr],
$$

and the per-image average carries $L(\text{weights}) / N$. A codec of this
size has on the order of ten million weights; at $16$ bits each that is over
$10^8$ bits, against a compressed photograph of roughly $10^5$ bits, so the
amortised cost falls below one per cent of a file only past about
$N = 10^5$ images. Below that
the shipped codec is not cheaper than a general-purpose one, which is the
finding that reversed the ranking in
<Ref lesson="language-models-as-compressors"/>. The course ends on the open
version of that question: a codec whose decoder is retrained per image or per
corpus is a model selection problem, and the criterion is the total length,
not the rate.
</Solution>

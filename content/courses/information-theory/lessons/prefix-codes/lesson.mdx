A yes/no question strategy over a finite outcome set and a binary prefix
code are the same object: each outcome sits at a leaf of a decision tree,
and its depth is the length of its codeword.

Everything the course has established so far attaches a number to a
distribution and stops there: surprisal to one event, entropy to a source,
and an entropy rate near one bit per letter to English against the eight bits
ASCII spends on it (<Ref lesson="entropy-of-english"/>). Nothing so far
connects any of those numbers to a bit that is actually stored or sent. This
module makes the connection, and it runs through codeword lengths: they spend
a budget of fixed size, which turns entropy from a summary of uncertainty
into the exact floor on expected bits per symbol. This lesson supplies the
object the rest of the module reasons about, the binary code tree, and the
cost function that ranks one code against another.

The route: a question strategy for a concrete four-outcome source, its
reading as a code, the prefix condition that makes concatenated codewords
decodable without separators, the expected length $L$ that ranks codes, an
exchange argument constraining which outcome gets which length, and the
entropy floor $H(X) \le L$ whose proof arrives in
<Ref lesson="source-coding-theorem-lite"/>. One question the lesson raises
and cannot answer is which sets of lengths are available at all;
<Ref lesson="kraft-inequality"/> settles that.

## A question strategy is a binary tree

The running source, used from here through
<Ref lesson="huffman-by-hand"/>: one draw from four outcomes with

$$
p(A) = 0.5, \qquad p(B) = 0.25, \qquad p(C) = 0.15, \qquad p(D) = 0.1.
$$

The task is to identify the draw by asking yes/no questions, using as few
questions as possible **on average** over many draws. A strategy is
committed before the draw: which question comes first, and which question
follows each possible answer. Later questions may depend on earlier
answers; a *binary tree* records exactly that dependence. Each internal node
is a question, its two children are the two answers, and each outcome sits
at the leaf its answer path leads to.

Fixing the strategy in advance is what makes the tree a well-defined object
rather than a description of one interrogation. The questioner may not look
at the draw and then decide what to ask.

### Three questions for four outcomes

One strategy: ask "Is it $A$?" first, since $A$ alone carries half the
probability. On "yes" the draw is identified after one question. On "no",
ask "Is it $B$?"; on a second "no", a final "Is it $C$?" separates $C$
from $D$.

### The average number of questions

The number of questions spent on a draw is the depth of its leaf. The
average cost of the strategy weights each depth by its outcome's
probability, the same weighting that defined entropy in
<Ref lesson="entropy-as-average-surprise"/>:

$$
.5 \cdot 1 + .25 \cdot 2 + .15 \cdot 3 + .1 \cdot 3 = 1.75
\text{ questions per draw.}
$$

Half of all draws end after a single question, which is what pulls the
average below 2 despite two outcomes sitting at depth 3. Two questions is
what a strategy that ignores the probabilities costs: split the four
outcomes two against two, then split each pair, and every draw takes exactly
two questions. The skewed tree beats it by a quarter of a question per draw
only because the draws are themselves skewed.

## Answers are bits: the strategy is a code

The tree was built to count questions. Recording the answers turns the same
tree into a way of writing outcomes down. Record each answer as one bit,
**yes = 1** and **no = 0**. A draw of $C$ produces the transcript no, no,
yes: the string `001`. Every outcome gets the binary string of answers
along its root-to-leaf path:

| outcome | $p$ | transcript | codeword | length |
| --- | --- | --- | --- | --- |
| $A$ | $.5$ | yes | `1` | 1 |
| $B$ | $.25$ | no, yes | `01` | 2 |
| $C$ | $.15$ | no, no, yes | `001` | 3 |
| $D$ | $.1$ | no, no, no | `000` | 3 |

The tree read this way is a *code tree*: each branch carries a bit, each
leaf carries a codeword, and **depth equals codeword length**. Asking one
question and reading one bit are the same act.

<Definition title="binary symbol code">
A **binary symbol code** for a finite outcome set $\mathcal{X}$ is a map
$C$ assigning each outcome $x \in \mathcal{X}$ a finite binary string
$C(x)$, its **codeword**, of length $\ell(x)$. A sequence of outcomes is
encoded by concatenating the codewords, with no separators.
</Definition>

Concatenation is where variable lengths pay off. The five-symbol message
$A\,B\,A\,A\,C$ encodes as

$$
\underbrace{1}_{A}\,\underbrace{01}_{B}\,\underbrace{1}_{A}\,
\underbrace{1}_{A}\,\underbrace{001}_{C} \;=\; \texttt{10111001},
$$

8 bits. A fixed-length code for four outcomes spends 2 bits per symbol
($\log_2 4 = 2$, the entropy ceiling of
<Ref lesson="entropy-as-average-surprise"/>), hence 10 bits on the same
message. The saving comes from giving the frequent outcome $A$ a 1-bit
codeword and paying 3 bits only for the rare $C$ and $D$.

<KeyFact>
Nothing in the correspondence requires a question to be about a single
outcome. Any yes/no question is a node, so a code tree can name blocks of
symbols as readily as symbols, which is the move that closes the one-bit
gap in <Ref lesson="source-coding-theorem-lite"/>.
</KeyFact>

## The prefix condition: outcomes at leaves only

The tree above has a structural property that decides whether the
concatenation just written can be read back: outcomes sit only at **leaves**.
Breaking that property breaks decoding.

### A broken tree and an ambiguous stream

Move $B$ from its leaf onto the internal node with path `01`, and hang
$C$ and $D$ below it at `011` and `010`, keeping $A$ at `1`. The
codewords become $\{A \mapsto \texttt{1},\; B \mapsto \texttt{01},\;
C \mapsto \texttt{011},\; D \mapsto \texttt{010}\}$. Now $B$'s codeword
`01` is a *prefix* of $C$'s codeword `011`, and the stream `011` has two
valid parses:

$$
\texttt{011} = \underbrace{\texttt{011}}_{C}
\quad\text{or}\quad
\texttt{011} = \underbrace{\texttt{01}}_{B}\,\underbrace{\texttt{1}}_{A}.
$$

A receiver holding `011` cannot decide between "one draw, $C$" and "two
draws, $B$ then $A$", and no amount of further reading settles it. In
tree terms: after the answers no, yes the receiver stands on $B$'s node
but cannot tell whether the walk has ended (emit $B$) or continues into
$B$'s subtree.

<Definition title="prefix code">
A binary symbol code is a **prefix code** (also *prefix-free code* or
*instantaneous code*) if no codeword is a prefix of another codeword.
Equivalently: in the code tree, every codeword sits at a leaf, and no
codeword lies on the path to another.
</Definition>

### Four codes against the definition

The definition has one clause, so the way to learn its boundary is to run
codes past it. All four below are codes for the same four outcomes.

- **The canonical case.** $\{\texttt{1}, \texttt{01}, \texttt{001},
  \texttt{000}\}$, the question tree: four leaves, no codeword on the path
  to another. Prefix.
- **A different surface, same structure.** The fixed-length code
  $\{\texttt{00}, \texttt{01}, \texttt{10}, \texttt{11}\}$ has no branching
  to look at and every codeword the same length, yet the clause holds
  vacuously: equal-length distinct strings cannot be prefixes of each other.
  Every fixed-length code is a prefix code.
- **A degenerate case that still qualifies.** $\{\texttt{1}, \texttt{01},
  \texttt{001}, \texttt{0001}\}$ is prefix-free with a wasted leaf: the node
  `0000` carries no outcome, so a decoder reading `0000` runs off the code.
  The definition says nothing about waste, and the code is legal;
  <Ref lesson="kraft-inequality"/> measures exactly what the waste costs.
- **The near miss.** $\{\texttt{1}, \texttt{01}, \texttt{011},
  \texttt{010}\}$, the broken tree above, violates the single clause once:
  `01` is a prefix of `011`. Every other pair is fine, and one violation is
  enough.

### Decoding a prefix stream: walk, emit, reset

Prefix codes decode a concatenated stream with no separators and no
lookahead: start at the root, follow one branch per bit, and the moment a
leaf is reached, emit its outcome and jump back to the root. Because no
codeword continues past a leaf, the walk never faces the ambiguity above:
each codeword is recognized the instant its last bit arrives, which is
what *instantaneous* means.

<Example title="decoding a concatenated stream">
Decode the stream `000011001` under the code
$\{A \mapsto \texttt{1}, B \mapsto \texttt{01}, C \mapsto \texttt{001},
D \mapsto \texttt{000}\}$.

Walk from the root, one bit per step:

1. `0`, `0`, `0`: three "no" branches reach the leaf $D$. Emit $D$,
   return to the root.
2. `0`, `1`: reaches the leaf $B$. Emit $B$, reset.
3. `1`: reaches the leaf $A$ in one step. Emit $A$, reset.
4. `0`, `0`, `1`: reaches the leaf $C$. Emit $C$.

The stream parses uniquely as `000`&#8203;`01`&#8203;`1`&#8203;`001`
$= D\,B\,A\,C$, nine bits, four symbols, no separators consumed.
</Example>

<Exercise>
Run the encoder rather than the decoder. Encode the message $C\,A\,D\,B$
with the same code, count the bits, and compare against the 8 bits a
fixed-length code spends on four symbols. Then decode your own bit string to
check it, and account for the comparison in one sentence.

<Solution>
Encoding concatenates `001`, `1`, `000`, `01`, giving `001100001`: **nine
bits**, one more than the fixed-length code's eight.

Decoding it back: `001` reaches $C$ (emit at bit 3), `1` reaches $A$ (bit 4),
`000` reaches $D$ (bit 7), `01` reaches $B$ (bit 9). The message returns
intact.

The variable-length code loses on this particular message because the
message is unrepresentative of the source: it contains one $C$ and one $D$,
outcomes that together carry only a quarter of the probability but two of
the four symbols here. Over draws from the actual source the code spends
$1.75$ bits per symbol, so a four-symbol message costs $7$ bits on average.
A code is a bet on the distribution, and it can lose an individual hand.
</Solution>
</Exercise>

<KeyFact>
The prefix condition is sufficient for unique decodability and not necessary:
codes that violate it can still be decodable, at the price of lookahead. The
restriction is nevertheless free, because
<Ref lesson="kraft-inequality"/> shows every length set achievable by any
uniquely decodable code is achievable by a prefix code.
</KeyFact>

## Expected length: the cost of a code

The prefix condition says which codes are legal. It says nothing about which
legal code to pick, and the running source admits many. Two of them are worth
comparing directly, both decodable without separators. The *balanced code*
assigns $\{A \mapsto \texttt{11}, B \mapsto \texttt{10}, C \mapsto
\texttt{01}, D \mapsto \texttt{00}\}$: a complete depth-2 tree, every
codeword of length 2. The *matched code* is the question tree built above,
lengths $(1, 2, 3, 3)$ tracking the probabilities $(.5, .25, .15, .1)$ in
decreasing order.

<Example title="expected length of two codes">
Balanced code: every outcome costs 2 bits, so the average is

$$
.5 \cdot 2 + .25 \cdot 2 + .15 \cdot 2 + .1 \cdot 2 = 2.00 \text{ bits.}
$$

Matched code: the tally from the question tree,

$$
.5 \cdot 1 + .25 \cdot 2 + .15 \cdot 3 + .1 \cdot 3
= .5 + .5 + .45 + .3 = 1.75 \text{ bits.}
$$

The matched code saves $0.25$ bits per symbol: $A$'s saved bit, weighted
by $p(A) = .5$, outweighs the extra bit each spent on $C$ and $D$,
weighted by only $.15 + .1 = .25$. Over a megabyte of symbols from this
source that is a quarter of a million bits, about 31 kB.
</Example>

<Definition title="expected codeword length">
The **expected length** of a code $C$ for a source $X$ with distribution
$p$ is
$$
L(C) = \sum_x p(x)\, \ell(x),
$$
the probability-weighted average of the codeword lengths, in bits per
symbol. Source coding seeks the prefix code minimizing $L(C)$.
</Definition>

### Lengths and the distribution are all that matter

$L(C)$ depends on the code only through its lengths $\ell(x)$, and on the
source only through $p$. Two consequences:

- **Bit labels are free.** Swapping the two children of any node
  (relabeling yes and no) permutes the codewords but changes no length,
  so $L$ is unchanged. The matched code with root labels swapped,
  $\{A \mapsto \texttt{0}, B \mapsto \texttt{11}, C \mapsto \texttt{101},
  D \mapsto \texttt{100}\}$, is equally good. What a code commits to is
  its multiset of lengths.
- **$L$ averages over the distribution, not over the leaves.** The
  matched code wins on this source, but on the uniform distribution
  $(.25, .25, .25, .25)$ its expected length is
  $.25(1 + 2 + 3 + 3) = 2.25$ bits, and the balanced code's $2.00$ wins.
  Neither tree is better in itself; a code is good only relative to a
  distribution.

<KeyFact>
A code is a bet on a distribution, and the balanced tree is the bet that
every outcome is equally likely. Coding data from $p$ with a code built for
$q$ costs a quantity with a name and a formula, the divergence of
<Ref lesson="kl-divergence"/>.
</KeyFact>

## More probable outcomes get shorter codewords

Because $L$ depends only on the lengths and on $p$, choosing a code splits
into two questions: which multiset of lengths to use, and which outcome gets
which length. The second question has a complete answer, and it comes from
swapping two codewords and watching $L$ move.

<Example title="one swap, 0.70 bits">
Assign the running source's codewords carelessly: give the depth-1 leaf to
$C$ and a depth-3 leaf to $A$, keeping the same tree shape. The code is
$\{C \mapsto \texttt{1}, B \mapsto \texttt{01}, A \mapsto \texttt{001},
D \mapsto \texttt{000}\}$, still prefix-free, with

$$
L = .5 \cdot 3 + .25 \cdot 2 + .15 \cdot 1 + .1 \cdot 3 = 2.45 \text{ bits,}
$$

worse than the balanced code. Now trade the codewords of $A$ and $C$,
changing nothing else. $A$'s length drops from 3 to 1 and $C$'s rises from 1
to 3, and

$$
L' - L = \bigl(p(A) - p(C)\bigr)\bigl(\ell(C) - \ell(A)\bigr)
       = (.5 - .15)(1 - 3) = -0.70 \text{ bits,}
$$

taking $L$ from $2.45$ down to $1.75$. The multiset of codewords is
unchanged by a trade, so the new code is prefix-free exactly as the old one
was.
</Example>

The arithmetic in that example used no property of the particular numbers.

<Theorem title="probability order forces length order">
Let $C$ be a prefix code of minimum expected length for a source with
$p(x) > 0$ for every outcome. If $p(x) > p(y)$ then $\ell(x) \le \ell(y)$.

<Proof>
Direct, by exhibiting a better code whenever the conclusion fails.

Suppose $p(x) > p(y)$ and $\ell(x) > \ell(y)$. Build $C'$ from $C$ by giving
$x$ the codeword $C(y)$ and $y$ the codeword $C(x)$, leaving every other
outcome alone. The set of strings used is the same set, so no new prefix
relations appear and $C'$ is a prefix code.

Only two terms of the sum $\sum_z p(z)\ell(z)$ change, so

$$
L(C') - L(C) = \bigl(p(x)\ell(y) + p(y)\ell(x)\bigr)
             - \bigl(p(x)\ell(x) + p(y)\ell(y)\bigr)
             = \bigl(p(x) - p(y)\bigr)\bigl(\ell(y) - \ell(x)\bigr).
$$

The first factor is positive by assumption and the second is negative, so
$L(C') < L(C)$, contradicting the minimality of $C$. Hence $\ell(x) > \ell(y)$
is impossible and $\ell(x) \le \ell(y)$.
</Proof>
</Theorem>

The statement is an inequality in one direction only. Equal lengths for
outcomes of different probability are permitted, and often forced: on
$(.5, .25, .15, .1)$ the optimal code gives $C$ and $D$ the same length 3
even though $p(C) > p(D)$.

<KeyFact>
The two-line computation uses nothing about bits: it swaps two terms of a
weighted sum. The same ordering therefore holds for codes over any alphabet
size and for any cost of the form
$\sum_x p(x) \cdot (\text{price of } x)$. Sorting is the easy half of code
design; the multiset of lengths is the hard half.
</KeyFact>

<Exercise>
A prefix code for $\{V: .4,\, W: .3,\, X: .2,\, Y: .1\}$ is proposed:
$V \mapsto \texttt{110}$, $W \mapsto \texttt{0}$, $X \mapsto \texttt{111}$,
$Y \mapsto \texttt{10}$. Compute $L$. Then find every pair the theorem
convicts, apply the trades, and report the expected length of the repaired
code. Write down each trade's predicted change before computing the new $L$.

<Solution>
Lengths are $\ell(V) = 3$, $\ell(W) = 1$, $\ell(X) = 3$, $\ell(Y) = 2$, so

$$
L = .4 \cdot 3 + .3 \cdot 1 + .2 \cdot 3 + .1 \cdot 2
  = 1.2 + .3 + .6 + .2 = 2.3 \text{ bits.}
$$

**Convicted pairs.** The theorem is violated whenever a more probable
outcome carries a longer codeword. Three pairs qualify: $(V, W)$ with
$.4 > .3$ and $3 > 1$; $(V, Y)$ with $.4 > .1$ and $3 > 2$; $(X, Y)$ with
$.2 > .1$ and $3 > 2$.

**Trade 1, $V$ against $W$.** Predicted change
$(.4 - .3)(1 - 3) = -0.2$ bits. After it, $V \mapsto \texttt{0}$ and
$W \mapsto \texttt{110}$, and $L = 2.1$. This clears both convictions
involving $V$ at once, and leaves $(W, Y)$ newly convicted alongside
$(X, Y)$.

**Trade 2, $W$ against $Y$.** Predicted change $(.3 - .1)(2 - 3) = -0.2$
bits. After it, $W \mapsto \texttt{10}$ and $Y \mapsto \texttt{110}$, and
$L = 1.9$. Now $X$ and $Y$ both have length 3, so the remaining pair is
acquitted: the theorem permits equal lengths for unequal probabilities.

**Check.** The final code is $V \mapsto \texttt{0}$, $W \mapsto \texttt{10}$,
$X \mapsto \texttt{111}$, $Y \mapsto \texttt{110}$, with lengths
$1, 2, 3, 3$ against probabilities $.4, .3, .2, .1$ in decreasing order:
$$
L = .4 \cdot 1 + .3 \cdot 2 + .2 \cdot 3 + .1 \cdot 3 = 1.9 \text{ bits.}
$$
The two trades removed $0.4$ bits in total, matching $2.3 - 1.9$.

The transferable move: trades never change the multiset of lengths, so they
can only reshuffle which outcome pays which cost. Sorting probabilities
against lengths is free; finding the right multiset of lengths is the hard
part, and it is what <Ref lesson="huffman-by-hand"/> does.
</Solution>
</Exercise>

## Split the mass, not the outcome count

Sorting fixes the assignment once the lengths are known. Building a good
tree in the first place is a question about the first split, and the choice
of first question sets the cost of the whole strategy. Two candidates split
the running source very differently:

- "Is it $D$?" isolates the **rarest** outcome: mass split $.1$ versus
  $.9$. The frequent draws all take the "no" branch, and everything
  popular still needs separating afterwards. Completing this tree as well
  as possible (ask "Is it $A$?" next, then "Is it $B$?") gives lengths
  $1, 2, 3, 3$ against the probabilities $.1, .5, .25, .15$: an expected
  $.1 \cdot 1 + .5 \cdot 2 + .25 \cdot 3 + .15 \cdot 3 = 2.30$ bits.
- "Is it $A$?" splits the mass $.5$ versus $.5$ and yields the matched
  code's $1.75$.

### One bit per question at most

The binary entropy function of
<Ref lesson="entropy-as-average-surprise"/> says why balance wins. The
answer to a question is a two-outcome random variable; if "yes" has
probability $q$, the answer carries entropy $H(q) \le 1$ bit, with
equality exactly at $q = \tfrac12$. The answer to "Is it $D$?" is a
90/10 coin, $H(0.1) \approx 0.469$ bits: the question spends a full
question-slot to learn less than half a bit. "Is it $A$?" is a fair coin
and delivers the full bit.

Splitting the number of outcomes in half is not the target. "Is it $A$ or
$B$?" balances the count two against two, but the mass $.75$ against
$.25$: its answer carries $H(0.75) \approx 0.811$ bits, and the strategy
it starts (two questions always) is the balanced code's $L = 2.00$.

Near-halving the mass at every node is a heuristic, not yet an algorithm.
It is also not always achievable: the mass reaching a node need not admit
any exact 50/50 split of its outcomes, and on the running source the second
question, "Is it $B$?", faces $.25$ against $.25$ of a remaining $.5$, which
is exact, while the third faces $.15$ against $.1$, which is not.
<Ref lesson="huffman-by-hand"/> gives the greedy construction that is
provably optimal without ever measuring a split.

<KeyFact>
A question delivers a full bit only when it splits the remaining mass 50/50,
so a tree can be perfect only when every probability is a power of
$\tfrac12$. Every other source pays a rounding cost, and bounding that cost
is the content of <Ref lesson="source-coding-theorem-lite"/>.
</KeyFact>

## ★ Where prefix codes sit among all codes

The prefix condition was reached from the decoding walk, which makes it look
like the definition of "decodable". It is not: it is the strictest of three
nested conditions, and the two weaker ones are worth seeing so that the cost
of the restriction is visible rather than assumed. Nothing later in the
lesson depends on this section.

A code is **nonsingular** if distinct outcomes get distinct codewords. That
is enough to describe one draw unambiguously and not enough for a stream:
with $\{\texttt{0}, \texttt{010}, \texttt{01}, \texttt{10}\}$ the string
`010` is the second codeword, or the first followed by the fourth, or the
third followed by the first.

A code is **uniquely decodable** if every stream has at most one parse. This
is strictly weaker than prefix-free. The comma code
$\{\texttt{0}, \texttt{01}, \texttt{011}, \texttt{0111}\}$ violates the
prefix condition four times over, yet every codeword begins with the only
`0` it contains, so each `0` in a stream marks the start of a new codeword
and the parse is forced. The price is delay: after reading `01` the receiver
must wait for the next `0` to learn whether the codeword has ended, whereas
a prefix code emits at the final bit of every codeword. Reversing every
codeword of a prefix code gives another uniquely decodable family with the
same lengths, and unique decodability can be arbitrarily hard to see by
inspection, which is why the Sardinas–Patterson procedure exists to decide
it mechanically.

The restriction to the innermost class costs nothing measurable.
[McMillan's theorem](https://en.wikipedia.org/wiki/Kraft%E2%80%93McMillan_inequality),
proved in <Ref lesson="kraft-inequality"/>, shows that every uniquely
decodable code obeys the same constraint on its lengths as every prefix
code, so any expected length reachable by the comma code above is reachable
by a prefix code with the same lengths and no decoding delay.

## Entropy is the floor: no code beats H

Two codes for the running source have now been priced at $2.00$ and $1.75$
bits, and a third at $2.30$. Nothing so far says how low the number can go.
The entropy of the source, by the three-step computation of
<Ref lesson="entropy-as-average-surprise"/>, gives the answer to within a
hundredth of a bit. Surprisals: $-\log_2 .5 = 1$, $-\log_2 .25 = 2$,
$-\log_2 .15 \approx 2.737$, $-\log_2 .1 \approx 3.322$; weighted,

$$
H(X) = .5 \cdot 1 + .25 \cdot 2 + .15 \cdot 2.737 + .1 \cdot 3.322
\approx 1.743 \text{ bits.}
$$

The matched code's $L = 1.75$ sits $0.007$ bits above this number, and not
below it. That is not an accident of this source.

<Theorem title="entropy bounds expected length">
For every prefix code $C$ for a source $X$,
$$
H(X) \le L(C).
$$
</Theorem>

The theorem is stated here for orientation and proved in
<Ref lesson="source-coding-theorem-lite"/>, after
<Ref lesson="kraft-inequality"/> supplies the tool. The strategy picture
makes it plausible: identifying the draw requires $H(X)$ bits on average and
each answer delivers at most one. That is a reading, not a proof, and it is
worth naming why. The reading assumes the questions can always be chosen to
deliver a full bit, which the previous section showed to be false in general.

### When the floor is hit exactly

The four-symbol source of <Ref lesson="entropy-as-average-surprise"/>
with probabilities $(\tfrac12, \tfrac14, \tfrac18, \tfrac18)$ has
$H = 1.75$ bits, and its surprisals $1, 2, 3, 3$ are integers. Assigning
each outcome a codeword of length equal to its surprisal (the matched
tree fits exactly) gives $L = 1.75 = H$: the floor is attained. On the
running distribution the surprisals $2.737$ and $3.322$ are not integers,
no codeword can be $2.737$ bits long, and the $0.007$-bit gap is the
rounding cost.

The gap on the running source is small enough to look like an artefact of
the numbers. It is not, and a second source shows it at a size that matters.

### A second source: three symbols, three codes

<Example title="three ways to code {a: .7, b: .15, c: .15} (EE376A §1.1)">
A source emits `a` with probability $.7$ and `b` and `c` with probability
$.15$ each, draws independent. Its entropy is

$$
H = .7 \log_2 \tfrac{1}{.7} + 2 \cdot .15 \log_2 \tfrac{1}{.15}
  \approx .7(0.515) + .3(2.737) \approx 1.181 \text{ bits.}
$$

**Fixed length.** Three outcomes need 2 bits each: $L = 2$ bits per symbol,
$0.82$ bits above the floor.

**Best symbol code.** Give `a` the one-bit codeword `0`, and `b`, `c` the
codewords `10` and `11`. Prefix-free, and

$$
L = .7 \cdot 1 + .15 \cdot 2 + .15 \cdot 2 = 1.3 \text{ bits per symbol,}
$$

which is $0.119$ bits above $H$. No prefix code on single symbols does
better: the only other length multisets available to three codewords are
$(2,2,2)$ at $2$ bits and $(1,2,3)$ at
$.7 + .3 + .45 = 1.45$ bits.

**Coding pairs.** Treat the source as emitting one of nine pairs, with
$p(\texttt{aa}) = .49$, four pairs at $.105$, and four at $.0225$. The best
prefix code on those nine outcomes assigns `aa` one bit, three of the
$.105$ pairs three bits, the fourth four bits, and the four rarest pairs six
bits each, for

$$
.49(1) + 3(.105)(3) + .105(4) + 4(.0225)(6) = 2.395 \text{ bits per pair,}
$$

which is $1.1975$ bits per symbol. The excess over $H$ has fallen from
$0.119$ to $0.016$ bits, a factor of seven, at the cost of a code table with
nine entries instead of three.
</Example>

<Figure
  src="./figures/blocking-ladder.svg"
  alt="Three horizontal bars of bits per symbol for the source a:.7 b:.15 c:.15 — a fixed 2-bit code at 2.00, the best symbol code at 1.30, and the best code on pairs at 1.1975 — against a dashed entropy floor at H = 1.181"
  caption="Three codes for one source against the floor: coding pairs cuts the excess over H from 0.119 to 0.016 bits per symbol."
/>

Blocking works because the whole-bit constraint is charged once per
codeword, not once per symbol: a pair code rounds nine lengths instead of
three, and each rounding error is then shared over two symbols.
<Ref lesson="source-coding-theorem-lite"/> pushes the block length to
infinity and shows the excess vanishes, which is what makes $H$ the exact
floor rather than merely a lower bound.

### What is open

Established: a code is a tree, its cost is $L = \sum_x p(x)\ell(x)$, the
prefix condition is what makes concatenated codewords readable, more
probable outcomes take shorter codewords in any optimal code, and $H(X)$ is
a floor that integer lengths generally miss.

What is not established is which multisets of lengths exist. The matched
code spends $(1, 2, 3, 3)$; the lengths $(1, 2, 2, 2)$ would give
$L = .5 + .5 + .3 + .2 = 1.5$ bits, comfortably below $H \approx 1.743$,
which the floor theorem forbids. Something must therefore rule those lengths
out, and nothing in this lesson does.
<Ref lesson="kraft-inequality"/> supplies the missing constraint, which
prices each codeword by its length and caps what a code may spend in total.
Exercise 6 computes the quantity it turns on.

## Exercises

<Exercise>
A source emits $E, F, G, H$ with probabilities $.4, .3, .2, .1$ and is coded
as $E \mapsto \texttt{0}$, $F \mapsto \texttt{10}$, $G \mapsto \texttt{110}$,
$H \mapsto \texttt{111}$. Compute $L$, then decode the stream `0110100` and
report the message.

<Solution>
Lengths $1, 2, 3, 3$, so
$$
L = .4 \cdot 1 + .3 \cdot 2 + .2 \cdot 3 + .1 \cdot 3
  = .4 + .6 + .6 + .3 = 1.9 \text{ bits per symbol.}
$$

Decoding, walking from the root and resetting at each leaf: `0` gives $E$;
`110` gives $G$; `10` gives $F$; `0` gives $E$. The message is
$E\,G\,F\,E$, seven bits for four symbols.

The code beats the fixed-length $2.00$ bits by $0.1$ bits per symbol,
which is the whole benefit available here: the source is only mildly skewed.
</Solution>
</Exercise>

<Exercise>
Push the source to the boundary the running example avoids. For a **uniform**
source over five outcomes, find the prefix code minimising $L$, report its
expected length, and explain why the answer is not $\log_2 5 \approx 2.322$
bits. Name the property of binary trees that forces the excess, and state
the sizes of alphabet for which the excess vanishes.

<Solution>
**The optimal code.** A binary tree has at most $2^d$ nodes at depth $d$, so
at most 4 outcomes can sit at depth 2 and no legal tree puts all five there.
Consider the possibilities by the shallowest leaf.

If some outcome sits at depth 1, the other four all live under the single
remaining depth-1 node, hence at depth 3 or more, giving lengths
$(1,3,3,3,3)$ and $L = (1 + 12)/5 = 2.6$ bits.

Otherwise every outcome is at depth 2 or deeper. If all four depth-2 nodes
held outcomes there would be no node left anywhere for the fifth, since
every deeper node descends from one of them, so at most $k = 3$ outcomes sit
at depth 2 and the other $5 - k$ sit at depth 3 or more. That bounds the
average below by
$$
L \ge \tfrac{1}{5}\bigl(2k + 3(5-k)\bigr) = \tfrac{15-k}{5},
$$
smallest at $k = 3$, giving $L \ge 12/5 = 2.4$ bits. The lengths
$(2,2,2,3,3)$ attain it: three depth-2 leaves, and the fourth depth-2 node
split into the two remaining leaves.

**Why not $\log_2 5$.** For a uniform source over $n$ outcomes,
$H = \log_2 n$, here $2.322$ bits. The excess is $2.4 - 2.322 = 0.078$ bits
per symbol. Every codeword length is a whole number of bits, and $\log_2 5$
is not a whole number, so no assignment can give every outcome exactly its
surprisal. The forcing property of the tree is the doubling of nodes per
level: depths available are $1, 2, 4, 8, \dots$ leaves, never $5$.

**When the excess vanishes.** Exactly when $n$ is a power of two. Then
$\log_2 n$ is an integer, the complete tree of that depth has exactly $n$
leaves, and $L = H = \log_2 n$.
</Solution>
</Exercise>

<Exercise>
Break this claim. "A code with shorter maximum codeword length always has
smaller expected length, because the longest codeword is what the code costs
in the worst case." Exhibit two prefix codes on one distribution where the
claim fails, name the step in the reasoning that is invalid, and state the
criterion the claim would be correct about.

<Solution>
**The counterexample.** On $(.5, .25, .15, .1)$, the balanced code has
maximum length 2 and $L = 2.00$ bits; the matched code has maximum length 3
and $L = 1.75$ bits. Longer maximum, smaller expected length.

**The invalid step.** The maximum length bounds $L$ from above,
$L \le \max_x \ell(x)$, and says nothing about it from below. A code may
carry one very long codeword provided the probability attached to it is
small: the matched code's two length-3 codewords are used on only a quarter
of draws, and $D$'s third bit is paid one time in ten. Expected length is a
weighted average, so a length is only as expensive as the probability
multiplying it.

**What the claim is correct about.** Maximum codeword length is the right
figure of merit for a different objective: worst-case latency, or the size
of a decoder's input buffer, or the length of the longest bit string a
hardware table must hold. A system that must guarantee a bound per symbol
rather than on average will accept a higher $L$ to lower $\max_x \ell(x)$,
which is what length-limited coding does in shipping formats.
</Solution>
</Exercise>

<Exercise>
Do a derivation the lesson skipped. Show that in a prefix code of minimum
expected length, with every $p(x) > 0$, the longest codeword is never
unique: at least two codewords have the maximum length, and two of them
differ only in their last bit. Argue on the tree, not with a formula.

<Solution>
Let $\ell_{\max}$ be the longest codeword length and let $c$ be a codeword
of that length, sitting at a leaf of depth $\ell_{\max}$. Write $s$ for its
**sibling**, the other child of $c$'s parent, also at depth $\ell_{\max}$.

**Case 1: the subtree at $s$ contains a codeword.** Any such codeword is at
depth $\ell_{\max}$ or more, and no codeword exceeds $\ell_{\max}$, so it is
$s$ itself. Then $c$ and $s$ are two maximum-length codewords differing only
in their last bit, as claimed.

**Case 2: the subtree at $s$ contains no codeword.** Then delete the last
bit of $c$, moving it up to its parent node. The result is still a prefix
code: no codeword can be a prefix of the shortened word, since such a
codeword would be an ancestor of $c$ and the original code was prefix-free;
and the shortened word is a prefix of no codeword, because the only nodes
below the parent are $c$'s old position, now vacated, and the empty subtree
at $s$. The new code has $L$ smaller by $p(c) > 0$, so the original code was
not of minimum expected length. Case 2 cannot arise.

Hence every maximum-length codeword has its sibling occupied, and there are
at least two maximum-length codewords.

The transferable move is the one the body used on the exchange argument:
assume optimality, perturb the code by one local edit, and show the edit
lowers $L$ unless the desired property already holds. Both edits here are
local, and neither needs to know anything about the rest of the tree.
</Solution>
</Exercise>

<Exercise>
A biased binary source emits `0` with probability $.9$ and `1` with
probability $.1$. Compute its entropy. Then report the expected length of
the best prefix code on single symbols, and the best on **pairs** of
symbols, in bits per symbol. Explain in one sentence why the second number
is smaller.

<Solution>
**Entropy.** Surprisals $-\log_2 .9 \approx 0.152$ and
$-\log_2 .1 \approx 3.322$ bits, weighted:
$$
H = .9(0.152) + .1(3.322) \approx 0.137 + 0.332 = 0.469 \text{ bits.}
$$

**Single symbols.** Two outcomes admit exactly one prefix code shape,
$\{\texttt{0}, \texttt{1}\}$, so $L = 1$ bit per symbol. The code cannot
respond to the bias at all, and it overspends by $0.531$ bits per symbol,
more than doubling the necessary size of the file.

**Pairs.** The four pairs have probabilities $p(\texttt{00}) = .81$,
$p(\texttt{01}) = p(\texttt{10}) = .09$, $p(\texttt{11}) = .01$. Lengths
$(1, 2, 3, 3)$ fit them in decreasing probability order:
$$
L_{\text{pair}} = .81(1) + .09(2) + .09(3) + .01(3) = 1.29 \text{ bits per pair,}
$$
that is $0.645$ bits per symbol, an excess over $H$ of $0.176$ rather than
$0.531$ bits.

**Why.** A symbol code must spend at least one whole bit on every symbol
however certain that symbol is, and pairing halves the number of whole-bit
roundings charged per symbol.
</Solution>
</Exercise>

<Exercise>
Try to build a prefix code on four outcomes with lengths $\{1, 2, 2, 2\}$.
Draw the tree, place the codewords shortest first, and report exactly where
the construction jams. Then compute $\sum_x 2^{-\ell(x)}$ for that length
set and for the matched code's $\{1, 2, 3, 3\}$, and say what distinguishes
the two numbers.

<Solution>
**The jam.** Place the length-1 codeword first, say `1`. The prefix
condition then forbids every string beginning with `1`, so `10` and `11`
are unusable and the three length-2 codewords must all come from the
subtree under `0`. That subtree has exactly two nodes at depth 2, `00` and
`01`. Two of the three fit; the third has nowhere to go. Starting with `0`
instead is the same situation with the labels swapped, so no ordering of
placements rescues it: the lengths $\{1,2,2,2\}$ are not realisable by any
prefix code, binary trees or not.

**The sums.**
$$
\{1,2,2,2\}:\quad 2^{-1} + 3 \cdot 2^{-2} = .5 + .75 = 1.25,
$$
$$
\{1,2,3,3\}:\quad 2^{-1} + 2^{-2} + 2 \cdot 2^{-3} = .5 + .25 + .25 = 1.00.
$$

**What distinguishes them.** The realisable set sums to exactly $1$; the
impossible one exceeds $1$. Each codeword behaves like a claim on a fixed
budget of size one, a codeword of length $\ell$ costing $2^{-\ell}$, and the
length-1 codeword alone consumes half the budget, which is why one short
codeword makes so many others impossible.

That budget is the subject of <Ref lesson="kraft-inequality"/>, which proves
that the sum computed here decides realisability for every set of lengths,
in both directions.
</Solution>
</Exercise>

No lossless code achieves fewer expected bits per symbol than the source
entropy. This lesson gives the argument.

The course's argument has reached the point where entropy stops being a
measure of uncertainty and becomes a measurement of cost. <Ref
lesson="prefix-codes"/> showed that a code's cost depends only on its
multiset of codeword lengths, <Ref lesson="kraft-inequality"/> showed which
multisets exist, and <Ref lesson="huffman-by-hand"/> found the cheapest one
and observed that it lands within one bit of the entropy. What stands open
is whether that agreement is a property of Huffman's algorithm or a law
about every possible code, and whether the leftover bit is a defect that can
be removed. This lesson answers both: the floor $L \ge H$ binds every
lossless code, and the leftover bit is an artifact of coding one symbol at a
time. With that, the theoretical half of the coding module closes;
<Ref lesson="arithmetic-coding"/> opens the practical half by building a
coder that spends fractions of a bit.

The route: every prefix code implicitly bets on a distribution
$q(x) = 2^{-\ell(x)}$; the expected length decomposes as
$L = H(p) + D(p\,\|\,q) + \text{slack}$ with every term non-negative, which
proves the floor; the Shannon code $\ell(x) = \lceil -\log_2 p(x) \rceil$
lands within one bit of the floor; block coding shrinks the remaining
per-symbol overhead to at most $1/n$; and the typical set explains why $nH$
bits is the right total for $n$ symbols.

## A code is a bet: lengths are probabilities

<Ref lesson="kraft-inequality"/> priced a codeword of length $\ell$ at
$2^{-\ell}$ of a budget of one, and its closing remark observed that for a
complete code the claims $2^{-\ell_i}$ are positive and sum to exactly 1:
formally a probability distribution. That observation now carries weight.

### The claims of the matched code, read as a distribution

The matched code for the running source, $A \mapsto \texttt{1}$,
$B \mapsto \texttt{01}$, $C \mapsto \texttt{001}$, $D \mapsto \texttt{000}$,
has lengths $(1, 2, 3, 3)$ and claims

$$
q = \bigl(\tfrac12,\ \tfrac14,\ \tfrac18,\ \tfrac18\bigr).
$$

On the dyadic source with exactly these probabilities, every codeword length
equals its symbol's surprisal and $L = H = 1.75$ bits (exercise 6 of
<Ref lesson="kraft-inequality"/>): the code is **exact** for $q$. Used on the
actual running source $p = (.5, .25, .15, .1)$, the same code acts as if $C$
occurred with probability $\tfrac18$ when it occurs with $.15$, and as if $D$
occurred with probability $\tfrac18$ when it occurs with $.1$. The code bets
on $q$; the source draws from $p$.

### The implied distribution of an arbitrary prefix code

For a code that is not complete, the claims sum to less than 1 and
normalizing them yields a distribution.

<Definition title="implied distribution of a code">
Let a prefix code have lengths $\ell(x)$ and Kraft sum
$c = \sum_x 2^{-\ell(x)} \le 1$. Its **implied distribution** is
$$
q(x) = \frac{2^{-\ell(x)}}{c},
$$
and every codeword length is a surprisal under $q$ plus a constant:
$\ell(x) = -\log_2 q(x) + \log_2 \tfrac{1}{c}$, with
$\log_2 \tfrac{1}{c} \ge 0$ by the Kraft inequality.
</Definition>

Three instances fix the boundary. Lengths $(1,2,3,3)$ give $c = 1$ and
$q = (\tfrac12, \tfrac14, \tfrac18, \tfrac18)$, the bet read off directly.
Lengths $(2,2,3,3)$ give $c = \tfrac34$ and, after normalizing,
$q = (\tfrac13, \tfrac13, \tfrac16, \tfrac16)$: a legitimate bet, but one
the code states in a wasteful currency, since $\log_2 \tfrac43 = 0.415$ bits
of every codeword buy nothing. Lengths $(1,2,2,2)$ are a near-miss: they
violate the one clause the definition rests on, $c \le 1$, since
$\tfrac12 + 3 \cdot \tfrac14 = \tfrac54$. No prefix code has them, and
correspondingly no distribution assigns total probability $\tfrac54$.

Short codewords are exactly high implied probabilities: assigning $C$ a
3-bit codeword and assigning $C$ implied probability $\tfrac18$ are the same
act.

<KeyFact>
A code can only bet on probabilities that are powers of $\tfrac12$, because
lengths are integers. Every result in this lesson, including the leftover
bit that <Ref lesson="arithmetic-coding"/> exists to recover, comes from
that restriction.
</KeyFact>

## The floor: expected length is entropy plus mismatch

The bet reading turns the gap $L - H$ into a computable quantity. The
concrete cases first.

### Two codes priced against the entropy

The running source has $H(p) \approx 1.743$ bits
(<Ref lesson="prefix-codes"/>). The balanced code (all lengths 2) costs
$L = 2.00$ bits, a gap of $0.257$; the matched code costs $1.75$, a gap of
$0.007$. Both gaps are exactly the mismatch between $p$ and each code's bet.

<Example title="the gap is a sum of betting errors">
For each code, compute $\sum_x p(x) \log_2 \tfrac{p(x)}{q(x)}$, the
probability-weighted log-ratio of truth to bet.

**Balanced code:** lengths $(2,2,2,2)$, complete, so
$q = (\tfrac14, \tfrac14, \tfrac14, \tfrac14)$. The terms:

$$
.5 \log_2 \tfrac{.5}{.25} = .5, \quad
.25 \log_2 1 = 0, \quad
.15 \log_2 \tfrac{.15}{.25} \approx -.111, \quad
.1 \log_2 \tfrac{.1}{.25} \approx -.132 .
$$

Sum: $.5 - .111 - .132 + 0 \approx 0.257$ bits: the gap $2.00 - 1.743$.

**Matched code:** $q = (\tfrac12, \tfrac14, \tfrac18, \tfrac18)$. The $A$
and $B$ terms vanish ($p = q$ there); the rest:

$$
.15 \log_2 \tfrac{.15}{.125} \approx .0395, \qquad
.1 \log_2 \tfrac{.1}{.125} \approx -.0322 .
$$

Sum: $\approx 0.007$ bits: the gap $1.75 - 1.743$.

**Bounds check:** individual terms go negative (the code over-bets on $D$),
but each total is positive and equals its code's gap exactly.
</Example>

### The decomposition: L = H + D + slack

The agreement is an identity. Take any prefix code with lengths $\ell(x)$,
Kraft sum $c$, and implied distribution $q(x) = 2^{-\ell(x)}/c$. Substituting
$\ell(x) = -\log_2 q(x) + \log_2 \tfrac1c$ into the expected length:

$$
L = \sum_x p(x)\,\ell(x)
= \underbrace{\sum_x p(x) \log_2 \tfrac{1}{p(x)}}_{H(p)}
\;+\; \underbrace{\sum_x p(x) \log_2 \tfrac{p(x)}{q(x)}}_{D(p \,\|\, q)}
\;+\; \underbrace{\log_2 \tfrac{1}{c}}_{\text{slack} \,\ge\, 0} ,
$$

where the first two terms come from adding and subtracting
$\sum_x p(x) \log_2 p(x)$ inside the sum. The middle term is the
*Kullback–Leibler divergence* $D(p\,\|\,q)$, the expected extra bits from
betting $q$ when the truth is $p$; it gets a lesson of its own
(<Ref lesson="kl-divergence"/>). The slack term prices an incomplete tree:
unclaimed budget is length wasted on no symbol. What remains to prove is
that the mismatch term is never negative.

<Theorem title="Gibbs' inequality">
For probability distributions $p$ and $q$ on a finite set,
$$
D(p \,\|\, q) = \sum_x p(x) \log_2 \frac{p(x)}{q(x)} \;\ge\; 0,
$$
with equality if and only if $p = q$.

<Proof>
If $q(x) = 0$ for some $x$ with $p(x) > 0$, the sum is $+\infty$ and the
inequality holds. Otherwise use $\ln t \le t - 1$, an inequality valid for
all $t > 0$ with equality only at $t = 1$ (the graph of $\ln$ lies below its
tangent at 1). Applied to $t = q(x)/p(x)$ inside the sum:

$$
-D(p\,\|\,q) \cdot \ln 2
= \sum_{x:\,p(x)>0} p(x) \ln \frac{q(x)}{p(x)}
\;\le\; \sum_{x:\,p(x)>0} p(x)\!\left(\frac{q(x)}{p(x)} - 1\right)
= \sum_{x:\,p(x)>0} q(x) \;-\; 1 \;\le\; 0 .
$$

Hence $D(p\,\|\,q) \ge 0$. Equality forces $q(x)/p(x) = 1$ wherever
$p(x) > 0$ and $\sum_{x:\,p(x)>0} q(x) = 1$, i.e. $q = p$.
</Proof>
</Theorem>

### The theorem: no code beats the entropy

<Theorem title="entropy floor">
Every uniquely decodable code for a source $X$ with distribution $p$
satisfies
$$
L \;\ge\; H(X),
$$
with equality if and only if $\ell(x) = -\log_2 p(x)$ for every outcome:
a complete code on a dyadic distribution.

<Proof>
By McMillan's theorem (<Ref lesson="kraft-inequality"/>), the lengths of any
uniquely decodable code satisfy $c = \sum_x 2^{-\ell(x)} \le 1$, so the
implied distribution $q$ and the decomposition above apply:

$$
L = H(p) + D(p \,\|\, q) + \log_2 \tfrac{1}{c} .
$$

Gibbs' inequality gives $D(p\,\|\,q) \ge 0$, and $c \le 1$ gives
$\log_2 \tfrac1c \ge 0$; hence $L \ge H(p)$. Equality requires both
$q = p$ and $c = 1$, which together say $2^{-\ell(x)} = p(x)$, i.e.
$\ell(x) = -\log_2 p(x)$: every probability a power of $\tfrac12$, every
length its symbol's surprisal.
</Proof>
</Theorem>

This settles the bound that <Ref lesson="prefix-codes"/> stated without
proof and <Ref lesson="huffman-by-hand"/> used as the lower half of its
guarantee. The proof also says where a code's cost goes: the entropy is the
part no code avoids, the mismatch $D$ is the price of betting on the wrong
distribution, and the slack is the price of wasting tree.

<KeyFact>
The equality condition is severe: the floor is attained only when every
probability is a power of $\tfrac12$. For every other source, including
almost every real one, $L > H$ strictly at one symbol per codeword, and the
rest of this lesson is about how far above the floor a code is forced to
sit.
</KeyFact>

## Achievability: rounding surprisals up costs less than a bit

The floor is approachable from above. The equality condition says lengths
should be $\ell(x) = -\log_2 p(x)$; when the surprisals are not integers,
round them up:

$$
\ell(x) = \lceil -\log_2 p(x) \rceil .
$$

This is the *Shannon code*: the ceiling-length witness that
<Ref lesson="huffman-by-hand"/> built to prove its one-bit guarantee, now
under its proper name. Since $2^{-\lceil -\log_2 p(x) \rceil} \le p(x)$, the
Kraft sum is at most $\sum_x p(x) = 1$ and the lengths are achievable; since
each length overshoots its surprisal by less than one bit, $L < H(p) + 1$.
On the running source the Shannon lengths are $(1, 2, 3, 4)$, costing
$L = 1.85$ bits: the rounding gaps $(0, 0, 0.263, 0.678)$, weighted by $p$,
add the $0.107$ bits above $H \approx 1.743$.

  caption="The Shannon code rounds each surprisal up to an integer length. Every gap is below 1 bit, so L = 1.85 < H + 1."

Huffman coding can only improve on this witness, which yields the two-sided
guarantee proved in <Ref lesson="huffman-by-hand"/>: the optimal symbol code
satisfies $H(X) \le L^* < H(X) + 1$.

<KeyFact>
The guarantee is one bit in absolute terms and worthless in relative terms.
A source with a symbol of probability $1 - 10^{-6}$ has
$H \approx 2.1 \cdot 10^{-5}$ bits, and any symbol code still spends a full
bit on it: 47,000 times the entropy, inside the same $H + 1$ promise
(exercise 2).
</KeyFact>

## Blocks: the overhead is per block, not per symbol

The remaining defect is the one <Ref lesson="huffman-by-hand"/> ended on:
the $+1$ is paid **per symbol**. The 90/10 coin has $H \approx 0.469$ bits,
yet any symbol code spends $L = 1$ bit per flip, an overhead of 113%. The
fix is to enlarge the symbol.

### A block of n symbols is one symbol with entropy nH

Treat $n$ consecutive independent draws $X_1, \dots, X_n$ as a single
super-symbol $X^n$ over the $2^n$ (in general $|\mathcal{X}|^n$) possible
blocks. Its entropy needs no new machinery: probabilities of independent
draws multiply, so surprisals add
(<Ref lesson="what-is-surprise"/>),

$$
-\log_2 p(x_1, \dots, x_n) = \sum_{i=1}^{n} -\log_2 p(x_i),
$$

and taking expectations term by term gives $H(X^n) = n\,H(X)$.

<Theorem title="block coding bound">
For an i.i.d. source $X$ and any block length $n$, the optimal prefix code
for blocks of $n$ symbols has expected length $L_n$ satisfying
$$
H(X) \;\le\; \frac{L_n}{n} \;<\; H(X) + \frac{1}{n} .
$$

<Proof>
Apply the entropy floor and the Shannon-code bound to the super-symbol
source $X^n$: $H(X^n) \le L_n < H(X^n) + 1$. Substitute
$H(X^n) = nH(X)$ and divide by $n$.
</Proof>
</Theorem>

The up-to-one-bit rounding cost is now paid once per **block**: at most
$1/n$ bits per symbol, squeezed toward zero by growing $n$.

</Aside>

### The price of the fix: an alphabet of size |X|ⁿ

Blocking buys $1/n$ with a code table of $|\mathcal{X}|^n$ entries, and that
exponent is not a footnote. On the 90/10 coin, $n = 8$ already means 256
codewords for a two-outcome source. On bytes, where $|\mathcal{X}| = 256$,
blocking two symbols gives 65,536 codewords, blocking four gives $4.3$
billion, and blocking eight gives $256^8 = 2^{64}$: one table entry for every
distinct 64-bit integer. The table must also be built from
block probabilities, held in memory, and either transmitted or recomputed by
the decoder.

So the theorem's construction is asymptotically right and practically
unusable past small $n$, and the two lessons that follow are the two escapes.
<Ref lesson="arithmetic-coding"/> keeps the block idea and drops the table by
coding the whole message as one interval; <Ref lesson="dictionary-coding"/>
drops the requirement that the distribution be known at all.

<KeyFact>
The exchange rate of block coding is $1/n$ bits of overhead for
$|\mathcal{X}|^n$ table entries: exponential cost for linear benefit, which
is why the theorem is proved with blocks and no deployed compressor uses
them.
</KeyFact>

## The typical set: where the probability concentrates

The block bound proves that $nH$ bits per block suffice; it does not say
what those bits are naming. The answer is a small subset of the $2^n$
sequences, and it is the structural reason block coding works. It returns
for channel coding in <Ref lesson="noisy-channel-coding"/>, where the same
counting argument is run on pairs of sequences.

### One hundred flips of the 90/10 coin

A block of $n = 100$ flips has $2^{100}$ possible outcomes. They are far
from equally likely:

- The single most probable sequence, all heads, has surprisal
  $100 \cdot 0.152 = 15.2$ bits: probability $2^{-15.2}$, about
  $2.7 \cdot 10^{-5}$.
- A sequence with the *expected* composition, 90 heads and 10 tails, has
  surprisal $90 \cdot 0.152 + 10 \cdot 3.322 = 46.9$ bits, exactly
  $nH$. There are $\binom{100}{10} \approx 2^{44}$ such sequences.
- The all-tails sequence has surprisal $100 \cdot 3.322 = 332$ bits:
  probability $\approx 10^{-100}$, an event that never occurs.

The draws that actually occur crowd around the expected composition, not
around the most probable sequence.

### Most probable is not typical

The natural expectation is that a compressor should reserve its short
codewords for the most probable sequences, and that the set carrying almost
all the probability is the set of the likeliest members. The arithmetic goes
the other way. All-heads is the most probable sequence of the $2^{100}$,
more likely than any 90-heads sequence by a factor of $2^{31.7}$, and it is
*atypical*: its per-symbol surprisal is $0.152$ bits against an entropy of
$0.469$. It still contributes only $0.0027\%$ of the probability, because
there is exactly one of it, while the band around the entropy holds roughly
$2^{53}$ far less probable members and collects $76\%$ of all draws at
$n = 100$.

### Near-average surprisal defines the set

The engine is the
[law of large numbers](https://en.wikipedia.org/wiki/Law_of_large_numbers)
applied to surprisals: the per-symbol surprisal of a block,
$-\tfrac1n \log_2 p(X^n) = \tfrac1n \sum_i \bigl(-\log_2 p(X_i)\bigr)$, is
an average of $n$ independent draws of a quantity whose mean is $H(X)$, so
it concentrates near $H(X)$ as $n$ grows.

<Definition title="typical set">
For an i.i.d. source $X$ and tolerance $\varepsilon > 0$, the **typical
set** $T_\varepsilon^{(n)}$ is the set of length-$n$ sequences whose
per-symbol surprisal is within $\varepsilon$ of the entropy:
$$
T_\varepsilon^{(n)} = \Bigl\{ x^n :
\Bigl| -\tfrac{1}{n} \log_2 p(x^n) - H(X) \Bigr| \le \varepsilon \Bigr\}.
$$
Equivalently, each member has probability between $2^{-n(H+\varepsilon)}$
and $2^{-n(H-\varepsilon)}$: typical sequences are near-equiprobable.
</Definition>

### The AEP, proved from the law of large numbers

<Theorem title="asymptotic equipartition property">
Let $X_1, X_2, \dots$ be i.i.d. draws from $p$ on a finite alphabet, with
entropy $H = H(X)$. For every $\varepsilon > 0$:

1. $\Pr\bigl(X^n \in T_\varepsilon^{(n)}\bigr) \to 1$ as $n \to \infty$.
2. $\bigl|T_\varepsilon^{(n)}\bigr| \le 2^{\,n(H+\varepsilon)}$ for every
   $n$.
3. $\bigl|T_\varepsilon^{(n)}\bigr| \ge (1-\delta)\,2^{\,n(H-\varepsilon)}$
   for every $\delta > 0$ and all $n$ large enough.

<Proof>
Write $Z_i = -\log_2 p(X_i)$. These are i.i.d., with mean
$\mathbb{E}[Z_i] = \sum_x p(x)\log_2 \tfrac{1}{p(x)} = H$ and, on a finite
alphabet with no zero-probability symbol, finite variance
$\sigma^2 = \operatorname{Var}(Z_i)$, since $Z_i$ takes finitely many
values.

**(1) Concentration.** Membership of $T_\varepsilon^{(n)}$ is the event
$\bigl|\bar{Z}_n - H\bigr| \le \varepsilon$ for the sample mean
$\bar{Z}_n = \tfrac1n\sum_i Z_i$, because
$\bar{Z}_n = -\tfrac1n \log_2 p(X^n)$ by additivity of surprisal over
independent draws. Chebyshev's inequality applied to $\bar{Z}_n$, whose
variance is $\sigma^2/n$, gives
$$
\Pr\bigl(X^n \notin T_\varepsilon^{(n)}\bigr)
= \Pr\bigl(|\bar{Z}_n - H| > \varepsilon\bigr)
\;\le\; \frac{\sigma^2}{n\,\varepsilon^2},
$$
which tends to 0. This is the weak law of large numbers with its rate made
explicit.

**(2) Upper bound on the size.** Every member has probability at least
$2^{-n(H+\varepsilon)}$, and the members are disjoint events inside a
probability space:
$$
1 \;\ge\; \Pr\bigl(X^n \in T_\varepsilon^{(n)}\bigr)
= \!\!\sum_{x^n \in T_\varepsilon^{(n)}}\!\! p(x^n)
\;\ge\; \bigl|T_\varepsilon^{(n)}\bigr| \, 2^{-n(H+\varepsilon)} ,
$$
so $\bigl|T_\varepsilon^{(n)}\bigr| \le 2^{n(H+\varepsilon)}$.

**(3) Lower bound on the size.** By (1), choose $n$ large enough that
$\Pr\bigl(X^n \in T_\varepsilon^{(n)}\bigr) \ge 1 - \delta$. Every member
has probability at most $2^{-n(H-\varepsilon)}$, so
$$
1 - \delta \;\le\; \!\!\sum_{x^n \in T_\varepsilon^{(n)}}\!\! p(x^n)
\;\le\; \bigl|T_\varepsilon^{(n)}\bigr| \, 2^{-n(H-\varepsilon)} ,
$$
giving $\bigl|T_\varepsilon^{(n)}\bigr| \ge (1-\delta)2^{n(H-\varepsilon)}$.
</Proof>
</Theorem>

Only step (1) is asymptotic, and Chebyshev prices it. For the 90/10 coin,
$Z$ takes the value $0.152$ with probability $.9$ and $3.322$ with
probability $.1$, so $\sigma^2 = 0.904$ bits². At $\varepsilon = 0.05$ the
bound guarantees $\Pr(\text{atypical}) \le 0.01$ only from
$n \ge 0.904/(0.01 \cdot 0.05^2) \approx 36{,}000$. Chebyshev is loose here
(the true crossing is near $n = 1{,}000$), but the shape of the guarantee is
the point: the block length needed grows with the variance of the surprisal
and with $1/\varepsilon^2$, and it does not depend on the alphabet size.

### Why nH bits is the right count, in both directions

**Sufficiency:** a block coder spends $\lceil n(H+\varepsilon) \rceil + 1$
bits to index the typical sequences, by part (2), and falls back on
$n + O(1)$ raw bits for the atypical remainder, whose probability tends to 0
by part (1); the expected cost per symbol approaches $H$. **Necessity:** any
scheme naming fewer than $2^{n(H-\varepsilon)}$ sequences must miss most of
the typical set, whose members are near-equiprobable and number at least
$(1-\delta)2^{n(H-\varepsilon)}$ by part (3), so its failure probability
tends to 1. Exercise 5 carries the necessity direction out.

The two directions are proved here for an i.i.d. source over a finite
alphabet. That is what "lite" means in this lesson's title. A source with
memory has an analogous statement with $H$ replaced by its entropy rate, the
per-symbol entropy given unbounded context that
<Ref lesson="entropy-of-english"/> measures, but its proof (the
Shannon–McMillan–Breiman theorem) needs an ergodic theorem rather than a
variance bound, and is not given here.

<KeyFact>
The AEP as proved rests on two hypotheses that later lessons remove one at a
time: independence, dropped by the entropy-rate version, and a known $p$,
dropped by the universal codes of <Ref lesson="dictionary-coding"/>, which
attain the entropy rate without ever being told the distribution.
</KeyFact>

## ★ Essential bit content: the same limit counted a second way

An alternative accounting reaches the same number without mentioning
typicality, and it answers a question the typical-set argument leaves
awkward: what if we simply take the most probable sequences, as intuition
demanded, and count them?

Fix a tolerance $\delta$ and let $S_\delta$ be the *smallest* set of
length-$N$ sequences with total probability at least $1 - \delta$: build it
by ranking sequences by decreasing probability and adding them until the
mass is reached. The **essential bit content** is
$H_\delta(X^N) = \log_2 |S_\delta|$, the number of bits needed to name a
member, and $\delta$ is the probability that the coder is handed something
it cannot name.

At $N = 1$ this quantity depends violently on $\delta$: for a source with
one dominant symbol, $\delta$ just above the second symbol's probability
collapses $H_\delta$ to 0. As $N$ grows, $\tfrac1N H_\delta(X^N)$ flattens
into a plateau at $H$ across the whole open range of $\delta$, and
Theorem 4.1 of MacKay's chapter 4 states exactly that: for any
$\varepsilon > 0$ and any $0 < \delta < 1$ there is an $N_0$ with
$\bigl|\tfrac1N H_\delta(X^N) - H\bigr| < \varepsilon$ for all $N > N_0$.

Two readings, in opposite directions, matter. Allowing any fixed failure
probability, however small, buys the full compression down to $H$ bits per
symbol. Allowing a large failure probability buys nothing further: even at
$\delta = 0.99$ the rate is still $H$. And the sets $S_\delta$ are built
from the *most probable* sequences, not from the typical ones, so the two
constructions differ in membership and agree in size to first order in the
exponent. Compression to $H$ does not depend on which of the two sets a
coder indexes.

## The source coding theorem

The pieces assemble into the module's headline result.

<Theorem title="source coding theorem">
Let $X$ be an i.i.d. source with entropy $H(X)$. Then:

1. **Converse.** Every uniquely decodable code for blocks of $n$ symbols
   has expected length per symbol at least $H(X)$.
2. **Achievability.** For every $n$ there is a prefix code for blocks of
   $n$ symbols with expected length per symbol below $H(X) + \tfrac1n$.

The infimum of achievable expected bits per symbol over all lossless codes
and all block lengths is exactly $H(X)$.

<Proof>
Both halves were proved above. The converse is the entropy floor applied to
the super-symbol source $X^n$: $L_n \ge H(X^n) = nH(X)$, using McMillan to
cover every uniquely decodable code. Achievability is the Shannon code on
blocks: $L_n < H(X^n) + 1 = nH(X) + 1$. Dividing both by $n$ gives the two
statements, and letting $n \to \infty$ closes the infimum onto $H(X)$.
</Proof>
</Theorem>

Shannon stated it in 1948 as Theorem 9, in terms of a channel of capacity
$C$ bits per second rather than bits per symbol: "it is possible to encode
the output of the source in such a way as to transmit at the average rate
$\tfrac{C}{H} - \varepsilon$ symbols per second over the channel where
$\varepsilon$ is arbitrarily small. It is not possible to transmit at an
average rate greater than $\tfrac{C}{H}$." Dividing a second's worth of
channel bits among $C/H$ symbols is $H$ bits per symbol; the $\varepsilon$
sits on the achievable side only, and the impossibility clause carries no
$\varepsilon$ at all.

   two-sentence statement quoted above (the epsilon-qualified achievable rate
   and the unqualified "It is not possible to transmit at an average rate
   greater than C/H"), so the reader sees the asymmetry between the two
   clauses in the original typography rather than in paraphrase; candidate
   amathematica-theorem9-page16 — Shannon 1948, page 16 (section 9, "The
   Fundamental Theorem for a Noiseless Channel"),
   https://people.math.harvard.edu/~ctm/home/text/others/shannon/entropy/entropy.pdf;
   placement centered */}

Entropy thereby acquires its **operational meaning**: $H(X)$ is not merely a
formula from <Ref lesson="entropy-as-average-surprise"/> but the measured
price, in bits per symbol, of transmitting the source losslessly.

### What the theorem does and does not say

Three boundaries, each load-bearing:

- **The bound is on the expectation.** Individual messages compress below
  $H$ routinely: the all-heads block of 100 flips gets a short codeword in
  any good block code. The average over the source cannot.
- **Lossless is essential.** Codes that tolerate reconstruction error can
  go below $H$; how far, as a function of the tolerated distortion, is the
  subject of <Ref lesson="rate-distortion"/>.
- **Independence is assumed.** For sources with memory (English text is
  the standing example), the floor is the *entropy rate*, the per-symbol
  entropy given unbounded context, which is lower than the single-symbol
  $H$. <Ref lesson="entropy-of-english"/> measures it at about one bit per
  letter against a single-letter $H$ of $4.1$ bits.

<Figure
  src="./figures/entropy-wall.svg"
  alt="A number line with a blue wall at the entropy 0.469 bits per symbol; the region left of it is marked unreachable, the symbol code sits at 1.000, and block codes at 0.645, 0.493, 0.470 converge onto the wall from the right"
  caption="The source coding theorem on the 90/10 coin: lossless codes approach the entropy wall from the right and never cross it."
/>

<KeyFact>
The module in one line: the Kraft inequality decides which length sets
exist, Gibbs' inequality proves none of them averages below $H(X)$, the
Shannon code comes within one bit, and block coding closes the gap.
</KeyFact>

What is established: entropy is the exact cost of lossless description, and
the excess of any code above it is a divergence plus a slack, both
computable from the code's own lengths. What remains is engineering.
<Ref lesson="arithmetic-coding"/> takes the block idea to its limit without
the $|\mathcal{X}|^n$ table, coding a whole message into one interval and
paying two bits total rather than one bit per symbol.
<Ref lesson="kl-divergence"/> takes up the mismatch term $D(p\,\|\,q)$ on its
own account, which is the quantity a trained model minimizes: a code's cost
$\sum_x p(x)\log_2\tfrac{1}{q(x)} = H(p) + D(p\,\|\,q)$ is the cross-entropy
loss of <Ref lesson="cross-entropy-loss"/>, so designing a code and fitting a
model are one optimization seen twice.

## Exercises

<Exercise>
For the source $p = (.35, .25, .20, .15, .05)$: compute $H(p)$, build the
Shannon code $\ell(x) = \lceil -\log_2 p(x)\rceil$, verify the Kraft sum,
compute $L$, and place it inside $[H, H+1)$. Then run Huffman on the same
source and report the two gaps to $H$.

<Solution>
Surprisals: $1.515, 2.000, 2.322, 2.737, 4.322$ bits. Weighted:
$H = .35(1.515) + .25(2) + .20(2.322) + .15(2.737) + .05(4.322) = 2.121$
bits.

Shannon lengths $(2, 2, 3, 3, 5)$. Kraft sum:
$\tfrac14 + \tfrac14 + \tfrac18 + \tfrac18 + \tfrac1{32} = 0.781 \le 1$, so
the lengths are achievable by the shortest-first construction of
<Ref lesson="kraft-inequality"/>.
$L = .35(2)+.25(2)+.20(3)+.15(3)+.05(5) = 2.50$ bits, and
$2.121 \le 2.50 < 3.121$.

Huffman: merge $.05+.15 = .20$; then $.20+.20 = .40$; then $.25+.35 = .60$;
then the root. Summing merge weights, $L^* = .20+.40+.60+1.00 = 2.20$ bits,
with lengths $(2,2,2,3,3)$.

Gaps: Shannon $0.379$ bits, Huffman $0.079$ bits. The Shannon code's excess
is mostly slack — its Kraft sum leaves $0.219$ of the budget unclaimed,
worth $\log_2 \tfrac{1}{0.781} = 0.357$ bits — which is exactly what the
decomposition attributes to a wasted tree rather than to a wrong bet.
</Solution>
</Exercise>

<Exercise>
A binary source has $p = (1 - 10^{-6},\ 10^{-6})$. Compute $H$, the
Shannon-code $L$, and the Huffman $L$. Then use the block coding bound to
state the smallest block length $n$ that guarantees a per-symbol cost below
$2H$, and say in one sentence what makes the answer so large.

<Solution>
$H = 10^{-6}\log_2 10^{6} + (1-10^{-6})\log_2\tfrac{1}{1-10^{-6}}
\approx 1.99 \cdot 10^{-5} + 1.44 \cdot 10^{-6} = 2.14 \cdot 10^{-5}$ bits.

Shannon lengths: $\lceil 1.44\cdot 10^{-6}\rceil = 1$ and
$\lceil 19.93 \rceil = 20$, giving
$L = 1(1-10^{-6}) + 20(10^{-6}) = 1.000019$ bits. Huffman on two symbols has
lengths $(1,1)$ and $L = 1$ bit exactly: both codewords must be at least one
bit long, so a symbol code cannot do better.

The bound gives $L_n/n < H + 1/n$, so $L_n/n < 2H$ is guaranteed once
$1/n \le H$, i.e. $n \ge 1/H \approx 46{,}800$.

The overhead is one bit per block whatever the source, while the entropy
here is a fiftieth of a thousandth of a bit; the block must be long enough
that one bit spread over it becomes comparable to that. The required table
would hold $2^{46{,}800}$ codewords, which is the concrete reason
<Ref lesson="arithmetic-coding"/> exists.
</Solution>
</Exercise>

<Exercise>
Refute the claim: *"the typical set is the set of the most likely sequences,
so a compressor that indexes the typical set is indexing the sequences it is
most likely to see."* Work on a Bernoulli$(0.9)$ source at $n = 100$ with
$\varepsilon = 0.1$: give the most probable sequence, compute its
$-\tfrac1n \log_2 p$, decide its membership, and name the step of the
reasoning that fails.

<Solution>
The most probable sequence is all heads, with probability
$0.9^{100} = 2.7\cdot10^{-5}$ and
$-\tfrac1{100}\log_2 p = -\log_2 0.9 = 0.152$ bits. Since
$|0.152 - 0.469| = 0.317 > \varepsilon = 0.1$, it is not in
$T_{0.1}^{(100)}$: the single likeliest sequence is excluded.

The step that fails is the slide from "most probable individually" to "most
probable collectively". Membership is decided by per-symbol surprisal, which
is a statement about composition, and there is only one all-heads sequence,
so its $2.7 \cdot 10^{-5}$ is the whole of its contribution. The typical
band ($7$ to $13$ tails at these settings) contains about $2^{53}$ sequences,
each far less probable individually, and collects $76\%$ of all draws.

The claim's conclusion survives in weakened form: indexing the typical set
is indexing what the compressor will almost certainly see, but not the
sequences with the largest individual probabilities. A compressor built on
the most probable sequences instead reaches the same rate anyway, which is
the essential-bit-content accounting of the starred section.
</Solution>
</Exercise>

<Exercise>
Derive the wrong-code results yourself, in two steps.
(a) Start from $L = \sum_x p(x)\ell(x)$ with the idealized lengths
$\ell(x) = -\log_2 q(x)$ for a distribution $q$; add and subtract
$\sum_x p(x)\log_2 p(x)$ and identify the two resulting terms. State the
condition under which the second vanishes.
(b) Now use the realizable lengths $\ell(x) = \lceil -\log_2 q(x)\rceil$ and
derive two-sided bounds on $L$.

<Solution>
(a) With $\ell(x) = -\log_2 q(x)$,

$$
L = \sum_x p(x)\log_2\tfrac{1}{q(x)}
= \sum_x p(x)\log_2\tfrac{1}{p(x)} + \sum_x p(x)\log_2\tfrac{p(x)}{q(x)}
= H(p) + D(p\,\|\,q),
$$

adding and subtracting $\sum_x p(x)\log_2 p(x)$. The second term vanishes
exactly when $q = p$, by the equality case of Gibbs' inequality. Note what
was *not* needed: no property of $q$ beyond being a distribution, and no
assumption that the lengths are integers.

(b) Ceilings satisfy $-\log_2 q(x) \le \lceil -\log_2 q(x)\rceil <
-\log_2 q(x) + 1$. Taking expectations under $p$ preserves the inequalities
term by term, and the middle expectation is $L$:

$$
H(p) + D(p\,\|\,q) \;\le\; L \;<\; H(p) + D(p\,\|\,q) + 1 .
$$

So a code designed for the wrong distribution pays the same $[\,\cdot,\
\cdot+1)$ band as a correct one, shifted upward by exactly $D(p\,\|\,q)$
bits per symbol. The transferable move is that ceilings never interact with
the expectation: bound the length pointwise, then average.
</Solution>
</Exercise>

<Exercise>
Prove the converse for fixed-length block codes: for an i.i.d. source with
entropy $H$, no scheme that maps blocks of $n$ symbols into $nR$ bits with
$R < H$ can have vanishing error probability as $n$ grows. Use only the two
AEP consequences, and state which one each step uses. (Fixed-length means
every block gets the same number of bits, so the decoder can reproduce at
most $2^{nR}$ distinct blocks.)

<Solution>
Let $\delta = H - R > 0$ and pick $\varepsilon = \delta/2$. Let $B$ be the
set of blocks the decoder can output; $|B| \le 2^{nR} = 2^{n(H-\delta)}$.
Correct decoding requires $X^n \in B$, so the success probability is
$\Pr(X^n \in B)$. Split it over the typical set:

$$
\Pr(X^n \in B) \;\le\;
\underbrace{\Pr\bigl(X^n \in B \cap T_\varepsilon^{(n)}\bigr)}_{\text{(i)}}
\;+\;
\underbrace{\Pr\bigl(X^n \notin T_\varepsilon^{(n)}\bigr)}_{\text{(ii)}} .
$$

Term (i) uses the *per-member probability bound* from the definition of the
typical set: each typical sequence has probability at most
$2^{-n(H-\varepsilon)}$, and at most $|B|$ of them lie in $B$, so
$\text{(i)} \le 2^{n(H-\delta)}2^{-n(H-\varepsilon)} = 2^{-n(\delta -
\varepsilon)} = 2^{-n\delta/2}$, which tends to 0.

Term (ii) uses AEP consequence (1), $\Pr(X^n \in T_\varepsilon^{(n)}) \to 1$,
so it tends to 0.

Hence the success probability tends to 0 and the error probability tends to
1: below the entropy the scheme fails almost surely rather than merely
often. Consequence (2), the size upper bound, is not needed for the
converse; it is what the achievability direction uses.
</Solution>
</Exercise>

<Exercise>
Estimate the byte entropy of a real file on your machine: tally the 256 byte
values, compute $H$ in bits per byte, and multiply by the file length to get
the size a symbol code would achieve. Compare with `gzip -1` on the same
file. Report the ratio of the two compressed sizes and state, in one
sentence, which assumption of this lesson the file violates.

<Solution>
Method: read the file as bytes, build the 256-bin histogram, compute
$H = -\sum_x \hat{p}(x)\log_2 \hat{p}(x)$ from the empirical frequencies,
and take $\lceil H \cdot N / 8 \rceil$ bytes as the symbol-code target,
ignoring the code table.

Typical outcomes. For English prose or source code, the byte histogram gives
$H$ around $4.5$ to $5$ bits per byte, so the symbol-code target is roughly
$60\%$ of the original; `gzip -1` on the same file usually lands near $35$ to
$45\%$, that is, below $4$ bits per byte. For an already-compressed file
(`.png`, `.zip`, `.mp4`) both numbers sit at about $8$ bits per byte and
gzip expands the file slightly.

The violated assumption is independence: the theorem's floor of $H$ bits per
byte is the floor for an i.i.d. source, and a text file is nothing of the
kind. `gzip` beats the byte entropy because it codes repeated substrings, so
the quantity it approaches is the entropy rate of
<Ref lesson="entropy-of-english"/>, which is far below the single-byte
entropy. A number to check the method against: on an ASCII text file the
first-order entropy should come out near Shannon's $4.1$ bits per letter
once whitespace and case are accounted for.
</Solution>
</Exercise>

<Exercise>
A code is built for the fair coin, $q = (\tfrac12, \tfrac12)$, and used on
the 90/10 source $p = (.9, .1)$. Compute $L$ and $L - H(p)$. Then compute
$\sum_x p(x)\log_2 \tfrac{p(x)}{q(x)}$ and compare. Finally state what the
number would be if the code were built for $q = (.9, .1)$ instead, and what
that says about the best possible symbol code for this source.

<Solution>
Lengths $(1,1)$, so $L = 1$ bit and $L - H(p) = 1 - 0.469 = 0.531$ bits.

$$
\sum_x p(x)\log_2\tfrac{p(x)}{q(x)}
= .9\log_2\tfrac{.9}{.5} + .1\log_2\tfrac{.1}{.5}
= .9(0.848) - .1(2.322) = 0.531 \text{ bits,}
$$

the same number: the entire overhead is the cost of the wrong bet, since the
code is complete and has no slack.

Building for $q = (.9, .1)$ changes nothing. The Shannon lengths are
$\lceil 0.152 \rceil = 1$ and $\lceil 3.322\rceil = 4$, giving $L = 1.3$
bits, worse than 1. Integer lengths on a binary alphabet admit only the bet
$(\tfrac12,\tfrac12)$ as a complete code, so a symbol code for a binary
source is *forced* to bet fair, whatever the source does. That is why the
90/10 coin's overhead is irreducible at $n = 1$ and vanishes under blocking.

The quantity computed here is the Kullback–Leibler divergence
$D(p\,\|\,q)$, which <Ref lesson="kl-divergence"/> takes up as an object in
its own right: the expected extra bits from coding $p$-distributed data with
a code matched to $q$, and the term that makes a model's loss a file size.
</Solution>
</Exercise>
